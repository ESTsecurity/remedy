## 0.5.1 — 파일은 PHP 자리만 (2026-11-20)

파일(코어 DLL)은 PHP 자리 14곳만 걷는다(`subject_roots.file` — PHP 11월 보안 업데이트 점검 Windows 룰과 같은 목록). 0.5.0 은
Apache 폴더까지 걸어, WampServer 가 Apache 폴더(`bin\apache\apache2.4.x\bin`)에 두는 코어 DLL 링크(본문 · 버전이 없다)를 판 없는
코어 DLL 로 세어 고친 버전으로 올려도 *확인 필요(6)* 였다. 설정(`text_config`)은 그대로 Apache 폴더도 읽는다 — WampServer 의
Apache 가 읽는 `php.ini` 와 Apache 설정의 `php_admin_flag` 줄이 그 자리에 있다. 판정 규칙은 0.5.0 과 같다.

검증(2026-11-20): 랩 VM 의 실제 수집(`testbed/harness/host/Invoke-Php202611Verify.ps1` 의 W 칸 · 개발 꾸러미) — WampServer
8.3.37 + Apache bin 링크 **0**(0.5.0 은 6) · 8.3.35 + 링크 6(판 폴더의 코어 DLL 은 그대로 찾는다) · 8.3.37 + 링크 + Apache
설정의 `php_admin_flag session.upload_progress.enabled on` 6(고친 버전이지만 직접 켰다는 까닭) · G1 청정 코퍼스 `win10x64-*` 10개 모두 0.

## 0.5.0 — 고친 판이고 직접 켠 설정이 없으면 0 (2026-11-20)

PHP 의 2026-11-19 보안 업데이트(8.2.36 · 8.3.37 · 8.4.28 · 8.5.13)가 이 결함을 고쳤다(GHSA-658j-r8rw-q6mx). 그래서 **찾은
코어 DLL 이 모두 고친 판 이상이고 직접 켠 설정이 없으면(꺼짐 · 없음) 0** 이다 — 0.4.1 은 PHP 가 있으면 늘 *확인 필요(6)* 였다.
고친 판이지만 설정에서 직접 켰으면 *확인 필요* 로 남고 까닭이 직렬화기를 같게 맞추라고 적는다(고친 판도 설정끼리 다른 직렬화기는
막지 않는다). 고치지 않은 코어 DLL 이 하나라도 있으면 0.4.1 의 까닭에 고친 판으로 올리라는 말을 더해 그대로 *확인 필요* 다.

판은 PHP 11월 보안 업데이트 점검(`php-2026-11-check-windows` 0.1.0)과 같이 코어 DLL 의 파일 버전으로 읽는다 — 코어 DLL 마다
고친 판 아래 · 8.1 이하(`core_unfixed`)이거나 정식 판을 읽지 못했으면(`core_unknown` — 버전 정보 없음 · RC · 개발 빌드) 고친
판으로 세지 않는다. 선언한 자리 밖의 PHP 는 그대로 *확인 필요* 다. 까닭 문구의 *기본값은 켜짐* 을 *고친 버전 전의 기본값은 켜짐*
으로 바로잡았고, 고치지 않은 PHP 줄의 까닭에 8.1 이하 단서와 버전을 확인하지 못한 PHP 의 길(11월 점검 안내)을 붙였다.

고친 판에서는 '켬' 을 놓치면 0 이 되므로 켬 · 끔을 두 꼴로 읽는다 — `php.ini` 꼴 `키 = 값`(값 뒤의 `; 주석` 도)과 Apache 설정의
`php_admin_flag 키 값` · `php_value 키 값` 꼴(XAMPP · WampServer · Apache 의 설정 폴더 — 이미 보는 자리다).

알려진 것(0.5.1 에서 고침): WampServer 는 Apache 폴더(`bin\apache\apache2.4.x\bin`)에 코어 DLL 링크를 두는데, 이 판은 그 링크를
버전 정보 없는 코어 DLL 로 세어 고친 버전으로 올려도 *확인 필요(6)* 였다.

검증(2026-11-20): 깨끗한 Windows 스냅샷에 `C:\php` 의 코어 DLL 기록(공식 zip 에서 잰 해시 · 파일 버전)과 설정 줄을 더한
`remedy evaluate` 12 — 8.3.37 설정 없음 **0**(0.4.1 은 6) · 직접 켬 6(새 까닭) · 끔 **0** · 8.3.36 6 · `8.6.0RC3` 6 · 버전 정보
없음 6 · 고친 판과 8.2.35 가 함께 6 · `On ; 주석` 6 · `Off ; 주석` **0** · Apache 설정의 `php_admin_flag … on` 6 · `off` **0** ·
`php_value … 1` 6 · G1 청정 코퍼스 `win10x64-*` 10개 모두 0.

## 0.4.1 — 같은 제품의 묶음 열쇠 (2026-11)

같은 제품의 점검 룰을 묶는 열쇠 `product: PHP` 를 적었다(코어 1.21.0 — 화면이 같은 제품의 발견을 한 덩어리로
묶는다). 판정 · 찾는 자리는 0.4.0 과 같다. 코어 1.21.0 이 필요하다.

## 0.4.0 — NSSM 이 감싸 띄우는 PHP (2026-11)

`php2shell-check-windows` 0.4.0 과 같은 규칙 — NSSM(srvany)으로 등록한 서비스의 `Parameters\Application` 이 선언한 자리
밖의 PHP 면 **확인 필요(6)** 로 낸다. 그 PHP 의 설정은 열지 않는다. 코어 1.10.0 이 필요하다.

## 0.3.0 — 다른 프로그램에 모듈로 실린 PHP (2026-11)

`php2shell-check-windows` 0.3.0 과 같은 네 규칙을 더했다 — 다른 프로그램(Apache 등)에 모듈로 실린 선언 밖의 PHP 는
그 프로그램의 경로와 걸린 DLL 을 적어 **확인 필요(6)** 로, 모듈 목록을 읽지 못한 Apache(`httpd.exe`)도 확인 필요로
낸다. 멈춰 있어도 남는 자리 — 선언 밖의 PHP 를 띄우는 **서비스**와 그 PHP 를 싣는 **Apache 설정**의 `LoadModule` 줄 —
도 같다. 그 PHP 의 설정은 열지 않는다. 코어 1.9.0 부터 Windows 도 실린 모듈을 모은다.

## 0.2.0 — 선언한 자리 밖의 PHP 를 알린다 (2026-11)

`php2shell-check-windows` 0.2.0 과 같은 세 규칙(IIS 의 FastCGI · 처리기 · 공유 설정, 실행 중인 `php.exe` ·
`php-cgi.exe` · `php-win.exe`)으로 선언한 자리 밖의 PHP 를 찾아 그 경로를 적고 **확인 필요(6)** 로 낸다. 그 PHP 의
`php.ini` 는 열지 않는다. 코어 1.6.0 이 필요하다.

## 0.1.0 — 처음 (2026-11)

PHP 가 있으면 늘 확인 필요로 내고, 까닭을 설정 상태로 가른다. 코어 1.3.0 의 `verdict.unconfirmed` 를 쓴다.

## 무엇을 하나

- **판정(2)을 세우지 않는다.** 위험은 세 조건이 겹칠 때뿐이다 — `session.upload_progress.enabled` 가 켜져 있고,
  서버의 `session.serialize_handler` 가 `php_binary` · `php_serialize` 이며, 앱이 `session_start()` 전에 `ini_set()` 으로
  그것을 `php` 로 바꾼다(또는 같은 세션을 쓰는 설정끼리 직렬화기가 다르다). 셋째는 앱 코드다. 10-23 공지 때는 고친 버전이
  없었고, 2026-11-19 보안 업데이트가 고쳤다 — 설정끼리 다른 직렬화기는 막지 않는다.
- PHP(코어 DLL)가 있으면, 찾은 코어 DLL 이 모두 고친 버전이고 설정에서 직접 켜지 않았으면 **0**(0.5.0), 고치지 않았거나
  버전을 확인하지 못한 코어 DLL 이 하나라도 있거나 직접 켰으면 **확인 필요(6)** 다 — `php.ini` · Apache 설정의 켜짐 ·
  꺼짐 · 없음(고친 버전 전의 기본값은 켜짐)에 따라 할 일을 갈라 적는다. WampServer 의 Apache 가 읽는
  `php.ini`(`C:\wamp64\bin\apache\…\bin`)도 본다. PHP 가 없으면 **해당 없음(0)**.
