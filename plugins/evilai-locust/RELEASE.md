# evilai-locust — 릴리스 기록

**버전 0.1.1** · 대상: EvilAI (Locust) · VT 패밀리 `meadowlocust`

> 출시 게이트(설계-03 §10) 통과 기록이다. **모든 플러그인은 배포 전 전 항목을
> 통과해야 한다.** 이 파일이 없거나 매니페스트 버전과 어긋나면
> `crates/remedy-core/tests/evilai.rs` 가 막는다 — 기록이 낡으면 "통과했다" 가
> 그대로 거짓이 되기 때문이다.

## 0.1.1 — 주석과 참조만 바뀌었다 (2026-11-06)

`plugin.yaml` 의 주석 셋 · `references` 한 줄과 `rules/evilai.yar` 의 머리 주석(1~58줄
`/* … */` 안)에서 **공개 저장소 밖의 문서 경로를 뺐다.** 탐지 · 치료에 쓰이는 값 — 룰의
조건 · 수집 대상 · 판정 · 치료 Op — 은 0.1.0 과 같다. 그래서 아래 게이트 결과는 0.1.0 에서
잰 그대로 이 판에 선다. 판을 올린 것은 서명 대상 파일의 바이트가 바뀌었기 때문이다
(`plugins/versions.lock.json` 이 그것을 막는다).

## 배포 판단

**P9 기준 게이트는 전부 통과했다.** G8(서명 강제)만 미해당이었는데, 서명 체계
자체가 P10 에 오므로 그 단계에서 잴 수 있는 것이 없었다.

### 서명 — **개발용 키다. 이대로 배포하지 않는다**

`MANIFEST` 와 `MANIFEST.minisig` 가 이 폴더에 있다. 서명 사슬이 끝까지 서는 것을
처음 실측하기 위해 **개발용 키로** 서명한 것이다(2026-09-08). 이 기록을 고친
2026-11-03 에 개발 키를 새로 만들어 다시 서명했다 — 앞 키의 암호가 남아 있지 않았다.

| | |
|---|---|
| 키 | 개발용. 저장소 밖(`~/.remedy-keys/dev.*`)에 있고 커밋되지 않는다 |
| 공개키 지문 | `RWRE8dmn1ahpOSJGJ/T7GMFjJzkjc4sbUD2zjJ4a9ivvaBOjeEzB0Ks9` |
| 서명 시각 | `MANIFEST.minisig` 의 주석에 있다 — **여기 적지 않는다** |

> **서명 시각을 이 문서에 적지 않는 이유.** 이 파일도 서명 대상이라, 여기를
> 고치면 서명이 깨지고 다시 서명하면 시각이 또 달라진다. 2026-09-08 에 그
> 순환을 실제로 밟았다 — `RELEASE.md: 서명 이후 내용이 바뀌었다` 로 `xtask
> package` 가 막았고, 그 판정이 옳았다. 한 사실은 한 자리에만 둔다.

**배포물은 이 서명을 쓰지 않는다**: 태그의 배포 잡(`.github/workflows/release.yml`)이
배포 키로 이 폴더에 다시 서명하고, 그 공개키를 `REMEDY_TRUST_ANCHOR` 로 박아 빌드한다. 개발용 키로 서명된
꾸러미는 릴리스 앵커가 박힌 바이너리에서 **거부된다**(키 id 불일치) — 그것이
이 설계가 의도한 동작이고, 실수로 개발 꾸러미가 나가는 것을 막는다.

실측으로 확인한 것(개발용 키·앵커 박은 빌드):

| 무엇 | 결과 |
|---|---|
| `plugin verify --dir plugins/evilai-locust` | 통과 — 파일 3개 전부 일치 |
| 룰에 한 줄 몰래 추가 | **거부** — `rules/evilai.yar: 서명 이후 내용이 바뀌었다` (종료 5) |
| `xtask package` 로 만든 꾸러미의 자기 검증 | 통과 |

## G9 — 정상 파일 258,382개, 오탐 0건 (엔진 yara-x 1.22.1)

게이트가 요구하는 것은 **가용한 최대 정상 파일 코퍼스에 룰을 전수 실행했을 때
오탐 0건**이다(설계-03 §10). 측정 도구는 제품 엔진(`remedy-yara` → `yara-x`)을
쓰는 `cargo xtask yara` 이고, **못 훑은 파일을 미매치로 접지 않는다.**

> 처음에는 게이트가 "사내 검체 저장소 배치"를 방법으로 못 박고 있었다. 그 시스템에
> 접근할 수 없는 동안에는 **통과 불가능한 게이트**였고, 2026-08-25 에 대상을
> "가용한 최대 정상 파일 코퍼스"로 재정의했다. 사내 저장소가 붙으면 코퍼스가
> 커질 뿐 정의는 바뀌지 않는다(설계-03 §10 · 설계-05 §6 · 설계-09 §3.5).

### 이번에 잰 것 (2026-11-03 · yara-x 1.22.1)

엔진을 1.19.0 에서 1.22.1 로 올린 뒤 아래 '재현' 의 두 명령을 같은 코퍼스에 다시
돌렸다 — 관리자 권한 없이, 77분(디스크를 함께 쓴 다른 작업이 10분쯤 겹쳤다).

| 대상 | 스캔 | 오탐 | 못 훑음 |
|---|---|---|---|
| `C:\Program Files` + `C:\Program Files (x86)` | **230,702** | **0** | 5 |
| `C:\Windows\System32` | **27,680** | **0** | 556 |
| 소계 | **258,382** | **0** | 561 |

**새 엔진으로 정상 파일 258,382개에서 오탐 0건이다.** 2026-08-25 에 옛 엔진(1.19.0)으로
같은 자리를 잰 값은 244,361개 · 오탐 0 · 못 훑음 553 이다 — 그 사이 설치된 프로그램만큼
늘었다.

### 검체 탐지 — 새 엔진으로 다시 쟀다 (2026-11-03 · yara-x 1.22.1)

| 대상 | 스캔 | 결과 |
|---|---|---|
| 탐지 — meadowlocust 검체 | 16 | **16 / 16** · 못 훑음 0 |

**이 플러그인이 하는 일의 본체**라 엔진을 올린 뒤 다시 쟀다 — 옛 엔진(1.19.0)이 낸 값과
같다. 명령은 아래 '재현' 의 탐지 줄이고, 대상은 큐레이션 코퍼스의 `script` 버킷에 있는
meadowlocust 열여섯이다(PE 버킷의 한 건은 이 열여섯에 들어가지 않는다 — 옛 측정도
그랬다). 검체는 저장소에 없고, 어디에 두었는지는 도출 기록이 가진다.

### 옛 엔진(yara-x 1.19.0)으로 잰 것 — 새 엔진으로는 다시 재지 않았다

| 대상 | 스캔 | 결과 |
|---|---|---|
| 오탐 — 타 형식·타 패밀리 검체 (25종 카테고리 전부) | 624 | **0** |
| 오탐 — VM 청정 `.js` (`remedy-lab-base-v2`, Defender 실시간보호 켠 상태) | 3,750 | **0** |
| 오탐 — 호스트 청정 `.js` (VS Code · Node 런타임 · node_modules 3벌) | 25,863 | **0** |

이 셋은 위 합계에 더하지 않는다. 룰이 바뀌지 않았으므로 오탐 쪽의 판정이 뒤집힐 자리는
엔진 자신뿐이고, 같은 엔진으로 잰 G9 의 258,382개가 그 자리를 덮는다.

### 못 훑은 561건 — 전부 OS 가 막은 것

| 사유 | 건수 | 처리 |
|---|---|---|
| 액세스 거부 — `System32` 의 `winevt\Logs` 469 · `wbem\AutoRecover` 64 · `Microsoft\Protect` 6 · `SMI\Store` 6 · `Recovery` 2 · 크래시 덤프 1, `GoogleUpdater\crx_cache` 5 | 553 | 기록하고 넘어간다 — 이 계정은 스캔 시점에 읽을 수 없다 |
| 다른 프로세스가 사용 중 (`catroot2`) | 8 | 같음 |
| **크기 상한 초과 (우리 설정)** | **0** | — |

마지막 줄이 이 측정의 핵심이다. **1차 측정(상한 256MB)에서는 26건이 상한에 걸렸다**
— `msedge.dll` 342MB 같은 것들이다. 그것을 남겨 두면 **"안 봤다"를 "안 맞았다"로
흘리는 것**이므로 상한을 1GB 로 올려 다시 훑었고(35분), 그 결과 26건이 0 이 됐다.
OS 가 막는 것과 우리가 막는 것은 다르게 다룬다(설계-03 §10).

### 재현

```
cargo xtask yara --rules plugins/evilai-locust/rules --expect clean \
    --max-bytes 1073741824 --list 40 \
    --scan "C:/Program Files" --scan "C:/Program Files (x86)"
cargo xtask yara --rules plugins/evilai-locust/rules --expect clean \
    --max-bytes 1073741824 --scan "C:/Windows/System32"
```

`--expect clean` 은 오탐이 0 이어도 **못 훑은 파일이 있으면 실패**로 끝난다. 그래서
위 명령의 종료 코드는 비0 이고, 그 목록을 보고 사유를 갈라 판단한 결과가 이 절이다.
**목록을 보지 않고 통과시키지 않는다.** 2026-11-03 측정은 목록을 다 받으려고
`--list 5000` 을 더했다 — 찍는 줄 수만 바뀌고 측정은 같다.

### 다음에 코퍼스를 키울 때

- **VM 전체 스캔은 현실적이지 않다** (실측). 테스트 VM 의 `C:\` 는 파일이
  **292만 개**이고, Defender 실시간보호와 알약이 모든 읽기를 가로채 8시간을 돌고도
  끝나지 않았다. 상한 재측정까지 필요하면 그 배가 든다. 키우려면 **정적 트리를
  골라서** 더하는 편이 낫다.
- 사내 검체 저장소가 서면 그것을 더한다. 규모가 커질 뿐 위 판정은 뒤집히지 않는다.

## 알려진 한계

배포 판단에 필요한 것만 적는다. 전부 **의도된 미완**이고 조용히 빠지지 않는다 —
`plugin lint` 나 계획의 `deferred` 가 매번 지적한다.

| 항목 | 영향 | 열리는 때 |
|---|---|---|
| `dir.delete_recursive` 가 없다 | 작업·Run 키·예외는 제거되고 페이로드는 격리되지만 **빈 디렉터리가 남는다**. 위협은 돌지 않는다 | P10 |
| `FileRecord.signature` 가 비어 있다 | 서명 기반 판단을 쓸 수 없다. 이 플러그인은 그것에 기대지 않는다(아래) | P10 |
| `verify.after_reboot` 를 예약하는 곳이 없다 | 재부팅 뒤 `remedy verify` 를 **직접 불러야 한다**. `plugin lint` 가 경고한다 | P10 |
| `advise_restart` 가 도달 불가 | 안전 모드 제안·손상 보고 경로를 이 플러그인 구성으로는 태울 수 없다 (`file.delete_on_reboot` 미사용) | P10 |

**`exclude` 를 두지 않는다.** 초안의 두 줄은 실측에서 발동할 수 없음이 드러나
제거했다 — 실기기의 node.exe 는 `OpenJS Foundation` 서명이라 첫 줄이 맞지 않고,
VS Code 는 예약 작업을 만들지 않아(청정 코퍼스 7종에서 node 실행 예약작업 0건)
둘째 줄은 겨눌 레코드가 없다. 오탐 방어의 본체는 `verdict: task and payload` 의
논리곱과 `from:` 이 거는 스캔 범위 제한이며, 청정 0건은 G1 이 매 커밋 보증한다.

## 재현

```
cargo test --workspace                                   # G1 · 탐지 회귀 포함
cargo xtask all                                          # arch · trace · schema
remedy plugin lint plugins/evilai-locust/plugin.yaml      # 오류 0 · 경고 1 (after_reboot)
testbed\harness\host\Invoke-P9Verify.ps1 -Build           # G2 · G3 · G4 (감염 VM)
# **`--scan` 은 반복 지정이다** (`--scan A --scan B`). 한 번에 여러 경로를 나열하면
# 첫 번째만 스캔되고, 그래도 "전부 맞았다" 가 나온다 — 실제로 그렇게 3/3 을 봤다.
# `--max-bytes` 없이는 대형 검체가 미측정으로 빠지고 그때는 **실패**로 끝난다.
cargo xtask yara --rules plugins/evilai-locust/rules --expect match --ext bin \
    --scan <meadowlocust 검체 디렉터리> [--scan ...]
cargo xtask yara --rules plugins/evilai-locust/rules --expect clean --ext bin \
    --max-bytes 629145600 --scan <타 패밀리 디렉터리> [--scan ...]
```
