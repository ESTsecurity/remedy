# cwpdoor-1-check — 릴리스 기록

**버전 0.1.2** · 대상: CWPdoor — 백도어를 심은 `cwpsrv`(Control Web Panel 의 패널 웹 서버) · 리눅스

> 출시 게이트(설계-03 §10) 기록이다. **찾기만 한다** — 치료는 같은 배포 파일의 `cwpdoor-2-clean` 이
> 한다. 판정 · 지표 · 쓰지 않는 것 · 실물 측정은 그쪽 `RELEASE.md` 와 같다.

## 0.1.2 — 무엇을 보지 않는지 적었다 (2026-11-08)

탐지 · 판정에 쓰이는 값은 0.1.1 과 같다. 이 기록에 *이 룰이 보지 않는 것* 절을 더했다 — 판정이
`헤더 and 서명키` 라 **키를 바꾼 판은 종료 0**(위협 없음)이 되는 것을 쟀고(아래), 종료 0 이 그
서버에 CWPdoor 가 없다는 뜻이 아님을 적어야 했다. 이 파일은 서명 대상이라 버전을 올렸다.

## 0.1.1 — 이 기록만 바뀌었다 (2026-11-07)

탐지 · 치료에 쓰이는 값 — 룰의 조건 · 수집 대상 · 판정 — 은 0.1.0 과 같다. 이 기록의 낱말
('꾸러미' · '판')과 서명 절(배포본은 배포 키로 서명된다 — 전에는 *개발용 키다. 이대로 배포하지
않는다* 라고만 적어 배포본을 받은 사람이 읽으면 틀린 말이었다)을 고쳤다. 이 파일도 서명 대상이라
버전을 올렸다. 아래 게이트 결과는 0.1.0 에서 잰 그대로 이 버전에 선다.

## 무엇을 하나

- **판정** — `cwpdoor-2-clean` 과 같다(활성화 헤더 셋 and 0x55 XOR 된 공격자 공개키).
- **바꾸지 않는다** — `remediate` 가 없다. 화면은 *"위협 발견, 치료하지 않았습니다."* 다.
- **`kind: check` 가 아니다** — 그 선언은 취약한 *상태* 용이라, 감염에 붙이면 화면이 백도어를
  "취약" 이라고 부른다(`docs/plugin-guide/24-check-plugins.md`).

| 종료 코드 | 뜻 |

## 이 룰이 보지 않는 것 — 종료 0 이 뜻하는 것

판정은 **활성화 헤더 셋 and 공격자의 서명키**다. 둘을 모두 요구하는 것은 문자열 한 무리의 오탐이
곧바로 격리로 이어지지 않게 하려는 것이고, 그래서 **서명키가 다르면 판정이 서지 않는다.** 쟀다
(2026-11-08 · 공개된 v1.1.2 · 네트워크 끊은 컨테이너 · 자리 채우기):

| 자리 채우기 | 종료 |
|---|---|
| 헤더 + 보고의 키 (대조군) | 2 · 흔적 2 · 위협 1 |
| 헤더 + 다른 2048비트 키 | **0** · 흔적 1 · 위협 0 |
| 잔존 함수 이름 둘만 | **0** · 흔적 0 |

그래서 종료 0 은 *"이 룰이 보는 한 가지 꼴이 아니다"* 이지 *"이 서버에 CWPdoor 가 없다"* 가 아니다.
보고가 밝힌 잔존 함수 이름(`ngx_http_integrity_init` · `ngx_http_integrity_check`)을 세 번째 근거로
두면 키 교체에도 판정이 서지만, 그러면 판정의 논리곱을 다시 짜야 한다(근거 하나로 격리가 일어나지
않게) — 이번 판에서는 하지 않았다. 침해가 의심되면 사람이 보고의 확인을 한 번 돌린다.

```sh
strings /usr/local/cwpsrv/bin/cwpsrv | grep X-Ngx-Integrity   # 활성화 헤더
ss -axp | grep integrity                                      # 돌고 있는 백도어의 소켓
```
