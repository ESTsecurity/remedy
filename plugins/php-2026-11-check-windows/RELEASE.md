## 0.1.0 — 2차 (2026-11-20)

긴급 경로의 2차다 — 1차(`php-2026-11-check-linux` 0.1.0 · `rules-2026.11.20`)가 리눅스를 냈고 이 룰이 Windows 를 더한다(코어
그대로). 영향 판 · 고친 판 · 결함마다의 조건 · 출처는 리눅스 룰의 `RELEASE.md` 와 같다 — 여기서 되풀이하지 않는다.
`added: "2026-11-20"`.

### 판정

| 무엇 | 결과 |
|---|---|
| 설치본(코어 DLL `php8ts.dll` · `php8.dll` · … 가 있는 폴더 — `C:\php` · `Program Files\PHP` · XAMPP · WampServer · Laragon · Chocolatey)의 파일 버전이 그 갈래의 고친 판 아래 · 지원이 끝난 8.1 이하 | 취약(2) |
| 코어 DLL 의 파일 버전을 읽지 못했다 | 확인 필요(6) |
| 위 자리 밖의 PHP 를 IIS 가 쓰거나 서비스(NSSM 포함) · Apache 설정이 싣거나 그 PHP 가 실행 중 · 다른 프로그램에 모듈로 실림 · 모듈 목록을 읽지 못한 Apache · IIS 공유 설정 | 확인 필요(6) |
| 그 갈래의 고친 판 이상 · 8.6 · PHP 없음 | 0 |

- **판으로만 판정한다**(1차 카드와 같은 정책) — PHP2Shell 룰(`php2shell-check-windows`)은 공식 빌드의 해시로 확정했지만 이
  룰은 판 번호를 따른다. Windows 의 PHP 는 배포판 백포트가 없고, 공식 빌드는 상류 판을 파일 버전에 그대로 적는다.
- **판은 코어 DLL 의 파일 버전 자원이다** — 판마다 하위 폴더를 두는 WampServer · Laragon · `Program Files\PHP\v8.3` 도 그대로
  읽는다(내용을 담지 않으므로 리눅스 룰의 글롭 한계가 없다).
- **설치본마다 가른다** — 고친 판과 영향 판이 함께 깔리면 영향 판 때문에 2, 판을 읽지 못한 설치본이 있으면 6 이다.
- 고친 Windows 빌드는 2026-11-19 에 상류와 같은 판으로 나왔다(downloads.php.net/~windows/releases — TS · NTS · 2026-11-19
  23:55 KST 확인).
