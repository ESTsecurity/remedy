# php2shell-url-check — 릴리스 기록

**버전 0.1.0** · 대상: PHP2Shell(CVE-2026-109618 · CVE-2026-109619) — 바깥에서 본 웹서버 응답 헤더 · Windows · 리눅스 · **점검**(바꾸지 않는다) · **네트워크 사용**

## 0.1.0 — 처음 (2026-11)

적어 준 주소의 웹서버가 응답 헤더로 알리는 PHP 버전을 수정 버전과 견준다. 코어 1.4.0 의 `network` 를 쓴다 —
본체(`remedy`)는 통신하지 않고, 이 룰을 고르면 서명을 확인한 동반 프로그램 `remedy-net` 을 실행해 맡긴다.

## 무엇을 하나

- **이 기계를 보지 않는다.** 점검 대상은 적어 준 주소의 서버다. 관리자 권한이 없어도 된다.
- 주소마다 HEAD 요청을 한 번 보내 응답 헤더(`Server` · `X-Powered-By`)만 읽는다. 서버가 HEAD 를 받지
  않으면(405 · 501) GET 을 한 번 보내고 본문은 읽지 않는다.
- 요청은 직렬이고 2초 간격이다. 주소는 50개까지, 요청은 한 번 실행에 100회까지, 주소 하나에 10초까지 기다린다.
  리다이렉트를 따르지 않고 프록시 · 쿠키 · 인증을 쓰지 않는다.
- 서버가 요청 제한(429)이나 오류(5xx)로 답하거나 연결을 끊으면 **그 서버에는 더 요청하지 않는다.**
- 시작할 때 이용 조건을 보이고 동의를 받는다. 소유하거나 점검을 허락받은 서버에만 쓴다.

## 결과 읽기

| 종료 코드 | 뜻 |
|---|---|
| 2 | **취약** — 헤더가 알리는 버전이 영향 버전이다. 실제 설치 버전과 백포트 패치는 확인하지 못했다 |
| 6 | **확인 필요** — 헤더로는 패치 여부를 가릴 수 없다(고친 버전을 알려도, 버전을 숨겨도) |
| 4 | 주소를 잘못 적었거나 이용 조건에 동의하지 않았다 |
| 5 | `remedy-net` 이 없거나 서명이 맞지 않아 실행하지 않았다 |

**양호(0)는 내지 않는다.** 취약이 나오지 않아도 안전하다는 뜻이 아니다 — 그 서버에서 remedy 의 PHP2Shell
점검으로 확인한다. 결과는 화면과 결과 폴더의 `remedy-net-url-<실행 번호>.json` 에 남는다(주소의 쿼리는 가린다).

## 이 룰이 보지 않는 것

- 헤더를 숨긴 서버의 버전 · 리버스 프록시 뒤의 실제 서버 · 응답 본문.
- PHP 세션 설정(CVE-2026-115560) — 바깥에서는 볼 수 없다.
- 적지 않은 주소 — 범위(CIDR)나 목록 파일을 펼치지 않고, 리다이렉트가 가리키는 곳에도 가지 않는다.

## 네트워크를 쓰지 않으려면

받은 폴더의 `remedy-net` 폴더를 지운다. 이 항목만 꺼지고 나머지 검사 · 치료는 그대로 쓴다.
