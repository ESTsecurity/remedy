# php-session-check-linux — 릴리스 기록

## 0.6.1 — RPM 자리의 패키지 밖 PHP (2026-11-20)

RPM 계열의 PHP 자리(`/usr/bin/php` · `php-cgi` · `/usr/sbin/php-fpm` · httpd 의 `libphp*.so`)에 **어느 패키지도 깔지 않은
정규 파일**이 있으면 고친 판으로 세지 않는다(`bin_rpm_unowned` · `sbin_fpm_unowned` — PHP 11월 보안 업데이트 점검 0.1.2 와 같은
규칙 · `/usr/sbin` 이 `bin` 으로 가는 링크인 Fedora 42 이후의 꼴은 그 룰의 RELEASE.md). 0.6.0 은 RPM 의 PHP 패키지가 있으면 그
자리의 파일을 모두 패키지의 것으로 보아, 고친 `php-cli` 옆에 따로 놓은 `/usr/sbin/php-fpm` 이 있고 설정에서 직접 켜지 않았으면 0
이었다(직접 켰으면 그때도 6). 패키지가 깐 실행 파일이 그 기록과 다른지 보는 자리에 합친 bin 의 패키지 자리
`/usr/bin/php-fpm` 을 더했다(0.6.0 은 그 자리를 보지 않았다). 그 밖의 판정은 0.6.0 과 같다.

검증(2026-11-20): `remedy evaluate` 합성 수집 결과(하네스의 Rocky 9 스냅숏의 PHP 기록만 바꿈) — 고친 RPM PHP(8.3.37) + 패키지
밖 `/usr/sbin/php-fpm` **6**(0.6.0 은 0) · Fedora 꼴 합친 bin 의 고친 PHP 0 · 그 꼴에 패키지 밖 `php-fpm` 6(0.6.0 은 0) · 그 꼴의
`/usr/bin/php-fpm` 이 패키지 기록과 다르면 6(0.6.0 은 0) · 고친 RPM PHP 만 0 · 그 밖의 합성 41 경우는 0.6.0 과 같다 · 실제
Fedora 42 수집(판을 8.4.28 로 바꾼 사본) 0 · G1 청정 코퍼스 `docker-*` · `wsl-*` 19개 모두 0.

## 0.6.0 — 고친 판이고 직접 켠 설정이 없으면 0 (2026-11-20)

PHP 의 2026-11-19 보안 업데이트(8.2.36 · 8.3.37 · 8.4.28 · 8.5.13)가 이 결함을 고쳤다(GHSA-658j-r8rw-q6mx — 기본값을
꺼짐으로 바꾸고, 켜진 동안 실행 중에 직렬화기를 바꾸지 못하게 한다). 그래서 **찾은 PHP 가 모두 고친 판 이상이고 직접 켠 설정이
없으면(꺼짐 · 없음) 0** 이다 — 0.5.1 은 PHP 가 있으면 늘 *확인 필요(6)* 였다.

| 무엇 | 결과 |
|---|---|
| 찾은 PHP 가 모두 고친 판 이상 · 켠 설정이 없다 | 0 |
| 고친 판이지만 설정에서 직접 켰다 | 확인 필요(6) — 고친 판도 설정끼리 다른 직렬화기는 막지 않는다(새 까닭: 직렬화기를 같게 맞춘다) |
| 고치지 않은 PHP · 버전을 확인하지 못한 PHP 가 하나라도 있다 | 확인 필요(6) — 0.5.1 의 까닭에 고친 버전으로 올리는 길(8.1 이하 · 배포판 패키지의 단서)과 버전을 확인하지 못한 PHP 는 11월 점검의 안내를 따르라는 말을 더했다 |
| 선언한 자리 밖의 PHP · 서비스 · Apache 설정 | 확인 필요(6) — 그대로 |

판 사실은 PHP 11월 보안 업데이트 점검(`php-2026-11-check-linux` 0.1.1)과 **같은 규칙**을 옮겨 왔다 — 배포판 패키지(dpkg ·
apk · RPM)는 상류 판으로(백포트한 패키지는 고친 판으로 세지 않는다), 패키지 밖의 실행 파일은 판 문자열(`rules/php.yar` · 같은
파일)로, 정식 판을 읽지 못하면(판 문자열 없음 · RC · 개발 빌드 — 실행 파일마다 가린다) · RPM 의 자리에 패키지가 깔지 않은 PHP ·
패키지 기록과 다른 실행 파일 · 고친 뒤 다시 시작하지 않은 PHP 는 고친 판으로 세지 않는다. Alpine 은 `phpN` · `phpNN` 이름(지원이
끝난 `php7` · `php8` 도)을 판으로 본다. 그 판을 보려고 `/usr/local/lib` · `/usr/lib/apache2/modules` 를 보는 자리에 더했다.
까닭 문구의 *기본값은 켜짐* 을 *고친 버전 전의 기본값은 켜짐* 으로 바로잡았다(고친 판부터 꺼짐이다).

고친 판에서는 '켬' 을 놓치면 0 이 되므로 넓게 읽는다:

- **켬 · 끔을 세 꼴로 읽는다** — php.ini 꼴 `키 = 값`(값 뒤의 `; 주석` 도), PHP-FPM 풀의 `php_admin_flag[키] = 값` ·
  `php_value[키] = 값` 꼴, Apache 설정의 `php_admin_flag 키 값` · `php_value 키 값` 꼴.
- **PHP-FPM 풀 자리를 더했다** — `/etc/php-fpm.d` · `/etc/php-fpm*.conf`(RPM 계열) · `/usr/local/etc/php-fpm.d` ·
  `/usr/local/etc/php-fpm*.conf`(공식 이미지). Alpine `/etc/php7` 도.
- **PHP 가 있다는 문을 판 사실과 같은 자리로 맞췄다** — 모듈 자리 둘(`/usr/local/lib/libphp*.so` ·
  `/usr/lib/apache2/modules/libphp.so`)과 RPM 의 PHP 패키지(SCL 이름 `php81-php-cli` · `rh-php73-php-fpm` 등)도 PHP 로 센다.
  문은 섰는데 판을 볼 규칙이 하나도 서지 않은 PHP(대상이 자리 밖인 링크만 있거나, 판 줄이 모르는 이름의 패키지가 깐 PHP)는
  고친 판으로 세지 않는다.

## 0.5.1 — 같은 제품의 묶음 열쇠 (2026-11)

같은 제품의 점검 룰을 묶는 열쇠 `product: PHP` 를 적었다(코어 1.21.0 — 화면이 같은 제품의 발견을 한 덩어리로
묶는다). 판정 · 찾는 자리는 0.5.0 과 같다. 코어 1.21.0 이 필요하다.

## 0.5.0 — 시작 스크립트 · Apache 설정 (2026-11)

`php2shell-check-linux` 0.6.0 과 같은 규칙 — SysV · OpenRC · Upstart 의 시작 스크립트가 띄우는 실행 파일(코어 1.10.0 이
실행하지 않고 풀어 서비스로 낸다)과 Apache 설정(`/etc/apache2` · `/etc/httpd` · `/usr/local/apache2/conf` ·
`/opt/lampp/etc`)의 `LoadModule` 줄이 선언한 자리 밖의 PHP 면 **확인 필요(6)** 로 낸다. 그 PHP 의 설정은 열지 않는다.
코어 1.10.0 이 필요하다.

## 0.4.0 — 서비스로 등록된 PHP (2026-11)

`php2shell-check-linux` 0.5.0 과 같은 규칙 — systemd 유닛이 선언한 자리 밖의 PHP 를 띄우면 그 유닛과 실행 파일을
적어 **확인 필요(6)** 로 낸다. 그 PHP 의 설정은 열지 않는다.

## 0.3.0 — 직접 빌드의 자리 (2026-11)

직접 빌드의 흔한 접두사 `/usr/local/php` · `/opt/php` 를 선언한 자리로 읽는다 — 그 아래의 PHP 실행 파일이 있으면
PHP 가 있는 기계로 보고(확인 필요), 그 아래의 설정(`lib/php.ini` · `etc/php.ini` · `etc/conf.d` 등 `.ini` · `.conf`)을
읽는다. `php2shell-check-linux` 0.4.0 과 같은 자리다. 0.2.1 은 그 자리의 PHP 가 돌지 않으면 PHP 가 없는 기계로 보아
*취약한 곳을 찾지 못했습니다* 였다.

## 0.2.1 — 화면 문구 (2026-11)

판정은 0.2.0 과 같다. 사유가 경로를 *위 경로* 로 가리키고(항목 줄이 주의 줄보다 위에 선다), *끈 설정이

## 0.2.0 — 선언한 자리 밖에서 실행 중인 PHP 를 알린다 (2026-11)

`php2shell-check-linux` 0.2.0 과 같은 규칙으로 선언한 실행 파일 자리 밖에서 도는 PHP 를 찾아 그 경로를 적고
**확인 필요(6)** 로 낸다. 그 PHP 의 설정 파일은 열지 않는다. 컨테이너 안에서 다른 사용자로 도는 프로세스를
들여다보지 못하면 관측 불완전(6)인 것도 같다. 코어는 1.3.0 그대로다.

## 0.1.0 — 처음 (2026-11)

## 무엇을 하나

- **판정(2)을 세우지 않는다.** 위험은 세 조건이 겹칠 때뿐이다 — `session.upload_progress.enabled` 가 켜져 있고,
  서버의 `session.serialize_handler` 가 `php_binary` · `php_serialize` 이며, 앱이 `session_start()` 전에 `ini_set()` 으로
  그것을 `php` 로 바꾼다(또는 같은 세션을 쓰는 설정끼리 직렬화기가 다르다). 셋째는 앱 코드다. 10-23 공지 때는 고친 버전이
  없었고, 2026-11-19 보안 업데이트가 고쳤다(기본값 꺼짐 · 켜진 동안 실행 중에 직렬화기를 바꾸지 못함) — 설정끼리 다른
  직렬화기는 막지 않는다.
- PHP(배포판 런타임 패키지 · RPM 의 PHP 패키지 · PHP 실행 파일 · 모듈)가 있으면, 찾은 PHP 가 모두 고친 버전이고 설정에서
  직접 켜지 않았으면 **0**(0.6.0), 고치지 않았거나 버전을 확인하지 못한 PHP 가 하나라도 있거나 직접 켰으면 **확인
  필요(6)** 다 — 설정이 켜짐 · 꺼짐 · 없음(고친 버전 전의 기본값은 켜짐)에 따라 할 일을 갈라 적는다. PHP 가 없으면 설정
  파일이 남아 있어도 **해당 없음(0)** 이다.
- 설정을 읽는 자리: Debian 계열 `/etc/php/<버전>/`(FPM 풀 `pool.d` 포함) · RPM 계열 `/etc/php.ini`(`/etc` 바로 아래 파일
  하나라 글롭 뿌리 `/etc/php*.ini` 로) 와 `/etc/php.d` · `/etc/php-fpm.d` · SUSE `/etc/php8` · Alpine `/etc/php7` ·
  `/etc/phpNN` · 공식 이미지 `/usr/local/etc/php` · `/usr/local/etc/php-fpm.d` · 직접 빌드 `/usr/local/php` · `/opt/php` ·
  `/usr/local/lib` · Apache 설정 자리 넷.

## 서명 — 저장소 사본은 개발용 키, 배포본은 배포 키

저장소의 `MANIFEST` · `MANIFEST.minisig` 는 저장소 사본을 확인하려고 **개발용 키로** 서명한 것이다. 배포본은
태그의 배포 잡이 배포 키로 다시 서명하고 그 공개키를 박아 빌드하므로, 내려받은 배포 파일에 든 이 폴더는 배포
키의 서명이다(`plugin verify` 로 확인한다). 개발용 키로 서명된 룰은 배포 앵커가 박힌 실행 파일에서 거부된다.
