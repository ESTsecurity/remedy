**버전 0.1.2** · 대상: nginx 의 결함 다섯 'nginx2root'(CVE-2026-123007 · CVE-2026-123634 · CVE-2026-123633 ·

## 0.1.2 — 더한 날을 적는다 (2026-11-19)

- **매니페스트에 `added: "2026-11-19"`** — 이 룰을 처음 낸 날이다(`rules-2026.11.19`). 엔진 1.25.0 의 고르는 화면이
  꾸러미의 가장 새 날부터 사흘 안의 룰을 검사 줄 바로 아래 *새로 추가된 항목* 으로 올리고 *[11월 19일 추가]* 를 붙인다 —
  전에는 이름순 자리(리눅스 9번)였다. `min_core` 를 1.25.0 으로 올린다(낮은 코어는 이 칸을 모른다).
- 판정 · 보는 자리 · 문구는 0.1.1 과 같다.

## 0.1.1 — 1차 고침 (2026-11-19)

1차(0.1.0)를 공개하기 직전 읽기 전용 검토 셋(판정 논리 · 글의 사실 · 하네스)이 찾은 것을 고친다. 0.1.0 은 그대로
공개했고(2026-11-19 08:55 KST) 이 차수가 고친다. 판정 범위(영향 판 · 고친 판)는 그대로다.

- **고친 판 안내** — 판을 읽지 못한 직접 빌드 · 보는 자리 밖 nginx 의 까닭이 *1.31.9 아래면 영향* 이라 적어, 고친
  stable 1.30.7 ~ 1.30.x 를 영향으로 안내했다. *1.30.7 아래이거나 1.31.0 ~ 1.31.8 이면 영향 · 1.30.7 이상의 1.30.x 와
  1.31.9 이상은 고친 판* 으로 고쳤다. 직접 빌드 · 패키지 없이 놓인 nginx 의 취약 줄도 *1.31.9 또는 1.30.7 이상으로
  올리십시오* 라 영향 판 1.31.0 ~ 1.31.8 이 드는 것으로 읽혔다 — *1.31.9 이상으로, stable 갈래(1.30.x)는 1.30.7 이상으로* 로
  고쳤다(ko · en).
- **nginx 목록 밖 이름의 패키지가 깐 nginx → 확인 필요(6)** — 0.1.0 은 보는 자리의 nginx 실행 파일을 `nginx-plus` ·
  `openresty` 같은 다른 이름의 패키지가 깔았으면 어느 줄에도 걸리지 않아 0 이었다. 파일 줄은 패키지가 깐 파일을 빼고,
  패키지 줄은 이름이 다르고, 프로세스 · 서비스 줄은 그 자리가 보는 자리라서다. F5 공지로는 NGINX Plus R34 ~ R36 에 고친 판이
  없다. `foreign_pkg_nginx` 가 그 파일을 잡아 *그 제품의 보안 공지로 확인하십시오* 로 알린다. 판정은 여전히 하지 않는다 —
  아래 *다음 차수 후보*. Alpine 의 파일 기록에는 깐 패키지가 적히지 않아 이 줄은 dpkg · RPM 기계에서만 선다(Alpine 의
  NGINX Plus 는 0.1.0 처럼 `/usr/sbin/nginx` 의 판 문자열로 본다 — 실측 전). 하네스는 dpkg 쪽만 잰다(RPM 의 패키지 DB 는
  바꿀 수 없다).
- **하네스** — 준비 셸이 실패하면 종료 97 로 적어 실패로 센다(판 줄을 바꾼 뒤 그 판이 읽히는지 본다 — `sed` 는 맞는 줄이
  없어도 0 이다). S1 은 머리 줄(룰 이름)의 CVE 로도 통과했다 — 취약 줄의 문구를 본다. S2 는 괄호의 영향 쪽과 고친 쪽,
  목록 밖 패키지의 까닭 줄(라벨에 없는 문구)을 본다. 목록 밖 패키지 칸 f01 과 화면 칸 S4(옛 문구 0 — 까닭 괄호 · 취약 줄) ·
  S5(배포판 패키지에 목록 밖 패키지 줄 없음) · S6(직접 빌드 취약 줄의 올릴 버전)를 더했다.

### 판정

| 무엇 | 결과 |
|---|---|
| nginx 실행 파일을 담는 패키지(dpkg `nginx` · `nginx-core` · `nginx-full` · `nginx-light` · `nginx-extras` / rpm `nginx` · `nginx-core` / apk `nginx` — nginx.org 저장소 포함)의 상류 판이 0.5.33 이상이고 1.30.7 아래 · 또는 1.31.0 ~ 1.31.8 | 취약(2) |
| 패키지가 깔지 않은 `nginx` 실행 파일(`/usr/local/sbin` · `/usr/local/nginx/sbin` · `/opt/nginx/sbin` · `/usr/local/openresty/nginx/sbin` · nginx 패키지가 없을 때의 `/usr/sbin`)의 판 문자열이 같은 범위 | 취약(2) |
| 그 실행 파일의 판 문자열(`nginx/<판>`)을 읽지 못했다 | 확인 필요(6) |
| 위 자리 밖에서 도는 nginx · 자리 밖의 nginx 를 띄우는 서비스 | 확인 필요(6) |
| 지워진 nginx 실행 파일로 도는 프로세스(올린 뒤 다시 시작하지 않음) | 확인 필요(6) |
| 1.31.9 이상 · 1.30.7 ~ 1.30.x · nginx 없음 | 0 |

- **Alpine 의 파일 기록에는 깐 패키지가 적히지 않는다**(2026-11-19 실측 — Debian · Rocky 는 적힌다). 그래서 배포판이 까는
  `/usr/sbin/nginx` 는 nginx 패키지가 하나도 없을 때만 직접 빌드로 본다 — 아니면 배포판이 같은 번호로 고친 빌드를 판 문자열만
  보고 취약으로 낸다.

- **판으로만 판정한다**(1차 카드) — 다섯 결함은 HTTP/2(123007 · 123633) · DNS 리졸버와 mirror(123634) · HTTP/3(121810) ·
  메일 프록시(113425)로 갈리고 설정은 include 가 흔하다. 기능을 끄는 법은 위협별 안내의 *꼭 할 일* 이다.
- **배포판의 고친 판이 없으면 영향 판은 취약(2)이다**(1차 카드) — 배포판은 고친 코드를 버전 번호를 그대로 두고 넣는다(백포트).
  고친 패키지가 나오면 다음 차수에서 그 배포판 줄을 더해 0(*취약한 곳을 찾지 못했습니다*)으로 가린다.
