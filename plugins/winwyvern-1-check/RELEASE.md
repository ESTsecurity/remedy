# winwyvern-1-check — 릴리스 기록

**버전 0.1.0** · 대상: WinWyvern — 정상 AI 도구(Ollama) 배포 페이지로 위장한 사이트로 퍼진 악성코드가 보안 제품을 무력화하려고
심는 취약 드라이버 NeacSafe64(CVE-2025-45737) · Windows · **탐지만**(바꾸지 않는다)

## 0 을 내는 갈래

| 갈래 | 근거 | 하네스 칸 |
|---|---|---|
| NeacSafe64 서비스도 System32 의 그 파일도 없다 | ASEC — 감염 흐름은 취약 드라이버를 시스템 디렉터리에 쓰고 서비스로 등록한다. 둘 다 없으면 이 룰이 볼 흔적이 없다 | `N1` |
| 서비스만 있고 System32 의 그 파일이 없다 | 1차 판정(승인 담당) — 두 근거 가운데 하나만 남은 기계는 흔적이고 0 이다(*이 룰이 보지 않는 것*) | `S1` |
| System32 의 그 파일만 있고 서비스가 없다 | 같은 판정 — 흔적이고 0 이다 | `F1` |
| 서비스의 시작 유형이 자동이 아니다(수동 · 사용 안 함 · 시스템 · 부팅) | ASEC [표 2] — 시작 유형 자동 시작. 공개 PoC 는 수동 시작이라 정상 설치와 가르지 못한다(1차 판정). 시스템 · 부팅 시작은 *다음 차수 후보* | `M1` · `M2` · `M3` · `M4` |
| 서비스가 System32 바로 아래가 아닌 자리(`System32\drivers` · `SysWOW64` 등)를 가리킨다 | ASEC [표 2] — 파일 경로 C:\Windows\System32\neacsafe64.sys. 정상 설치의 자리는 ASEC 에 없어 다른 자리는 정상 설치일 수 있다(1차 판정) | `D1` · `D2` · `D3` |

## 0.1.0 — 1차 (2026-11-24)

긴급 경로의 1차다(`docs/긴급-대응.md` · 코어 그대로). 치료는 `winwyvern-2-clean` 으로 따로 낸다 — 이름은 1차에 정했다.

**1차 출처** — ASEC, *"BYOVD를 통한 국내 보안 제품 무력화 시도: 정상 AI 도구로 위장한 악성코드 유포 주의"*(한국어판
2026-11-23 <https://asec.ahnlab.com/ko/96707/> · 영문판 2026-11-20 <https://asec.ahnlab.com/en/96708/>). 지표는 이 보고에 있는
것만 쓴다. 실검체는 없다 — 하네스는 표지 글자만 담은 자리 채우기와 시작하지 않는 서비스 등록으로 잰다.

### 무엇을 하나

- **판정** — 아래 표. 레지스트리의 서비스 등록과 디스크의 드라이버 파일, 독립적인 두 근거가 함께 서야 위협이다.
- **바꾸지 않는다** — `remediate` 가 없다. 화면은 *위협 발견, 치료하지 않았습니다* 다. 찾으면 위협별 안내의 *꼭 할 일* 로
  사람에게 넘긴다.
- **`kind: check` 가 아니다** — 그 선언은 취약한 *상태* 용이라 감염의 흔적에 붙이면 화면이 "취약" 이라고 부른다
  (`cwpdoor-1-check` 와 같다).
- **빠른 검사에 남는다** — 디스크 전체(`%FIXED_DISKS%`)를 보지 않는다. 보는 자리는 레지스트리의 서비스 목록과
  `%SystemRoot%\System32` **바로 아래**의 그 이름 파일뿐이다. System32 는 어느 Windows 에나 있어 깨끗한 기계는 6 이 아니라 0 이다.
- **고르는 화면** — `added: "2026-11-24"` 라 *새로 추가된 항목* 맨 위에 선다(코어 1.25.0).

### 판정

| 무엇 | 결과 |
|---|---|
| 서비스 NeacSafe64 가 자동 시작이고 System32 바로 아래의 neacsafe64.sys 를 가리키며, `%SystemRoot%\System32\neacsafe64.sys` 가 있다 | 위협 발견(2) — 치료하지 않는다 |
| 위 둘 가운데 하나만 있다 · 시작 유형이 자동이 아니다 · 서비스가 다른 자리를 가리킨다 | 0 — 선 근거는 화면의 흔적으로 센다 |
| NeacSafe64 가 없다 | 0 |
| 서비스 목록이나 System32 를 다 읽지 못했다 | 6 |

서비스가 가리키는 자리는 드라이버를 등록하는 길마다 꼴이 달라(커널의 꼴 · 상대 경로 · 펴지 않은 환경 변수 · NT 경로 · Win32
전체 경로 · 따옴표) 모두 받는다. Windows 폴더가 `C:\Windows` 가 아닌 기계도 받게 지었다(하네스는 `C:\Windows` 로만 쟀다). 서비스
이름 · 경로의 대소문자는 가리지 않는다.

### 이 룰이 보지 않는 것 — 종료 0 이 뜻하는 것

- **대체 데이터 스트림에 숨긴 악성 DLL**(ASEC — `C:\Windows\System32:msedge.exe`) — 엔진이 대체 데이터 스트림을 보지 못한다
  (파일 기록의 `streams` 칸을 채우지 않는다).
- **커널 메모리에만 올린 WinWyvern 드라이버** — 파일이 없다(ASEC). 지금 돌고 있는 드라이버 · 장치는 관측 대상이 아니다.
- **서비스나 파일 하나만 남은 기계** — 흔적으로 적고 0 이다(위 표). 파일만 치워졌거나 서비스만 지워진 기계가 여기 든다.
- **다른 시작 유형 · 다른 자리 · 다른 이름** — 수동 시작 · `System32\drivers` 같은 꼴의 NeacSafe64 는 정상 설치일 수 있어
  0 이다. 이름이나 자리를 바꾼 변종은 찾지 못한다.
- **설치 파일과 내려받은 페이로드** — ASEC 이 공개한 지표는 MD5 뿐이고 엔진의 파일 해시는 SHA-256 뿐이라 견주지 못한다.
- **무력화된 보안 제품의 상태** — 보안 제품의 메모리가 고쳐졌는지는 보지 않는다.
- **서비스 유형 · 미니필터 값**(ASEC [표 2] · [표 3]) — 엔진이 서비스의 유형 칸을 모으지 않고, 미니필터 값은 공개 PoC 의 INF 와
  거의 같아 정상 설치와 가르지 못한다.

그래서 종료 0 은 *"이 룰이 보는 꼴 — 자동 시작으로 등록된 그 서비스와 System32 의 그 파일 — 이 함께 있지 않다"* 이지 *"이 PC
에 WinWyvern 이 없다"* 가 아니다.

## 서명 — 배포본은 배포 키

저장소의 이 폴더에는 서명이 없다. 배포본은 태그의 배포 잡이 배포 키로 서명하므로, 내려받은 배포 파일에 든 이 폴더는 배포
키의 서명이다(`plugin verify` 로 확인한다).
