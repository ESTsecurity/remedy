# node2shell-check-windows — 릴리스 기록

**버전 0.4.0** · 대상: Node2Shell(CVE-2026-111497 · Brotli 디코더) — Windows 의 Node.js 와 PHP for Windows 의 Brotli · **점검**(바꾸지 않는다)

## 0.4.0 — NSSM 이 감싸 띄우는 node.exe · PHP (2026-11)

NSSM(srvany)으로 등록한 서비스의 `Parameters\Application` 이 선언한 자리 밖의 `node.exe` · PHP 면 **확인 필요(6)** 로
낸다(`php2shell-check-windows` 0.4.0 과 같은 꼴 · PHP 쪽은 이 룰의 PHP 자리). 0.3.0 의 서비스 규칙은 `ImagePath` 만 봐서
실행 파일 자리가 `nssm.exe` 인 서비스를 몰랐다. `npm` · `pm2` 같은 도구를 띄우는 서비스는 그 도구가 어느 `node.exe` 를
부르는지 이 룰이 알 수 없어 보지 않는다(실행 중이면 0.2.0 규칙이 본다). 코어 1.10.0 이 필요하다.

## 0.3.0 — 선언 밖을 알려 주는 자리가 늘었다 (2026-11)

선언한 자리 밖의 Node.js · PHP 를 찾는 출처를 더했다 — 그 파일은 여전히 열지 않고 경로를 적어 **확인 필요(6)** 로
낸다(목표 결정 28 · 29).

- **다른 프로그램에 모듈로 실린 PHP** — 코어 1.9.0 부터 Windows 도 실린 모듈을 모은다. 선언 밖의 PHP 코어 DLL 이
  실린 프로세스와, 모듈 목록을 읽지 못한 Apache(`httpd.exe`). `php2shell-check-windows` 0.3.0 과 같은 규칙이다.
- **서비스** — 실행 파일 자리(`ImagePath`)가 선언 밖의 `node.exe` · PHP 인 서비스. 멈춰 있어도 남는다.
- **Apache 설정** — 선언 밖의 PHP 를 싣는 `LoadModule php_module` 줄(Apache Lounge · Apache 설치 프로그램 · XAMPP ·
  WampServer · Laragon 의 설정 폴더).
- **Node.js 설치 프로그램이 적은 자리** — `HKLM\SOFTWARE\Node.js` 의 `InstallPath` 가 `Program Files\nodejs` 가
  아니다. 설치 목록(`Uninstall`)의 `InstallLocation` 은 Node.js MSI 가 비워 둔다(랩 VM 실측: Node.js 24.19.0).

## 0.2.1 — 화면 문구 (2026-11)

판정은 0.2.0 과 같다. 사유가 경로를 *위 경로* 로 가리키고(항목 줄이 주의 줄보다 위에 선다), 고친 버전을 계열마다
적는다(22 는 22.23.4 · 24 는 24.22.1 · 26 은 26.12.1 — 그 밖의 계열은 고친 버전이 없다). 자리 밖에서 도는
`node.exe` 사유에 *다른 제품이 함께 깐 것이면 그 제품을 올린다* 를, 자리 밖 PHP 사유에 *8.1 이하는 고친 버전이
없다* 를 붙였다. 이 룰이 보는 PHP 폴더 가운데 Chocolatey 는 `C:\tools\php82` ~ `php85` 뿐이다 — `php81` · `php80` ·
`php74` 에서 도는 PHP 는 자리 밖으로 알린다.

## 0.2.0 — 선언한 자리 밖의 Node.js · PHP 를 알린다 (2026-11)

선언한 자리 밖에서 찾으면 그 경로를 적고 **확인 필요(6)** 로 낸다. 그 파일은 열지 않는다(목표 결정 22).

- **실행 중인 `node.exe`** — 선언한 자리(`Program Files\nodejs` · 사용자마다의 nvm-windows · fnm · Volta · nvm) 밖.
- **PHP** — `php2shell-check-windows` 0.2.0 과 같은 세 규칙(IIS 의 FastCGI · 처리기 · 공유 설정, 실행 중인
  `php.exe` · `php-cgi.exe` · `php-win.exe`). 그 PHP 의 `brotlidec.dll` 은 보지 않았다는 뜻이다.

판정 묶음이 하나라 **하나라도** 취약(2)이 나온 회차에는 자리 밖의 항목이 화면에 나오지 않는다 — 고친 뒤 다시
검사하면 확인 필요로 나온다. 코어 1.6.0 이 필요하다(IIS 설정을 XML 로 편다).

## 0.1.0 — 처음 (2026-11)

공식 빌드의 해시로만 판정하고, 그 밖은 확인 필요로 낸다. 코어 1.3.0 의 `verdict.unconfirmed` 와 `hash_large`
(83~90 MiB 인 공식 `node.exe` 를 흘려 읽어 해시)를 쓴다.

## 무엇을 하나

- **Node.js** — `node.exe` 가 공식 빌드(win-x64 89개 버전)의 해시와 맞으면 그 버전이 판정이다. 22 · 24 · 26 계열은 고친 버전
  (22.23.4 · 24.22.1 · 26.12.1) 미만이면 **취약(2)**, 지원이 끝난 18.20.8 · 20.20.2 는 든 Brotli(1.1.0)가 영향 범위라
  **취약(2)**. 맞지 않으면(기준에 없는 버전 · 다른 빌드 · 읽지 못함) **확인 필요(6)**.
- **PHP for Windows 의 Brotli** — PHP 폴더의 `brotlidec.dll` 이 2026-10-26 재빌드(`-1` · Brotli 1.2.1) 전의 공식
  빌드(Brotli 1.2.0)이면 **취약(2)**, 재빌드면 0, 맞지 않으면 **확인 필요(6)**. 파일에 버전 정보가 없어 해시로만 가린다.
- 자리: 공식 설치 관리자(`Program Files\nodejs`) · 사용자마다의 nvm-windows · fnm · Volta · nvm(`%ALLUSERPROFILES%` —
  모든 사용자), PHP 는 `php2shell-check-windows` 와 같은 자리.

## 이 룰이 보지 않는 것

- 다른 제품 안에 든 Node.js(Electron 앱 · 단일 실행 파일 — 실행 파일 이름이 `node.exe` 가 아니다).
- 선언한 자리 밖에 놓였을 뿐 실행 중도 아니고 어디에도 적히지 않은(IIS · Apache 설정 · 서비스 · 설치 자리)
  `node.exe` · `brotlidec.dll`. `npm` · `pm2` 같은 도구를 띄우는 서비스는 그 도구가 부르는 `node.exe` 를 몰라, 실행 중일 때만 본다.
- 실행 중인 프로세스가 고친 버전을 실었는가 — 고친 뒤에는 그 서비스를 다시 시작한다.

## 근거 — 공개 자료

- CVE-2026-111497(CNA Google) — Brotli 1.0.3~1.0.10 미만 · 1.1.0~1.1.1 미만 · 1.2.0~1.2.1 미만이 영향 범위
- Node.js 2026-10 보안 릴리스 — 22.23.4 · 24.22.1 · 26.12.1
- Node 공식 해시 — nodejs.org 의 서명한 SHASUMS256 의 win-x64 `node.exe` 89개 버전. 값마다 룰에 버전을 적었다
- PHP for Windows — downloads.php.net 의 8.2.35 · 8.3.36 · 8.4.27 · 8.5.12 원래 빌드와 `-1` 재빌드 ZIP(TS · NTS).
  각 ZIP 의 SHA-256 을 같은 자리의 SBOM(`.cdx.json`)과 맞췄고, SBOM 이 Brotli 버전(1.2.0 → 1.2.1)을 적는다. 같은 빌드
  도구 묶음(vs16: 8.2 · 8.3 / vs17: 8.4 · 8.5)은 같은 `brotlidec.dll` 을 낸다(2026-11-09 실측)

## 서명 — 저장소 사본은 개발용 키, 배포본은 배포 키

저장소의 `MANIFEST` · `MANIFEST.minisig` 는 저장소 사본을 확인하려고 **개발용 키로** 서명한 것이다. 배포본은
태그의 배포 잡이 배포 키로 다시 서명하고 그 공개키를 박아 빌드하므로, 내려받은 배포 파일에 든 이 폴더는 배포
키의 서명이다(`plugin verify` 로 확인한다). 개발용 키로 서명된 룰은 배포 앵커가 박힌 실행 파일에서 거부된다.
