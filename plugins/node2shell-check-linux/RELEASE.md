# node2shell-check-linux — 릴리스 기록

**버전 0.5.0** · 대상: Node2Shell(CVE-2026-111497 · Brotli 디코더) — 리눅스의 Node.js 와 그것이 쓰는 시스템 Brotli · **점검**(바꾸지 않는다)

## 0.5.0 — 서비스로 등록된 Node.js (2026-11)

systemd 유닛이 선언한 자리 밖의 `node` 를 띄우면(`ExecStart` 의 첫 낱말) 그 유닛과 실행 파일을 적어 **확인 필요(6)** 로
낸다 — 돌고 있지 않아도 유닛 파일이 남는다(목표 결정 28 · 0.2.0 의 실행 중 규칙과 같은 자리 정규식). nvm · fnm ·
Volta 의 자리는 선언한 자리다. pm2 가 띄우는 앱은 유닛의 첫 낱말이 pm2 라 여기서 보지 않는다(실행 중이면 0.2.0
규칙이 본다). `php2shell-check-linux` 0.5.0 과 같은 규칙이다.

## 0.4.0 — 다시 시작하지 않은 Node.js 를 알린다 (2026-11)

실행 중인 프로세스의 실행 파일 `node` · `nodejs` 나 실린 `libnode.so*`(Debian 의 `node` 가 싣는 본체) ·
`libbrotlidec.so*`(시스템 Brotli)가 지워진 옛 파일이면(` (deleted)`) 그 프로세스는 고치기 전 코드를 실은 채 돈다 —
패키지나 Node.js 를 올리고 그 앱(pm2 · systemd 서비스 등)을 다시 시작하지 않은 것이다. 그 경로를 적어 **확인
필요(6)** 로 낸다. `php2shell-check-linux` 0.4.0 의 `stale_php` 와 같은 규칙이고 코어 1.7.0 이면 된다.

## 0.3.0 — 패키지가 깐 node 를 패키지 기록과 대조한다 (2026-11)

패키지 버전으로 서는 판정(Debian 의 nodejs · Debian 의 libbrotli1 · Oracle Linux 8.10 의 nodejs 모듈)은 패키지가
깐 `node`(`/usr/bin/node` · `/usr/bin/nodejs`)가 **패키지 기록과 같을 때만** 세운다 — `php2shell-check-linux` 0.3.0
과 같은 규칙이고 코어 1.7.0 이 필요하다. 다르거나 · 기록이 없거나 · 끝까지 읽지 못했으면 그 경로를 적어 **확인
필요(6)** 로 낸다. 공식 빌드 해시 판정(`node_vuln`)은 그대로다.

- Debian 의 `/usr/bin/node` 는 `libnode` 를 싣는 작은 실행 파일이다 — 실제 코드가 든 `libnode.so` 는 보는 자리
  밖이라 대조하지 않는다.
- Debian 이 고치지 않은 것으로 확인한 버전(`deb_node_vuln` 의 목록)을 *기준 없는 Node.js 패키지* 로 세지 않는다 —
  그 버전은 기준이 있다. 0.2.0 에서는 늘 취약(2)으로 서서 드러나지 않았고, 실행 파일이 기록과 달라 판정을 세우지
  않는 회차에 그 사유가 함께 섰다(개발 빌드 실측).
- 화면 문구: 사유가 경로를 *위 경로* 로 가리킨다 · 확인할 고친 버전을 계열마다 적는다(그 밖의 계열은 고친 버전이
  없다).

## 0.2.0 — 선언한 자리 밖에서 실행 중인 node 를 알린다 (2026-11)

실행 파일이 `node` · `nodejs` 인 프로세스가 선언한 자리(`/usr/bin` · `/usr/local/bin` 바로 아래의 `node*` ·
`/opt/node` · `/opt/nodejs` · `/usr/local/lib/nodejs` · `/root` 와 `/home/<누구>` 의 nvm · fnm · Volta) 밖에서 돌면
그 경로를 적고 **확인 필요(6)** 로 낸다. 그 Node.js 는 판정하지 않는다(목표 결정 22). 코어는 1.3.0 그대로다.

- 바뀐 뒤 다시 시작하지 않은 프로세스의 실행 파일에는 ` (deleted)` 가 붙어 이 이름 꼴에 맞지 않는다.
- 컨테이너 안에서 다른 사용자로 도는 프로세스를 들여다보지 못하면 관측 불완전(6)이다 — `php2shell-check-linux`
  0.2.0 의 같은 줄.
- 판정 묶음이 하나라 **하나라도** 취약(2)이 나온 회차에는 확인 필요 항목(자리 밖의 `node` 등)이 화면에 나오지
  않는다 — 고친 뒤 다시 검사하면 나온다.

## 0.1.0 — 처음 (2026-11)

공식 빌드의 해시와 공급사 공지로 판정하고, 그 밖은 확인 필요로 낸다. 코어 1.3.0 의 `verdict.unconfirmed` ·
`hash_large`(공식 `node` 를 흘려 읽어 해시) · RPM 수집 · `rpm_version_lt` · `vendor` 를 쓴다.

| 패키지가 깐 `node` 가 패키지 기록과 다르다 · 기록이 없다 · 끝까지 읽지 못했다(0.3.0) | **확인 필요(6)** — 그 패키지 버전으로 판정하지 않는다 |

해시하지 않는다.

## 이 룰이 보지 않는 것

- 다른 제품 안에 든 Node.js(Electron 앱 · 단일 실행 파일 · 컨테이너 이미지).
- 선언한 자리 밖에 놓였을 뿐 실행 중이 아닌 `node`.
- RPM 의 Node.js 가 시스템 Brotli 를 쓰는지 — 그 자리는 확인 필요로 남긴다.
- 실행 중인 프로세스가 고친 버전을 실었는가 — 고친 뒤에는 그 서비스를 다시 시작한다.

## 서명 — 저장소 사본은 개발용 키, 배포본은 배포 키

저장소의 `MANIFEST` · `MANIFEST.minisig` 는 저장소 사본을 확인하려고 **개발용 키로** 서명한 것이다. 배포본은
태그의 배포 잡이 배포 키로 다시 서명하고 그 공개키를 박아 빌드하므로, 내려받은 배포 파일에 든 이 폴더는 배포
키의 서명이다(`plugin verify` 로 확인한다). 개발용 키로 서명된 룰은 배포 앵커가 박힌 실행 파일에서 거부된다.
