# 업데이트 내역 조각

룰 PR 은 [`docs/업데이트-내역.md`](../업데이트-내역.md) 를 고치지 않고 이 폴더에 **조각 하나**를 더한다(2026-11-21).
여럿이 같은 main 에서 함께 지어도 서로 다른 파일이라 부딪히지 않는다 — 전에는 그 파일 맨 위 칸을 고쳐 병합할 때마다
충돌했다.

## 어디에 실리나

- **출시** — 배포 잡이 *지금 Latest 의 트리에 없고 그 태그의 트리에 있는 조각* 을 모아 릴리스 본문의 *2. 변경 내용* 을
  짓는다(`cargo xtask changes --since <Latest 의 태그>` · `ci/release-notes.sh`). 어느 출시에 실리는지를 git 이 정하므로,
  버린 묶음의 조각은 다음 묶음에 저절로 실린다.
- **업데이트 내역 파일** — 하루 한 번 `bash ci/batch.sh views` 가 공개한 출시마다 같은 조각으로 그 칸을 지어 넣고, 옮긴
  조각을 이 폴더에서 지운다(그래서 그 파일은 최대 하루 늦다).

## 파일 이름

- 룰 하나 — `<룰 id>-<새 버전>.md`(예: `php-2026-11-check-linux-0.4.1.md`)
- 그 밖 — `<주제>-<날>.md`(예: `batch-release-2026-11-21.md`)
- 공개한 조각의 이름을 다시 쓰지 않는다 — 출시는 지금 Latest 의 트리에 없는 이름만 새 조각으로 센다.

## 꼴

```text
---
section: rules
rules: [php-2026-11-check-linux, php-2026-11-check-windows]
---
* **세션 점검의 판 줄 바로잡기** (Linux)\
  설명 한 줄 — 합쇼체로 적습니다.
```

| 머리 칸 | 뜻 |
|---|---|
| `section` | `rules` · `프로그램` · `그 밖` 가운데 하나 |
| `rules` | `section: rules` 일 때만 — 이 조각이 말하는 룰의 `id` 를 한 줄로(`rules: [a, b]` — 공개 걸음이 그 줄을 읽는다). 한 조각의 위협 룰은 한 위협(README *다루는 위협* 표의 한 줄)이다. 표의 한 줄은 룰 이름 · 하는 일 · 참고가 모두 같은 룰을 묶는다(위 예시의 OS 짝) — 하는 일이 다른 점검 · 치료 짝(`<사고>-1-check` · `<사고>-2-clean`)은 두 줄이라 조각도 둘로 나눈다. 데이터 룰(`remedy-net-criteria`)은 그 기준을 쓰는 위협 룰과 함께 적는다 |

본문은 받는 사람이 읽는 글이다 — 업데이트 내역 머리의 꼴 그대로다.

- 말투는 합쇼체다 — 단계 안내는 "…합니다", 경고 · 금지만 "…하십시오".
- `* **바뀐 것 — 명사형으로 끝낸다** (한 OS 에만 해당하면 그 OS)\` 줄과 그 아래 두 칸 들인 설명 한 줄. 필요하면 `  * ` 로 나눈다.
- 알아 둘 점 · 자세한 안내 링크는 `<details><summary><b>알아두실 점 및 자세한 내용 보기</b></summary>` … `</details>` 안에.
- 한 문단 · 한 항목을 한 줄에 적는다 — 릴리스 본문은 줄바꿈을 그대로 그린다.
- 링크는 `https://` 절대 주소로 — 상대 주소는 릴리스 본문에서 열리지 않는다.
- `#` 로 여는 줄을 쓰지 않는다 — 칸 머리(`## 룰 <룰 버전> · 프로그램 <엔진> — <날>`)와 위협 소제목(`### <위협 표 이름에서 끝의
  ' (…)' 한 덩이를 뺀 것>`)은 모으는 쪽이 짓는다. 차례는 위협 표의 차례 → `### 프로그램` → `### 그 밖` 이고, 같은 위협의 조각
  여럿은 파일 이름순으로 한 소제목에 모인다.
- 판정은 그대로이고 안내 글만 고쳤으면 판정이 바뀐 것처럼 적지 않는다.

## 검사

`cargo xtask all` 의 `fragments` 가 PR 에서 본다.

- 조각마다 꼴 — 머리 칸 · 있는 룰인가 · 한 위협 · 제목 줄 · 상대 링크 · `<details>` 짝 · 코드 블록 짝 · `{{`
- git 바탕(PR 은 받는 가지 · [`개발-안내.md`](../개발-안내.md#커밋하기-전에))보다 `version` 이 바뀐 룰(새 룰 포함)마다 바탕
  뒤에 더한 조각이 그 룰을 적었는가

미리 보기 — `cargo xtask changes --since <지금 Latest 의 태그>` 가 다음 출시의 *2. 변경 내용* 을 그대로 낸다.
