# ex04 — 점검 전용: 아무것도 바꾸지 않는 플러그인

**이 예제가 가르치는 것**: `kind: check` 를 적고 `remediate` 를 **뺀** 플러그인으로
**노출 조건**을 보는 법.
무엇이 **있는지** 만 말하고 아무것도 지우지 않는다 — 취약점 점검 도구가 이 모양이다.
규약 전체는 `24-check-plugins.md` 에 있다.

`ex01` 도 `remediate` 가 없지만 `kind` 를 적지 않고 **감염 흔적**을 찾는 예제다. 상태를 `not` 과 설치본
그룹으로 보는 점검은 없었다 — 그것이 이 예제의 자리다.

## 파일

| 파일 | 무엇 |
|---|---|
| `plugin.yaml` | 룰 — `kind: check` 가 있고 `remediate` 가 없다 |
| `artifacts.json` | 입력 스냅샷 — PHP-FPM 둘(8.2 · 8.3) · CLI 하나 · 함정 둘 |
| `expected-plan.json` | 기대 계획 — **`actions` 가 빈 배열**이고 판정은 하나 |

`cargo test -p remedy-core --test guide` 가 이 셋을 실제로 돌린다.

## 무엇을 점검하는가

PHP 의 세션 업로드 진행 표시(`session.upload_progress.enabled`)는 공개 권고가
지목한 **노출 조건**이다. 기본값이 **켜짐**이다. 이 예제는 *"FPM 풀이 열려 있는데
그 FPM 의 `php.ini` 가 그것을 꺼 두지 않았다"* 를 찾는다.

| 스냅샷의 설치본 | 결과 | 왜 |
|---|---|---|
| `/etc/php/8.2/fpm` | **판정이 선다** (`g0`) | 풀이 열려 있다. `php.ini` 의 끄는 줄은 `[PATH=/var/www/admin]` 안에만 있다 — 그 경로에만 걸린다 |
| `/etc/php/8.3/fpm` | 서지 않는다 (`g1`) | `Off ; mitigation for …` 로 껐다 — 줄 끝 주석이 붙어 있다 |
| `/etc/php/8.2/cli` | 보지 않는다 | 풀이 아니다. **여기서 껐다고 FPM 이 꺼지지 않는다** |

> **이것은 버전 판정이 아니다.** 노출 조건 하나를 볼 뿐이고, 권고는 *"설정만으로
> 안전하다고 하지 말라"* 고 적었다. 버전 점검은 `version_lt` · `version_gt` 와
> `file.version`(Windows PE 가 선언한 문자열 `FileVersion`)으로 쓴다 — 그러나 **이 예제는
> Linux 고 ELF 에는 그 구조가 없다.** 리눅스 바이너리의 버전은 YARA 로 문자열을
> 훑는 길뿐이고, 예제 시험은 YARA 룰 없이 평가하므로 그런 실물은 예제로 둘 수
> 없다 — `24-check-plugins.md` §버전.

## 여섯 가지를 보여 준다

### 1. `kind: check` 를 적고 `remediate` 를 빼면 아무것도 바꾸지 않는다

계획의 `actions` 가 빈 배열이다. `run` 으로 불러도 *"점검만 하는 룰이므로 바꿀 것이
없습니다"* 를 내고 **승인을 묻지 않는다** — 바꿀 것이 없으면 승인할 것도 없다.
종료 코드가 곧 점검 결과다: **2** 취약하다 · **0** 취약한 곳을 찾지 못했다 ·
**6** 다 보지 못했다.

**PHP 가 없는 기계에서는 0 이다**(B-6 · 2026-10-26). `scan_roots` 의 `/etc/php` 가
없는 것은 *확인 필요* 가 아니라 **해당 없음**이고, 그것이 가장 흔한 경우다. 0 이 두
뜻을 담게 되었으므로 화면이 어느 쪽인지 말한다 — *"점검 대상이 이 기계에 없습니다"*
안내 줄에 없던 경로가 함께 적힌다.

`kind` 를 빼면 **같은 룰이 6 을 낸다.** 그 한 줄이 가르는 것이다.

### 2. 기본값이 켜짐이면 "켰다" 가 아니라 "끄지 않았다" 를 본다

```yaml
verdict:
  require: "pool and not turned_off"
```

`On` 을 찾는 규칙을 쓰면 **줄이 없는 설치본을 놓친다** — 그런데 그것이 가장 흔한
노출이다(기본값). `not` 으로 *"끄는 줄이 없다"* 를 말한다.

**`pool and` 를 빼면 안 된다.** 풀이 없으면 자식은 평가되지 않아 0건이고, `not
turned_off` 는 **참**이 된다 — `not turned_off` 만 남기면 PHP 가 없는 기계에서도 증거
0건으로 판정이 선다(실측). 판정을 설치본으로 좁히는 것은 앞의 `pool and` 다.

### 3. `from` 이 같은 설치본으로 묶는다

`turned_off` 는 `from: "${pool.fpm_dir}"` 로 **그 풀의 FPM 폴더 안**만 본다. 같은
버전이라도 CLI 는 **다른 파일, 다른 프로세스**다.

**빼 보면 판정이 0 이 된다**(실측). 설치본이 그룹으로 갈리지 않고 한 그룹에 전부
섞여 — 풀 둘과 `Off` 둘(CLI 것까지) — **어느 한 곳의 `Off` 가 전부를 지운다.** 노출된
8.2 를 놓치고 *"없다"* 라고 말한다. 점검에서 가장 나쁜 실패다.

캡처는 이어 쓴다: `path | dirname | dirname` 이 `…/fpm/pool.d/www.conf` 에서
`…/fpm` 을 낸다.

### 4. 거짓 표기를 다 덮는다 — 함정 하나

PHP 는 `Off` · `0` · `false` · `no` · `none` · `null` · 빈 값 · 따옴표 친 값을 모두 거짓으로
읽고 줄 끝 `;` 주석을 뗀다. 수집기의 `value` 는 `=` 뒤를 다듬기만 한 원문이라
따옴표와 주석이 **남는다.**

8.3 의 `Off ; mitigation for …` 가 그 함정이다. `(?i)^(off|0|false|no)$` 로 쓰면 이 줄을
*안 껐다* 로 읽어 **꺼 둔 8.3 을 노출로 보고한다**(실측 — 판정이 `g0` · `g1` 둘이 된다).
정규식은 YAML **작은따옴표**에 둔다 — 큰따옴표 안의 `\s` 는 YAML 이 거부한다.

### 5. 경로 한정 섹션은 전체를 끄지 않는다 — 함정 둘

`[PATH=…]` · `[HOST=…]` 안의 값은 그 경로 · 호스트에만 걸린다(FastCGI). 8.2 의 끄는
줄이 `[PATH=/var/www/admin]` 안에 있다 — FPM 전체는 켜져 있다. `exclude` 로 그 섹션을
뺀다. **`exclude` 를 빼면 8.2 를 끈 것으로 읽어 판정이 0 이 된다**(실측).

### 6. `equals` 는 접두사를 잡지 않는다

`key equals "listen"` 은 같은 파일의 `listen.owner` 를 잡지 않는다. 풀 하나에 근거가
하나만 서야 그룹이 하나다.

## 보지 않는 것

이 예제는 **그 FPM 의 `php.ini` 만** 본다. 실효값을 바꾸는 아래 자리에서 껐으면
오탐, 다시 켰으면 미탐이다. 실제 점검 룰은 이 자리를 함께 본다.

- `conf.d/*.ini` — 이름순으로 뒤에 읽힌다. Debian 의 `phpenmod` 가 만드는 것은
  **심볼릭 링크이고, 수집기는 링크를 따라가지 않는다**
- FPM 풀의 `php_value[…]` · `php_flag[…]` · `php_admin_value[…]` · `php_admin_flag[…]`
- 웹 서버가 넘기는 `PHP_VALUE` · 디렉터리별 `.user.ini`
- 같은 키가 `php.ini` 뒤쪽에 다시 나오면 **뒤의 값이 이긴다** — 집합 조건으로는 쓸 수 없다

## 고쳐 쓸 때

- **청정 코퍼스에서 판정이 서면 안 된다.** 시험이 *"판정 0"* 을 요구한다. 감염 없는
  기계도 취약할 수 있으므로 점검에서는 이 요구의 뜻이 다르다 —
  `24-check-plugins.md` §청정 코퍼스.
- 꾸러미에 치료 플러그인과 함께 담으면 폴더 이름으로 차례를 정한다 —
  `<사고>-1-check` · `<사고>-2-clean`.
