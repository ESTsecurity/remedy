# 존재하지 않는 기능 — 지어내지 않는다

선행: `00-invariants.md`

아래는 **없다.** 각 항목에 *"대신 무엇을 쓰는가"* 를 함께 적는다 — 부정만 하면
다른 방식으로 같은 것을 시도하게 된다.

---

## 실행·쓰기

| 없는 것 | 대신 |
|---|---|
| 임의 명령 실행 (`exec` · `run_command` · `powershell` · `shell`) | 없다. 파괴 동작은 **카탈로그에 있는 Op 뿐**이고 그 목록은 `machine/ops.json` 이다 |
| 파일 **쓰기·수정** Op | 없다. 파괴(`file.delete` 계열)와 원복(`restore`)만 있다. 내용을 고치는 것은 `registry.strip_value` 처럼 **정해진 형태의 부분 편집**뿐이다 |
| 새 파일·키 **생성** | 없다. 이 도구는 지우고 되돌리기만 한다 |
| 스크립트 런타임 (`script:` · `lua:` · `js:`) | **현재 버전에 없다.** 룰은 선언이고 코드가 아니다 |

**왜 없는가.** 임의 명령 실행이 있으면 이 도구는 "서명된 원격 실행 엔진" 이 된다.
플러그인이 곧 실행 코드가 되는 순간 서명의 뜻이 *"이 파괴 지시서를 검토했다"* 에서
*"이 프로그램을 검토했다"* 로 바뀌고, 뒤엣것은 실질적으로 검토가 불가능하다.

## 네트워크

| 없는 것 | 대신 |
|---|---|
| 룰에서 HTTP 요청 | 없다. `collect` · `evaluate` · `plan` · `apply` 경로에는 **네트워크를 말하는 코드가 링크되지 않는다** |
| 룰에서 평판 조회 | 조회는 `enrich` 단계이고 룰이 부르지 않는다. 결과는 `reputation` 으로 실려 오되 **삭제를 줄일 수만 있다** |
| 룰에서 검체 전송 | `submit_hint` 로 **무엇을 보낼지 표시**만 한다. 보내는 것은 별도 단계이고 동의가 필요하다 |
| 외부 지표 파일 참조 (`ioc_file:` · `feed:` · URL) | 없다. 목록은 매니페스트 안에 `in` 으로 적는다 — 서명 범위 안에 있어야 한다. `20-detect-recipes.md` §알려진 지표 목록 |

| `confidentiality_min` 하향 | 하한만 올릴 수 있다 |

## 판정 문법

**문법은 닫혀 있다** — 이 넷뿐이다 (설계-02 §5). 넓힌 만큼 판정이 불투명해진다.

| 형태 | 뜻 |
|---|---|
| `<rule-id>` | 그 규칙이 **한 건이라도** 매치됐다 |
| `and` · `or` · `not` | 논리 결합. **`and` 가 `or` 보다 강하게 묶는다** — `a or b and c` 는 `a or (b and c)` 다 |
| `( … )` | 묶음. 우선순위를 뒤집는다 |
| `count(<rule-id>) >= N` | 그 규칙이 **N건 이상** 매치됐다. `>` 는 없다 — `>=` 뿐이다 |

```yaml
require: "appinit and (payload or config)"   # 부모 하나 + 독립 근거 아무거나 하나
require: "task and count(payload) >= 2"      # 한 건으로는 서지 않게
```

> 2026-09-02 까지 예제 셋과 이 문서의 모든 예가 `"a and b"` 뿐이라 **나머지를
> 쓸 수 있다는 것이 보이지 않았다.** `or` 가 필요한 자리가 있다 — 두 번째
> 근거를 하나로 못박으면 그 근거가 이미 사라진 기계(다른 백신이 바이너리만
> 잡아간 기계)에서 판정이 서지 않는다 (`40-review-checklist.md` 2번).

| 없는 것 | 대신 |
|---|---|
| 점수 임계값 (`threshold` · `score >= 80`) | `verdict.require` 의 불 대수식. `score` 는 보고용이다 |
| `or` 만으로 된 판정 | 문법상 되지만 **근거가 하나뿐인 것과 같다** — 린트가 경고한다 |
| 정규식 역참조 `\1` · 전방탐색 `(?=)` | **RE2 다.** 입력 길이에 선형이라 룰이 스캐너를 멈추는 사고가 원천 차단된다. 대신 조건을 나눠 `all:` 로 묶는다 |
| 임의 시각·난수 | 없다. 평가는 결정적이어야 하고, 그래야 계획 비교로 회귀를 잡는다 |

## 필드·대상

**전수는 생성물에 있다** — `machine/subjects.json` · `machine/catalog.json`.
이 문서에 목록을 옮겨 적지 않는다. 옮겨 적는 순간 낡기 시작한다.

없는 필드를 쓰면 린트가 **유효 필드 전수**와 함께 거부한다. 그 목록이 답이다 —
거기 없으면 없는 것이다.

| 흔한 착각 | 사실 |
|---|---|
| `cmdline` | 없다. `command` 와 `args` 로 나뉜다 |
| 살아 있는 네트워크 연결 (`network_conn`) | subject 에 없다. 연결은 관측 대상이 아니다 |
| `file.content` 를 조건으로 직접 비교 | 없다. 내용 판정은 `yara:` 로 한다 |

## 볼 수 없는 것 — 빈 값은 "없다" 가 아니다

관측은 완전하지 않다. **관리자로 돌려도 그렇다.** 빈 값을 "그것이 없다" 로 읽는
룰은 조용히 빗나간다.

| 빈 값 | 뜻 | 대신 |
|---|---|---|
| `process.cmdline` 이 빈 문자열 | **우리에게 없다.** 보호 프로세스의 명령줄은 OS 가 아무에게도 주지 않는다 | 그 프로세스가 무엇으로 등록되었는지를 본다 — `service` 의 `image_path` · `start_type`, `autorun` 의 `command` |
| `process.modules` 가 빈 배열 | **봤고 없었거나, 모듈을 실을 수 없는 프로세스다** — Linux 의 커널 스레드, Windows 의 보호 프로세스(PPL — 서명된 모듈만 싣는다)와 끝난 프로세스. 두 플랫폼 다 채운다(Linux 는 `/proc/<pid>/maps` 의 실행 가능한 파일 매핑, Windows 는 2026-11-12 부터 Toolhelp 스냅숏 — 룰이 모듈 칸을 쓸 때만 연다) | 목록을 **못 읽은** 프로세스는 `process.modules_denied` 가 `"true"` 다 — 스스로를 지키는 보안 제품이 그 꼴이다(랩 VM 실측 둘). 룰이 볼 자리(웹 서버 · PHP)라면 그 칸을 함께 본다 |
| `text_config.key` 가 빈 문자열 | 그 줄이 **`키=값` 이 아니다.** `.htaccess` 의 `php_value x 1` · `pam.d` 의 `auth required …` 가 그렇다 — `=` 가 없으면 `line` 만 찬다 | `line contains` 로 겨눈다. `=` 가 **줄 안쪽에** 있으면 `key` 가 거기서 끊겨 엉뚱한 이름이 된다(실측: 청정 코퍼스 6,320줄 중 474줄) — 그 줄도 `line` 으로 본다 |

> **2026-10-27 부터 2026-11-12 까지는 Windows 가 이 목록을 늘 비웠다**(열거가 unsafe
> 였다). 그동안 린트와 `scan.json` 이 Windows 플러그인에 *"채우지 않는 필드"* 라고
> 말했다 — 그 전에는 둘 다 침묵해서, 모든 프로세스가 싣는 모듈을 조건으로 건 룰이
> 회차를 *"위협이 발견되지 않았습니다"* 로 끝냈다. 이제 Windows 도 채우므로 그 경고는
> 없다.
>
> 빈 목록의 평가는 그대로다 — 평가기가 목록을 JSON 문자열로 꺼내므로 `[]` 도 있는
> 값이다.
>
> | 쓴 술어 | 빈 목록에서 |
> |---|---|
> | `modules contains '...'` | 걸리지 않는다 |
> | `modules exists` | **걸린다** — 보호 프로세스처럼 목록이 빈 프로세스까지 고른다 |

실측 (2026-09-01, Windows 10 · 관리자): 프로세스 145개 중 19개의 명령줄이
비었다 — `csrss` · `wininit` · `services` · `smss` · 보안 제품 · `svchost` 4개.
같은 기계에서 WMI(`SeDebugPrivilege` 를 가진 SYSTEM 서비스)에 물어도 준 것은
**0개**였다. 권한을 더 올려서 되는 일이 아니다.

**이 19개는 관측 불완전로 보고되지 않는다.** 늘 그러하기 때문이다 — 상시로
뜨는 경고는 경고가 아니다. 대신 여기 적어 둔다.

> 반대로 **방화벽 규칙이 0건인데 관측이 깨끗하면 그것은 버그였다.** 키가
> 잠겼는지 없는지 가리지 않았기 때문이다. 지금은 잠긴 것을 거부로 세고
> 종료 코드 6으로 말한다.

## "아직 없는 것" 과 "영원히 없는 것"

린트는 둘을 **다르게** 말한다. 아직 없는 것에는 **언제 오는지**가 붙는다.

```
아직:  … 의 수집기는 아직 없다 (현재 코어: P12) (P13 에서 사용 가능해진다)
영원:  알 수 없는 필드 "cmdline" — 유효 필드: command, args, principal, …
```

앞엣것은 기다리면 된다. 뒤엣것은 다른 이름을 찾아야 한다. **그 구분이 오류
메시지에 들어 있으므로 메시지를 끝까지 읽는다.**

> **이 갈래는 subject 에만 붙고, 지금은 비어 있다** — subject 21종이 전부
> 구현됐다(P2·P4 · 현재 코어 P12 · `package` 가 2026-10-27 에, `unix_socket` 이 코어 1.2.0 에, `archive_entry` 가 1.11.0 에 더해졌다). 카탈로그에 새 subject 가 예고되면 다시
> 나온다. **Op 은 이 갈래가 아니다** — 아직 오지 않은 Op 은 린트가 아니라
> 계획 단계에서 `deferred` 로 빠진다(`22-remediate-recipes.md`).
