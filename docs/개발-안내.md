# 개발 안내 — 이 저장소에서 일할 때 걸리는 것들

이 문서는 **코어를 고치거나 검증을 돌리는 사람**이 읽는다. 룰만 쓰는 사람은
[`plugin-guide/README.md`](plugin-guide/README.md), 도구를 돌리는 사람은
[`operator.md`](operator.md) 가 먼저다.

여기 적힌 것은 전부 **한 번씩 겪고 나서 알게 된 것**이다. 대부분은 실패가
엉뚱한 곳을 가리키는 종류여서, 모르면 같은 자리에서 같은 시간을 쓴다.

## 저장소 한눈에 — README 에서 옮겨 왔다 (2026-11-06)

`README.md` 는 받아서 쓰는 사람의 첫 장이 되었다. 개발자가 알아야 할 것은 여기 둔다.

**템플릿 하나 + 위협별 플러그인.** 위협마다 단품 도구를 찍어내면 관리 비용이 무한히
누적된다. remedy 는 바이너리 하나를 두고 위협별 대응을 **선언적 룰**로 표현한다. 새 위협
대응은 `plugin.yaml` 과 `rules/*.yar` 만 배포하면 된다 — 코어를 다시 만들지 않는다.
실행 파일은 CRT 정적 링크라 재배포 패키지가 필요 없고, **네트워크를 말하는 코드가
링크되지 않는다** — 임포트 전수를 `cargo xtask static` 이 매번 확인한다.

**설계의 척추 셋.**

1. **파괴 동작은 실행 전에 계획으로 완전히 확정된다.** `collect → evaluate → plan →
   apply` 각 단계가 파일 아티팩트로 나뉘며, `apply` 는 `plan.json` 에 있는 것만 수행한다.
   드라이런의 정확성 · 삭제 상한의 사전 차단 · 감사 완전성이 전부 여기서 파생된다.
2. **스크립트는 읽고, 룰은 쓴다.** 플러그인은 관찰과 제거 대상만 선언하고, 순서 · 백업 ·
   프로세스 종료는 코어가 정한다.
3. **되돌리기가 지우기보다 먼저다.** 격리 · 복원이 첫 파괴 동작보다 앞선 Phase 에 완성된다.

**규칙은 문서가 아니라 CI 가 지킨다** — 아래 "커밋하기 전에" 의 명령 일곱이 그것이다.
`arch` 의 금지 의존 목록과 `trace` 의 인벤토리는 **코드에 박혀 있지 않고 설계 문서에서
읽는다** — 같은 사실을 두 곳에 적으면 반드시 갈라지기 때문이다.

**아직 없는 것.**

| | |
|---|---|
| 코드서명한 공개본 | **서명 도구는 서명하는 기계에 있고(2026-11-18 · Azure Trusted Signing) 배포 차례의 한 걸음이다**(아래 "출시 검증" 3 · 5). 그 전에 낸 공개본(1.23.0 · 룰 2026.11.18 까지)은 코드서명이 없다. **기능은 서명 없이 전부 동작한다**(2026-09-02) — 서명이 없다는 이유로 치료를 막지 않고, 대신 매 실행에서 *"코드서명이 없어 공식 배포본인지 스스로 확인하지 못합니다"* 라고 말한다 — 서명 없는 공식 파일도 이 줄을 띄우므로 '공식 배포본이 아닙니다' 라고 단정하지 않는다(2026-11-06). 공식 배포본에만 서명한다 — 개발 빌드 · 하네스가 짓는 빌드는 서명하지 않는다 |
| 서명된 룰만 로드 (P10-A2) | 검증(`plugin verify`)은 섰다. **강제가 도는 자리가 안내 모드 하나**다 — 인자 없이 실행하면 옆에 놓인 꾸러미 중 검증을 통과한 것만 쓴다. `run --plugin <경로>` 로 직접 준 것은 **서명을 보지 않는다.** 릴리스 키가 서야 켠다 |
| 사내 분석시스템 연동 (P13) | `enrich` — 조회는 사내에서 실행한다는 결정(D9) 아래 설계만 서 있다. 치료 경로는 이것 없이 완결이다 |
| GUI (P15) | CLI 만 |

**제출 기능은 제품 범위 밖이다** (2026-08-28). 분석가가 손으로 올리고 remedy 는
`support-bundle` 까지만 만든다 — 근거는 설계-09 "제출을 제품 밖으로".

## 커밋하기 전에

| 명령 | 무엇을 보나 |
|---|---|
| `cargo fmt --all -- --check` | 서식 |
| `cargo clippy --workspace --all-targets -- -D warnings` | 린트 |
| `cargo clippy -p remedy-cli -p remedy-net -- -D clippy::print_stdout -D clippy::print_stderr -D clippy::dbg_macro` | 실행 파일의 코드(두 실행 파일과 그것이 링크하는 작업 공간 크레이트)가 화면에 `println!` 류로 쓰지 않는가 — 읽는 쪽이 먼저 닫힌 파이프에서 패닉해 1.21.0 까지는 치료 도중에 7 로 멈췄다. 본체는 `outln!` · `screen_err!` 등, `remedy-net` 은 `crate::outln!` 등으로 쓴다 |
| `cargo xtask all` | 저장소 검사 열세 가지 |
| `cargo test --workspace` | 시험 전부 |
| `cargo xtask leaks` | 공개하지 않는 값 · 넣는 목록 밖의 파일 |
| `cargo deny check` | 의존의 보안 권고 · 라이선스 · 출처 · 금지 — 권고는 새 공지가 나오면 코드와 상관없이 실패한다 |

**`cargo xtask all` 과 `cargo test` 는 서식·린트를 보지 않는다.** 그 둘만 돌리고
커밋해 CI 의 fmt 가 깨진 적이 있다. CI(`.github/workflows/ci.yml`)는 위 표의
명령을 그대로 돈다.

**`leaks` 는 push 하기 전에 돌린다 — CI 는 병합을 막을 뿐이다.** PR 에 올라간
커밋은 가지를 지워도 그 PR 로 닿는다. PR 의 참조(`refs/pull/`)는 읽기 전용이라
지우려면 GitHub 지원에 맡겨야 하고, 저장소가 public 이 되면 PR 과 함께 보인다.

**rustfmt 가 한 번에 안 맞는 자리가 있다.** 중첩 안의 긴 한글 문자열
(`f(&x, format!("…"))` 꼴)은 한 번 돌린 뒤에도 `--check` 가 다른 모양을
요구한다. 두 번째에 수렴하지만 들여쓰기가 흐트러진 채 남으므로, 메시지를
`let why = format!(…);` 로 먼저 빼서 중첩을 줄이는 편이 낫다. **`fmt` 뒤에는
`--check` 를 한 번 더 돌린다.**

**`cargo test -p xtask` 는 시험 실행만 10분이 넘는다**(`exam` 쪽이 무겁다).
컴파일이 느린 것이 아니다. 시한에 걸려 끊긴 것을 "멈췄다" 로 읽지 않도록,
처음부터 백그라운드로 돌리고 기다린다. 새로 쓴 모듈만 볼 때는
`cargo test -p xtask <모듈 이름>` 으로 걸러 수십 초에 끝난다.

## 빌드와 산출물

**`target/release/xtask.exe` 는 저장소에 없으므로 낡는다.** 마지막으로 지은
사람의 판이 남아, 새로 더한 서브커맨드를 모르고 `알 수 없는 작업` 으로 떨어진다.
하네스의 정적 링크 검사는 그 exe 가 있으면 **그것을 먼저 부르므로**, 낡은 판으로
조용히 통과할 수도 있다. `xtask` 로 무언가를 재기 전에 `--help` 로 그 명령을
아는지 보고, 모르면 `cargo build --release -p xtask` 로 다시 짓는다.

**무거운 빌드를 겹치지 않는다.** 전체 시험 · 리눅스 CI · 컨테이너 빌드를 함께
돌리면 링커가 `LNK1102: out of memory` 로 죽는다. 원인은 여유 RAM 이 아니라
**커밋 한도**다 — VM 과 WSL 이 쥔 양이 합산된다. 그 뒤 재실행은 반쯤 쓴 산출물
때문에 코드와 무관한 오류(`required to be available in rlib format`)를 낸다.
복구는 **오류에 이름이 나온 크레이트만** `cargo clean -p <크레이트>` 다 —
`cargo clean` 전체는 채점에 쓰는 공식 바이너리까지 지운다.

**시작할 때 잰 여유로는 막지 못한다** — 켜진 랩 VM 을 되돌려 다시 켜는 순간처럼 도중에
떨어진다(15.1 → 7.0 GB). 긴 랩 일(콘솔 재캡처 · rc 묶음 · 벤치마크)에는
`testbed/harness/host/Watch-CommitHeadroom.ps1 -Log <일의 기록> -Out <여유 기록>` 을 나란히 띄운다 —
15초마다 재고, 기준(기본 6 GB) 아래면 곧바로 끝나 알린다. 일의 기록 끝에 `DONE` 줄을 쓰면 함께 끝난다.

**변이 시험 뒤에는 디버그 바이너리를 되살린다.** 소스를 해시까지 확인하며
되돌려도 `target/debug` 에는 **마지막 변이로 지은 바이너리**가 남는다. 그것으로
한 즉석 실험은 소스에 없는 결함을 보고한다.

**컨테이너 빌드는 툴체인을 내려받는다.** `rust:1.96-bookworm` 이미지의 판은
`rust-toolchain.toml` 이 고정한 판과 다르므로 rustup 이 매번 받는다. 망에서
TLS 가로채기가 걸리면 실패하고, 캡처 스크립트는 빌드 출력을 숨겨 **"빌드 실패"
한 줄만** 남긴다. 그때는 같은 마운트로 `cargo build` 를 따로 돌려 stderr 를 본다 —
호스트 쪽 rustup 의 같은 판 툴체인을 읽기 전용으로 붙이면 내려받기를 건너뛴다.

**프로그램이 읽는 환경 변수는 열하나다**(2026-11-17 · `git grep -o 'REMEDY_[A-Z_]*' -- 'crates/*.rs'`). 운영자에게
알리는 것은 `REMEDY_LANG` 하나이고(`docs/operator.md` · `--help`), 나머지는 시험과 하네스의 자리다.

| 변수 | 무엇을 바꾸나 | 배포 빌드 |
|---|---|---|
| `REMEDY_LANG` | 화면 언어 (`--lang` 이 이긴다) | 읽는다 |
| `REMEDY_ASCII` | `1` 이면 장식을 ASCII 로, `0` 이면 UTF-8 로 (`--ascii` 와 같다) | 읽는다 |
| `REMEDY_HEARTBEAT_SECS` · `REMEDY_TOOL_WARN_SECS` | 심장박동 주기 · 오래 걸리는 도구를 알리는 시점(시험은 1초) | 읽는다 |
| `REMEDY_NET_CRITERIA` | remedy-net 이 판정 기준(데이터 룰)을 읽는 폴더 — 서명 확인은 그대로다 | 읽는다 |
| `REMEDY_TRUST_ANCHOR` · `REMEDY_TARGET` | 빌드 때 박는 값(공개키 · 타깃 이름) — 실행 중에는 읽지 않는다 | 빌드 때만 |
| `REMEDY_ELEVATION` · `REMEDY_NET_ANCHOR` · `REMEDY_PANIC_TEST` · `REMEDY_SLOW_COLLECT_MS` | 권한 검사 대신 · 동반 프로그램 공개키 · 패닉 시험 · 수집 지연 | 읽지 않는다(`cfg(debug_assertions)`) |

## 채점과 증거

**채점 전에 배포 바이너리가 지금 코드로 지어진 것인지 본다.** 자리·해시·빌드
명령과 그 해시를 만든 코드 커밋은 운영 정보 파일(`.cargo/host.yml` 의
`binaries`)에 있다. 증거의 `binary_sha256` 이 그 해시와 달라지면 재측정 전체가
헛일이 된다.

**내려받은 배포물로 잴 때는 하네스에 그 경로를 준다** — 저장소 산출물
(`target\...`)을 덮지 않는다. 덮으면 위 해시 대조가 그 자리에서 깨진다.
메뉴 하네스와 종료 코드 하네스 넷(`Invoke-GuardVerify` · `Invoke-ObsVerify` ·
`Invoke-PartialVerify` · `Invoke-SignVerify`)은 `-Package <푼 꾸러미 폴더>`, 시연 쪽은
`-Bin <remedy.exe>`, 리눅스는 `--bin <파일>` 이고, 그렇게 주면 **짓지도 서명하지도 않는다**.

**리눅스 하네스는 WSL 쪽 자리의 바이너리를 먼저 집는다.** 캡처·CI 가 docker
이름 볼륨에 빌드하면 하네스가 돌리는 것과 기록된 해시가 어긋난다. 재측정 전에
`sha256sum` 으로 운영 정보의 해시와 같은지 확인한다.

**새 위협의 첫 감염 스냅숏을 뜨기 전에 대상 JSON 을 미리 만들어 둔다**
(`testbed/ai-exam/threats/<위협>/infected/<위협>.json`, `{}` 두 글자면 된다).
`New-ThreatSnapshot.ps1` 은 오타로 엉뚱한 자리에 쓰지 않도록 그 파일이 없으면
멈추는데, **새 위협에는 아직 그 파일이 없다.** 가드는 고치지 않는다 — 그 줄이
막는 오타가 더 비싸다.

**`console-doc` 은 문서와 기준선만 댄다.** 제품의 화면 문자열을 바꾸면 기준선이
바이너리와 어긋나는데도 그 게이트는 초록이다 — 문서와 기준선이 둘 다 옛 문구를
담고 서로 맞기 때문이다. 그것을 잡는 것은 재캡처와 `console-diff` 뿐이다.

## 출시 검증

출시는 태그로 한다(`AGENTS.md`). 평소 경로는 **rc 를 내려받아 두 OS 의 rc 묶음을 공개
전에** 돌린다. 룰만 바꾼 긴급 건은 [`긴급-대응.md`](긴급-대응.md) 의 짧은 길로 가고, 같은
rc 묶음을 공개 뒤 24시간 안에 돌린다. 스크립트는 모두 **내려받은 파일로** 재고 짓지
않는다. 시료(Maven Central 의 공식 jar · 원격 점검이 읽는 이미지 tar · remedy-net 의 Apache
하네스가 짓는 `apache-images` · PHP zip)는 `testbed/harness/results/rc-inputs` 에 스스로 받아 둔다(커밋하지
않는 자리 · 처음 한 번 망).

`remedy-net` 의 이미지 · 컨테이너 · url 점검을 바꾼 PR 은 PR 전에 개발 빌드로 Apache 하네스를 돈다
(2026-11-15 실측 약 6분 · 리눅스 32칸 — 이미지 17 · 컨테이너 9 · url 6 · 그 tar 로 Windows 17칸):

```bash
bash testbed/harness/linux/musl-dev-build.sh /tmp/remedy-dev --net
bash testbed/harness/linux/net-apache-verify.sh --bin /tmp/remedy-dev/remedy-net \
     --criteria plugins/remedy-net-criteria --anchor <개발 키의 공개키> \
     --images testbed/harness/results/rc-inputs/apache-images --out <결과 폴더>
```

### 버전 번호

**버전은 둘이다 — 엔진 버전과 룰 버전.** 받는 사람이 받는 것은 엔진과 그 OS 의 룰이 함께 든
파일 하나지만, 둘은 따로 오른다(2026-11-16 결정 — 엔진과 탐지 내용을 따로 매기는 보안 도구의
관행 · Defender 의 플랫폼 · 엔진과 보안 인텔리전스, ClamAV 의 엔진과 서명 DB, Nuclei 의 엔진과
템플릿). 전에는 룰만 더해도 엔진 버전의 마이너를 올려 열흘에 마이너가 19번 올랐고, 버전만
보고는 엔진이 바뀌었는지 알 수 없었다.

| 버전 | 자리 | 꼴 | 언제 오르나 |
|---|---|---|---|
| 엔진 | `Cargo.toml` 의 `[workspace.package] version` | SemVer `X.Y.Z` | 엔진(실행 파일을 짓는 코드)이 바뀔 때만 — 아래 표 |
| 룰 | `plugins/RULES-VERSION` 한 줄 | 날짜 `YYYY.MM.DD` · 같은 날 둘째부터 `.2` · `.3` … | `plugins/` 의 룰이 바뀔 때만 — 그 룰 묶음을 확정한 날(버전을 올리는 커밋의 날) |

| 엔진에서 바뀐 것 | 올리는 자리 | 예 |
|---|---|---|
| 종료 코드 · 명령줄 약속(인자 · 결과 파일의 꼴)을 바꾼다 | 메이저 | 아직 없다 |
| 엔진 기능 — 새 술어 · 화면 · 명령 · 동반 프로그램의 새 점검 | 마이너 | 1.16.0(메뉴를 하는 일로 묶었다) · 1.14.0(새 술어 `apk_version_lt`) |
| 버그 고침 · 의존성 · 툴체인 올림 | 패치 | 1.1.1(상대 경로로 띄운 치료의 재부팅 재검사) · 1.19.1(이미지 점검의 관리자 주소) |

'엔진' 은 실행 파일을 짓는 것 전부다 — `crates/` · `Cargo.toml` · `Cargo.lock` · `rust-toolchain.toml` ·
`.cargo/config.toml`. 새 룰 · 룰의 판정 고침 · 고친 버전 표 갱신은 **룰 버전만** 올린다. 룰마다의 버전도
그대로 있다(`plugin.yaml` 의 `version` — 룰을 고치면 올리고 `cargo xtask plugin-lock` 이 본다).

**태그는 출시의 종류를 말한다.**

| 출시 | 태그 | 시험판 | 업데이트 내역 칸 · Release 이름 |
|---|---|---|---|
| 엔진이 바뀐 출시(룰도 바뀔 수 있다) | `v<엔진 버전>` — `v1.20.0` | `v1.20.0-rc.1` | `## 1.20.0 · 룰 2026.11.15 — <공개일>` · `1.20.0 · 룰 2026.11.15` |
| 룰만 바뀐 출시 — 엔진 코드가 지난 공개본과 같다 | `rules-<룰 버전>` — `rules-2026.11.18` | `rules-2026.11.18-rc.1` | `## 룰 2026.11.18 · 프로그램 1.20.0 — <공개일>` · `룰 2026.11.18 · 프로그램 1.20.0` |

두 태그 모두 같은 배포 워크플로가 같은 차례로 짓는다 — 룰만 바뀐 출시도 엔진을 다시 짓지만
엔진 코드는 그대로라 버전도 그대로다(Windows 실행 파일은 링크 시각 · PDB GUID 칸만 다르다). 두
태그 모두 태그 보호 룰셋 `release-tags` 로 조직 Owner 만 만들고, 서명 비밀을 든 Environment
`release` 는 두 태그에서만 열린다. 업데이트 내역 칸의 이름은 머리의 앞 낱말이다(배포 워크플로가
그것으로 칸을 찾는다 — 엔진 출시는 `1.20.0`, 룰만 바뀐 출시는 `룰 2026.11.18`).

받는 사람은 두 버전을 함께 본다 — 화면 머리말 첫 줄(`ESTsecurity 전용백신 1.20.0 · 룰 2026.11.15`) ·
`--version` 의 둘째 줄 · 꾸러미 `README.txt` 의 `프로그램` · `룰` 줄 · Release 이름. 엔진은 꾸러미의
`plugins/RULES-VERSION` 을 읽어 **보여 주기만 한다** — 서명 밖의 파일이라 무엇을 돌릴지 정하는 데
쓰지 않는다(`remedy_sdk::rules_version`).

**정책을 따르는지는 배포 워크플로가 본다** — 시험판 태그에서부터(`ci/version-check.sh <태그>` —
저장소 루트에서 `bash` 로 그대로 돈다 · 태그를 밀기 전에 돌려 볼 수 있다). 지난 정식 공개본(첫 부모
역사에서 가장 가까운 정식 태그)과 견준다. 그 스크립트를 고치면 `bash ci/version-check-test.sh` 를 돌린다 —
이 저장소의 역사를 쓰지 않고 임시 폴더에 작은 저장소를 지어 21 경우(통과 10 · 멈춤 11)를 돌린다(약 20초).

- `v` 태그 — 태그 = 엔진 버전 · 엔진이 바뀌었다 · 엔진 버전이 더 높다
- `rules` 태그 — 태그 = 룰 버전 · 엔진이 그대로다 · 룰이 바뀌었다
- 둘 다 — 룰이 바뀌었으면 룰 버전이 더 높고, 그대로면 룰 버전도 그대로다

엔진이 바뀌었는지는 버전 줄을 가린 꼴로 견준다(`Cargo.toml` 의 `[workspace.package]` · `Cargo.lock` 의
작업 공간 크레이트) — 버전만 올린 것은 엔진이 바뀐 것이 아니다. 기능인지 고침인지는 사람이 가린다.
엔진도 룰도 아닌 것(꾸러미를 짓는 `xtask/` · 문서 · 하네스)만 바뀐 것은 혼자 내지 않는다 — 어느 태그도
통과하지 못하고, 다음 출시에 함께 실린다. 긴급 경로는 `xtask/` 도 0줄이어야 한다(`긴급-대응.md`).

## 새 룰을 더할 때 — 룰 폴더 밖에서 손대는 자리

엔진 코드(`crates/`)는 0줄이다 — 제품 코드에 룰 id 를 박은 목록이 없고, 배포 워크플로는 룰 목록을
`xtask threats --dirs <os>` 로 받는다. 룰 폴더(`plugins/<id>/`) 밖에서 손대는 자리는 일곱이고, 넷은 검사가 막는다
(2026-11-17 기술부채 검토 · 룰을 더한 PR #67 · #68 · #76 으로 쟀다).

| # | 자리 | 무엇을 | 빠뜨리면 |
|---|---|---|---|
| 1 | `plugins/versions.lock.json` | `cargo xtask plugin-lock --write` 가 짓는다 | `xtask all` 이 막는다 |
| 2 | README *다루는 위협* 표 | `cargo xtask threats --write` 가 짓는다 | `xtask all` 이 막는다 |
| 3 | `plugins/RULES-VERSION` | 룰 버전(날짜) 한 줄 | 태그 때 `ci/version-check.sh` 가 막는다 |
| 4 | `docs/업데이트-내역.md` 의 그 출시 칸 | 해요체 한 문장 + `* **바뀐 것**` 과 설명 줄(그 파일 머리의 안내 · 2026-11-18 부터) | 태그 때 `ci/release-notes.sh` 가 막는다 — 릴리스 본문의 *2. 이번에 바뀐 내용* 이 그 칸이다. 본문의 틀은 `.github/release-notes.md` 이고 *3.* 의 묶음 · 표는 README 표와 룰 매니페스트에서 짓는다. 미리 보기: `bash ci/release-notes.sh <태그>` |
| 5 | `docs/위협별-안내.md` 의 그 위협 절(세 줄 · 자세히 · 제목 위 고정 주소 `<a id="<위협>"></a>`)과 README *위협별 안내* 표 한 줄(고정 주소로) | 손으로 쓴다 — 다운로드 페이지 글이 그 고정 주소를 가리킨다(`docs/긴급-대응.md` *사용방법 틀*) | 막는 검사가 없다 |
| 6 | `testbed/harness/{linux,host}/<룰>-verify.*` | 하네스 새 파일 | 막는 검사가 없다 |
| 7 | `testbed/harness/README.md` 표 | 한 줄 | 막는 검사가 없다 |

조건에 따라 더 — rc 묶음에 넣을 하네스면 `linux/rc-bundle.sh` · `host/Invoke-RcBundle.ps1` 에 단계 하나. 리눅스
룰이면 콘솔 기준선 4벌과 화면 문서(리눅스 캡처가 리눅스 룰 전부를 담는다). remedy-net 기준과 같은 공지를 쓰는 룰
(PHP · Node · Apache)이면 `plugins/remedy-net-criteria/*.json` 과 `xtask/src/netcriteria.rs`(룰 id 가 박혀 있다). AI
시험 위협으로 두면 `xtask/src/exam.rs` 의 REFERENCES. leaks 오탐이 나면 `xtask/leaks-except.txt`.

**룰 수에 비례하는 비용** — *모두 검사* 는 룰마다 처음부터 다시 수집한다(합성 1,000개: 리눅스 약 3.5분 · Windows 약
35분 — 11-16 결정 D9 로 1시간 안). 실제 룰이 수백 개가 되면 한 번의 모두 검사 동안 읽기 결과를 나눠 쓰게 한다 —
`remedy-platform` 의 읽기 trait 넷을 감싸 기억하는 장식자 하나와, `remedy-core` 의 `collect_declared` 두 자리가 그
백엔드를 받게 하는 변경이다(한 크레이트 안 · 수집기와 결과 파일은 그대로). 뿌리의 합집합을 한 번 걷는 길은 범위 ·
잘림 · 관측 완전성 판정이 룰마다 달라져 크레이트 셋에 걸친 구조 변경이다 — 앞의 것으로 모자랄 때 다시 잰다.

## 화면을 고칠 때

고객이 보는 경로의 한국어는 **실패·거절·미룸 사유까지 전부 합쇼체**다. 조사는
`remedy_sdk::i18n` 의 조사 함수로 앞말 받침에 맞춰 고르고 `이(가)` 병기는 쓰지
않는다. 일부러 해라체로 남긴 자리가 있다 — `--help-all` · `plugin lint` 진단 ·
매니페스트 검증 · 카탈로그의 필드 설명(작성자·개발자용).

**화면 문구를 바꾸면 하네스의 판독 문구도 함께 고친다.** 긍정 단정은 실패로
드러나지만 **부정 단정과 세는 단정**(`-notmatch` · `[regex]::Matches`)은 옛 꼴을
0건으로 세어 **조용히 늘 통과한다.** 옛 문구로 `testbed/harness` 전체를 찾고,
변수에 담은 패턴까지 본다.

## Windows·WSL 에서 겪는 것

**새로 뜨는 콘솔의 코드페이지가 UTF-8 이 아닐 수 있다.** 그런 기계에서 하네스를
숨은 창으로 띄우면 UTF-8 한글 판정 줄이 깨져 전부 `판정 못 읽음` 이 된다. 줄 끝
바이트가 선행 바이트가 되면 **줄바꿈까지 먹혀 두 줄이 붙는다.** 출력을 직접 읽는
쪽은 `StandardOutputEncoding` 을 UTF-8 로 두고, 셸을 거칠 때는 그 셸의
코드페이지를 확인한다.

**`$LASTEXITCODE` 는 프로세스 전역이다.** `& <스크립트>` 는 같은 프로세스에서
돌므로, 그 스크립트가 `exit` 를 두지 않으면 읽는 쪽은 **앞서 돈 다른 네이티브
명령**의 코드를 본다. 하네스가 성공 경로에서 `exit` 를 두지 않아 11/11 인 회차가
실패로 찍힌 적이 있다. `exit $변수` 도 주의한다 — 변수가 비면 0(통과)이 된다.

**`.ps1` 은 UTF-8 BOM 으로 저장한다.** BOM 이 없으면 PowerShell 5.1 이 ANSI 로
읽어 한글 주석의 바이트를 따옴표·괄호로 오독하며 파싱이 무너진다. **`.json` 은
그 반대로 BOM 이 없어야 한다** — 대부분의 파서가 거부한다.

**`.ps1` 을 `sed -i` 로 고치지 않는다.** 이 저장소의 `.ps1` 은 줄 끝이 섞여
있고(CRLF 와 LF), `sed -i` 는 CRLF 파일을 다시 쓰며 LF 로 바꾼다. 한 줄만 고쳐도
diff 가 파일 전체로 부푼다.

**변수나 종료 코드가 들어가는 WSL 명령은 스크립트 파일로 부른다.**
`wsl … bash -c '… $VAR … $?'` 는 셸이 두 번 끼어들어 변수가 비고 `$?` 가 언제나
0 이 된다. 종료 코드는 스크립트 안에서 파일에 적어 그 파일로 확인한다.

**다른 프로세스가 덧붙여 쓰는 파일에 `tail -f` 를 걸지 않는다.** Windows 에서는
그 파일이 잠겨 쓰는 쪽이 실패하고, 그 실패는 조용히 삼켜질 수 있다.

## 서명

`cargo xtask sign` 은 `REMEDY_SIGN_PASSWORD` 가 없으면 **TTY 에 암호를 묻는다.**
자동화에서는 stdin 이 리다이렉트되어 그 프롬프트가 끝나지 않는다. 종료도 오류도
없이 0바이트 파일만 남아 **"빌드가 느리다" 처럼 보인다.**

## 매니페스트 값의 원문 모양

따옴표 없는 YAML 값은 뜻이 바뀐다. `8.10` 은 실수로 읽혀 `8.1` 이 되고, 그러면
`version_lt` 가 완전히 패치된 기계를 양호로 보낸다. **버전·고정 폭 식별자는
따옴표로 감싼다.** 코드 쪽 가드는 린트와 평가기 **양쪽**에 있어야 한다 — `scan`
은 린트를 돌리지 않는다.

Windows PE 의 버전은 **두 눈금**이다(문자열과 2진 `VS_FIXEDFILEINFO`, 실물의
20%가 서로 다르다). 공급사는 문자열 눈금으로 공지하므로 2진 값을 담으면 권고대로
적은 비교가 틀린 답을 낸다. 권위는 `crates/remedy-collect/src/peversion.rs` 의
머리말이다.
