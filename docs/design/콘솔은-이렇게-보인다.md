# 콘솔은 이렇게 보인다 — Windows·Linux 실측 화면 모음

2026-09-09 · **지어낸 화면이 하나도 없다.** 전부 배포 빌드를 진짜 기계에서 돌려
받았다. 화면마다 **그 화면을 만든 룰 조각**을 함께 실었다 — 플러그인의 어느 줄이
콘솔의 어느 줄이 되는지 보이려는 것이다.

**2026-10-02 · 여기서 마감한다.** 화면은 2026-09-30 에 마감했다 — 고객 경로의
문장을 전부 합쇼체로 고르고 내부 용어·`--ascii` 누출을 지웠다(`1b2fffc`). 기준선
4벌은 그날 캡처한 것이고(Windows 31절 · Linux 42절), 나1(승인 전 재검사 약속) 뒤의
Windows 두 벌만 한 번 더 받았다(`9ed736b`). 그 뒤의 제품 변경(`sha256` 린트 ·
`ee5589b`)은 캡처가 쓰는 룰에 닿지 않아 기준선을 다시 받지 않았다. 다음 실제 위협
때 다시 시작하는 자리는 `remedy-전체-그림.md` §16 이다.

> **출처는 `testbed/harness/baseline/console/` 이다.** 이 문서의 화면은 그 기준선
> 파일에서 옮겼고, 길어서 줄인 자리에는 `…` 를 두었다. 화면이 바뀌면 기준선을 먼저
> 다시 받고(`cargo xtask console-diff` 로 의도한 줄만인지 확인한 뒤) 이 문서를 그에
> 맞춘다 — **순서가 반대면 문서가 코드보다 앞서 거짓말을 한다.**
>
> 그리고 위의 "지어낸 화면이 하나도 없다" 는 **재는 주장이다.**
>
> ```bash
> cargo xtask console-doc
> ```
>
> 문서의 화면 블록에서 줄을 뽑아 기준선에 그대로 있는지 본다(`←`·`…`·`$ ` 줄과
> `yaml` 블록은 뺀다). **아무도 재지 않는 주장은 곧 거짓이 된다** — 이 문서는
> 화면을 바꾼 회차 다섯을 지나는 동안 조용히 낡았고, 2026-09-09 에야 그것이
> 드러났다.
>
> **다만 재지 않는 자리가 있다.** 펜스가 ` ```text ` 인 블록 여덟은 기준선이 **그
> 꼴로는** 담지 않은 화면이라 `console-doc` 이 개수만 보고하고 대조하지 않는다.
> 그것만이 아니다 — 대조되는 블록 안에서도 `←`·`…`·`$ ` 가 든 한글 줄 46개는 한
> 번도 대조되지 않는다. 2026-10-26 에 **양쪽 다 낡아 있었다**(화면 마감 뒤 문구를
> 그대로 들고 있었다 — ` ```text ` 쪽 여러 줄과 `…` 로 가려진 §권한 게이트의
> `실패: 관리자 권한이 필요합니다. …`).
>
> **이제 그 두 자리도 잰다** (2026-10-26). 옳은 꼴이 `console-doc` 이 이미 여는 파일
> 안에 있었다 — 기준선에, 그리고 기준선이 담지 않은 화면은 **제품의 한국어 문자열
> 리터럴**에. 그래서 **한글 낱말만 남긴 골격**으로 가장 가까운 줄을 찾아, 거의 같은데
> 낱말이 갈라지면 걸게 했다. 값이 다른 것은 걸지 않는다(경로가 Windows·Linux 로, 사유
> 개수가 2·1 로 다른 줄이 실제로 있다 — 골격이 값을 떨어낸다. 서식 치환자도 같이 떨어진다).
>
> 재는 범위: 대조 밖 한글 **72줄 가운데 28줄**을 견준다. 4줄은 견줄 상대가 아예 없고,
> 32줄은 한글이 짧아 못 세고, **8줄은 심장박동**이라 일부러 뺀다(2026-10-28 — 어느
> 단계가 찍히는지가 캡처 시각에 달려 짝이 생겼다 없어졌다 했다. 그 요동이 아래 상한을
> 밀어 올리고 있었다). 화면 마감 전 판에 걸면 **열셋**을 자리까지 짚는다 — 그날 실제로
> 낡았던 대조 밖 줄은 열여섯이었다.
>
> **이 검사의 가장 나쁜 실패는 조용해지는 것이다.** 어긋남이 골격 앞 열두 글자 안에
> 떨어지면 그 줄은 견줄 상대를 잃고 검사에서 빠진다 — 적대 검증이 머리말(`주의:`)을
> 함께 바꾸면 여덟 블록이 다 낡아도 통과하는 것을 보였다. 그래서 **상대가 없는 줄의
> 수에 상한을 두었다**(지금 **4**). 늘면 실패다. 문서나 기준선이 늘어 그 수가 커지는
> 것이 옳을 때는 같은 회차에 `UNMEASURED_MAX` 를 올린다. 게이트가 **그 줄 번호를
> 함께 말하므로**(2026-10-28) 늘었을 때 어느 줄인지 찾아 헤맬 필요가 없다.
>
> 다시 받을 자리를 적어 둔다 — 여덟 중 일곱은 **하네스가** 내고, 하나는 그 수치를
> 내는 회차가 없어 단위 시험이 근거다.
>
> | ` ```text ` 블록 | 다시 받는 곳 |

> | 관측 불완전 — `scan_roots` 전부 없음 | 리눅스 쌍둥이는 캡처에 있다(바로 위 블록). **Windows 경로 변종**만 `Invoke-ObsVerify` (`obs-missing`) 가 낸다 |
> | 관측 불완전 — 수집 잘림 | `linux/trunc-verify.sh` — 진행 줄까지 그대로 낸다 |
> | 관측 불완전 — 접근 거부 1회 | `Invoke-ObsVerify` (`obs-denied`) |

>
> 2026-10-26 에 그 여덟의 한글 줄 스물일곱을 다시 맞췄다. **스물셋은 그날 한 바퀴
> (`sweep-20261026-190226`)의 로그·`screens.txt` 와 바이트까지 같다.** 남은 넷 가운데
> 진행 줄은 `trunc-verify.sh` 가 그대로 내지만(앞선 바퀴 열 곳에서 바이트 일치) 심장

>

## 0. 화면에 나오는 것은 어디서 오는가

이 도구는 **위협마다 플러그인 하나**를 받는다. 화면에 나오는 이름·개수·항목은 거의
전부 그 플러그인에서 온다. 두 위협의 뼈대를 먼저 보자.

### Windows — `evilai-locust`

```yaml
schema_version: 1
id: evilai-locust
version: 0.1.0
platforms: [windows]
name:
  ko: "EvilAI(Locust) 제거"
  en: "EvilAI (Locust) Removal"

scan_roots:
  - "%LOCALAPPDATA%\\Programs"          # 페이로드가 자리잡는 곳
subjects: [persistence, file, autorun, process, av_exclusion]
```

### Linux — `ldso-preload`

```yaml
id: ldso-preload
version: 1.0.0
platforms: [linux]
name:
  ko: "라이브러리 경로 로더 제거"
  en: "Library path loader removal"

scan_roots:
  - "/etc/ld.so.conf.d"
  - "/usr/local/lib"
  - "/usr/share/applications"
subjects: [text_config, file, shortcut]
```

**`name` 과 `id`·`version` 이 곧 배너의 둘째 줄이다.** 언어에 따라 `name.ko` 나
`name.en` 이 뽑히고, 뒤에 괄호로 `id` 와 `version` 이 붙는다.

```
 EvilAI(Locust) 제거  (evilai-locust 0.2.0)          ← REMEDY_LANG=ko
 EvilAI (Locust) Removal  (evilai-locust 0.2.0)      ← 기본(영어)
```

`scan_roots` 는 성능 설정이 아니라 **읽기 권한의 상한**이다. 플러그인 원문의 표현을
그대로 옮기면 이렇다.

> `scan_roots` 는 성능 최적화가 아니라 "여기 밖은 읽을 수 없다"는 상한이다.
> 서명된 플러그인이 임의 경로를 읽을 수 있으면 그 자체가 정보 수집 도구가 된다.

그래서 심장박동에 찍히는 `폴더 N개 · 항목 M개` 는 **`scan_roots` 가 정한 범위**이고,
그 자리가 하나도 없으면 §15 의 종료 코드 6 이 된다.

## 1. 화면의 뼈대

치료 한 회차의 화면은 일곱 덩어리다. 아래 그림의 `←` 주석은 설명을 위해 덧댄 것이고
실제 출력에는 없다.

```
────────────────────────────────────────────────────────
 ESTsecurity 전용백신 1.17.0                          ← ① 배너: 제품과 버전
 EvilAI(Locust) 제거  (evilai-locust 0.2.0)           ←    플러그인의 name·id·version
────────────────────────────────────────────────────────
 시작 시각  : 2026-09-08 16:59:35 UTC                 ←    시각은 언제나 UTC
 실행 기계  : <host> (windows)

검사를 시작합니다.                                    ← ② 시작 신호: 첫 침묵을 없앤다
검사 완료 : 흔적 6건 · 위협 1건                       ← ③ 검사 결과: 증거와 판정

이 치료의 부작용:                                     ← ④ 부작용: 승인을 묻기 전에 말한다
  ! [1] node.exe 가 종료됩니다 — 저장하지 않은 작업이 있으면 사라집니다

7 건을 수행합니다:                                    ← ⑤ 계획: 무엇을 할지 먼저 다 보인다
   1. 프로세스 종료  (실행 중인 것을 찾아서)
      지금 돌고 있는 그 프로그램을 멈춥니다           ←    항목마다 한 줄로 뜻을 푼다
   …

  * 치료를 마친 뒤 이 PC 를 재시작하면 자동으로 한 번 더 검사합니다(관리자 계정으로 로그온했을 때).

치료를 시작합니다.                                    ← ⑥ 진행: 한 줄에 하나씩
  수행 [1/7] 프로세스 종료  (실행 중인 것을 찾아서)   ←    계획과 같은 말을 쓴다
   …

────────────────────────────────────────────────────────
 결과       : 위협 발견, 치료 완료 (7건 수행 완료)    ← ⑦ 마무리 표
 되돌리려면 : remedy restore --run run-…              ←    되돌리는 법과
 오탐 신고  : remedy support-bundle --run run-…       ←    신고하는 법을 직접 말한다
────────────────────────────────────────────────────────
```

**요점 여섯.**

- **② 가 첫 침묵을 없앤다.** 배너 뒤 검사가 5초를 넘기기 전까지는 아무 줄도 나오지
  않는다. 그 몇 초 동안 화면이 멎어 보이면 사람은 창을 닫는다.
- **④ 를 승인 앞에 둔다.** *"프로그램이 하나 꺼진다"* 는 사실은 승인을 누른 **뒤**에
  알면 이미 늦다. 저장하지 않은 작업이 있으면 사라지기 때문이다.
- **⑤ 의 설명 줄은 `프로세스 종료` 를 사람 말로 옮긴 것이다.** 항목 이름만으로는
  비IT 사용자가 무엇에 동의하는지 알 수 없다.
- **계획을 먼저 다 보인다.** `--yes` 없이 부르면 ⑤ 에서 멈추고 승인을 기다린다.
  무엇을 지울지 모르는 채로 지워지는 일이 없다.
- **⑤ 와 ⑥ 은 같은 말을 쓴다.** 승인한 문장과 수행한 문장이 다르면 승인이 승인이
  아니다. `[1/7]` 은 계획의 몇 번째인지를 그대로 가리킨다.
- **⑦ 이 다음 행동을 말한다.** 되돌리는 명령과 신고하는 명령을 화면이 직접 적어
  준다 — 그대로 복사해 붙이면 된다.

**그때만 나오는 줄들.** `검사만`·`실패`·`재부팅 예약`·심장박동은 조건이 맞을 때만
나온다. 5초 안에 끝난 검사는 심장박동을 한 줄도 찍지 않고, 리눅스에는 재부팅 예약
줄이 아예 없다. ④ 도 부작용이 있는 Op 이 계획에 들었을 때만 나온다.

**터미널에서는 역할 색과 표시가 붙는다** (2026-11-06). 좋음은 녹색 `✓`, 나쁨 ·
실패는 적색 `✗`, 주의 · 알림은 황색 `!` 를 줄 앞(들여쓰기 뒤)에 달고, 진행 줄 ·
구분선은 흐리게, 제품 이름은 청록이다. 표시는 문구 앞에 붙을 뿐 문구를 쪼개지
않는다. **파이프 · 파일 · `NO_COLOR` · `TERM=dumb` 에서는 붙지 않는다** — 이 문서의
화면(기준선)이 그 글자다. `--ascii` 에서는 `v` · `x` · `!` 다. 콘솔 호스트는 `✓` ·
`✗` 를 대체 글꼴로 넓게 그려 뒤의 빈칸을 덮는다(Windows Terminal · xterm 은 띄운다).

**진행 줄(심장박동)은 터미널에서는 제자리에서 바뀐다** (2026-11-06). 줄을 더하지 않고
창 폭에서 잘라(넘치면 `…`) 같은 줄을 다시 그리고, 다음 줄이 나오기 전에 걷는다.
파이프 · 파일 · 회차 로그에는 지금처럼 한 줄씩 쌓인다 — 기준선의 심장박동이 그 글자다.

## 2. 첫 화면 — 사용법과 안내 모드

### 인자를 주고 부르면 — 사용법

인자 없이 치거나 `--help` 를 주면 이것이 나온다. **언어는 PC 를 따른다** — 한국어
Windows 면 한국어, 그 밖은 영어이고, `--lang`·`REMEDY_LANG`·POSIX `LANG` 이 있으면
그것이 이긴다(2026-09-09 부터. 그 전에는 환경변수 없이는 늘 영어였고, 받아서
더블클릭한 한국어 PC 가 영어 화면을 봤다). 아래는 C 로케일 컨테이너라 영어다.

```
$ remedy --help                                              (Linux · 기본 언어)
Notice: no code-signing check on this OS: cannot verify this is the official release. Check the file's checksum
ESTsecurity Dedicated Cleaner 1.17.0
--------------------------------------------------------

Usage
  remedy run --plugin <plugin.yaml> [--yes]       scan and treat
  remedy run --plugin <plugin.yaml> --dry-run     scan only, change nothing
  remedy restore --list                            list the runs that can be undone
  remedy restore --run <run_id> [--yes]           undo a treatment
  remedy --help-all                               every command and option

  Run as root. Without it nothing starts and the exit code is 5.
  Without --yes the plan is shown and approval is awaited.

Options
  --lang ko|en   output language (Korean on a Korean PC, else English; REMEDY_LANG also works)
  --ascii        ASCII-only decorations (terminals without Unicode fonts)
  --verbose      detailed diagnostics

The eight exit codes are in `remedy --help-all` (for unattended deployment).

Copyright (c) 2026 ESTsecurity Corp. All Rights Reserved.
```

**고객이 쓰는 명령은 넷뿐이다** — `run` · `restore --list` · `restore --run` ·
`--help-all`. 나머지(단계별 `collect`·`evaluate`·`plan`, `plugin lint`, 신뢰 목록
관리)는 `--help-all` 에만 있다. 첫 화면이 길면 아무도 읽지 않는다.

**종료 코드 표는 여기 없다.** 여덟 줄짜리 표였고, 그 독자는 무인 배포를 짜는
사람이다. 지우지 않고 `--help-all` 로 보냈으며, 첫 화면에는 어디 있는지를 한 줄로
남겼다 — 조용히 지우면 그 표를 알던 사람이 없어졌다고 생각한다.

```
$ REMEDY_LANG=ko remedy --version
알림: 이 OS 에는 코드서명 확인이 없어 공식 배포본인지 스스로 확인하지 못합니다. 받은 파일은 체크섬으로 확인하십시오
ESTsecurity 전용백신 1.17.0 (remedy)
```

### 받아서 더블클릭하면 — 안내 모드

홈페이지에서 받은 사람은 인자를 칠 자리가 없다. 그래서 **실행 파일 옆에 꾸러미가
있으면** 인자 없는 호출이 사용법 대신 검사로 이어진다. 찾는 자리는 두 곳뿐이다 —
실행 파일 옆의 `plugin.yaml`, 그리고 `plugins/<이름>/plugin.yaml` 한 겹까지.

**아무거나 실행하지는 않는다.** 옆에 있는 꾸러미라도 서명이 우리 것으로 확인되지
않으면 거절한다. 폴더에 룰 하나를 몰래 넣어 두는 것이 가장 쉬운 공격이기 때문이다.

```
$ remedy                                        (꾸러미 옆 · 서명도 앵커도 없다)
  건너뜀 C:\remedy-lab\pkg\plugins\demo: 이 프로그램은 플러그인 번들을 검증할 수 없습니다 (배포본이 아닙니다)
  쓸 수 있는 검사 항목이 없어 아무것도 검사하지 못했습니다.
[exit=5]
```

**거절이 0 이 아니라 5 다.** 0 은 "이 PC 는 깨끗하다" 로 읽힌다 — 검사를 한 번도
못 한 실행이 그 말을 하면 안 된다. 위 화면은 앵커를 박지 않은 캡처용 빌드라서
나온 것이다.

**서명이 통과하면 이렇게 간다.** 임시 키로 서명하고 **그 앵커를 박은 빌드**로
받았다(`A8`·`B2`). 아래는 감염된 기계에서 부른 것이다.

```
EvilAI(Locust) 제거를 검사합니다.
검사 완료 : 흔적 6건 · 위협 1건

이 치료의 부작용:
  ! [1] node.exe 가 종료됩니다 — 저장하지 않은 작업이 있으면 사라집니다
```

안내 모드는 `run` 과 **같은 문**을 지난다. 그래서 승인 앞에서 선다.

```
  주의: 승인할 사람이 없습니다 (터미널이 아닙니다).
     무인 배포에서는 --yes 를 명시하십시오. 아무것도 하지 않았습니다.
```

**위가 `exit 2` 로 끝나는 것은 캡처가 stdin 을 막아 두기 때문이다.** 그 자리에는
물을 사람이 없으니 검사까지만 가고 선다. **더블클릭한 창은 터미널이므로 거기서는
검사가 아니라 질문이 먼저 뜬다** — 바로 아래가 그 화면이고, 작업을 고른 뒤에야
계획이 나오고 `예` 를 묻는다(§7).

꾸러미가 **아예 없는 자리**에서는 지금까지처럼 사용법이 나오고 끝난다(종료 0).
안내 모드가 열리는 것은 실행 파일 옆에 꾸러미가 있을 때뿐이다.

### 무엇을 할지 먼저 묻는다 — 작업 메뉴

받아서 띄운 사람은 명령을 칠 자리가 없다. 그래서 **인자 없이 띄우고 사람이 앞에
있으면** 할 수 있는 일을 늘어놓고 번호를 받는다. 명령 스물을 외우지 않아도 되는
자리가 이것이다. **첫 화면은 받은 사람의 일만 보인다** — 아래는 치료한 적이 없는 PC 다.

```
ESTsecurity 전용백신 1.17.0
검사 항목: EvilAI(Locust) 제거
관리자 권한으로 실행 중입니다.

무엇을 할까요?

  1. 검사하고 치료하기
  2. 검사만 하기 (아무것도 바꾸지 않습니다)
  3. 더 보기 (기록 · 프로그램 정보 · 관리자 · 룰 작성자)
  0. 그만두기

번호를 고르십시오 (0-3):
```

**머리말이 먼저 선다** — 제품 이름 · 판 · 고른 검사 항목 · 권한. 권한 줄은 고른 뒤에
거절당하지 않게 먼저 보인다. 관리자가 아니면 *"관리자 권한이 없습니다 — 검사 · 치료는
관리자 권한으로 다시 실행해야 합니다."* 가 나오고(리눅스는 root), 재지 못하면 그 줄을
내지 않는다. 검사 항목 줄은 항목이 여럿인 꾸러미에서 고른 뒤 어느 것을 골랐는지 보이려고
섰다(2026-11-06).

**일이 생기면 그 줄이 선다** (목표 remedy_사용자메뉴 · 2026-11-08). 받은 사람의 일은 여섯이고
첫 화면에는 **그 일이 있을 때만** 선다.

| 줄 | 서는 때 |
|---|---|
| 검사하고 치료하기 | 치료하는 룰을 골랐다 |
| 검사만 하기 | 룰을 골랐다 |
| 치료가 유지됐는지 다시 보기 | 치료하는 룰 · 치료한 기록이 있다 |
| 치료 전으로 복원하기 | 치료한 기록이 있다(권한으로 못 읽으면 그 까닭과 함께) |
| 신고에 붙일 것 모으기 | 치료한 기록이 있다 |
| 중단된 작업 이어서 하기 | 끝나지 않은 치료가 있다 |

치료한 뒤의 첫 화면은 *1. 검사하고 치료하기 · 2. 검사만 하기 · 3. 치료가 유지됐는지 다시 보기 ·
4. 치료 전으로 복원하기 · 5. 신고에 붙일 것 모으기 · 6. 더 보기* 다. 1.2.0 까지는 스물한 줄이 늘 같은
번호로 섰다 — 첫 화면 열넷 가운데 다섯이 *"치료한 기록이 없습니다"* 를 달고 흐렸고, 일곱(룰 서명 확인 ·
룰 검사 · 자체 점검 · 버전 · 명령줄 사용법 · 모든 명령과 옵션 · 작성자·운영자 명령 보기)이 받은 사람의
일이 아니었다(v1.2.0 실측).

**나머지는 더 보기 한 곳에 있다.** 마지막 줄이 열다섯을 묶음 제목 넷 아래 한 화면 더 세우고, 그 화면의
`0` 은 **메뉴로** 돌아온다. 개발자 · 룰 작성자 · 운영자의 자리라 이 화면은 전의 규칙 그대로다 — 기계
상태와 상관없이 같은 차례로 서고, 지금 고를 수 없는 줄은 까닭을 단다. 명령 전부에 **닿는다**는 것도
그대로다(`menu::every_command_has_a_menu_line` — 깨끗한 PC 에서 서지 않는 것은 입력이 없는 셋, 유지
확인 · 신고 · 이어서 하기뿐이다).

```
더 보기 — 관리자 · 룰 작성자 · 문제 확인용 명령입니다 (명령줄로 쓰려면 remedy --help)

기록
  1. 복원할 수 있는 치료 기록 보기 — 치료한 기록이 없습니다

프로그램
  2. 프로그램 자체 점검
  3. 버전 보기
  4. 명령줄 사용법
  5. 모든 명령과 옵션

룰 작성자
  6. 룰 검사 (작성자용)
  7. 룰 서명 확인

운영자 (사내 평가 · 조직 목록)
  8. 수집만 하기 (평가는 사내에서)
  9. 승인한 계획을 수행하기 — out 폴더에 승인한 계획(plan*.json)이 없습니다
  10. 수집 결과를 평가하기 — out 폴더에 수집 결과(artifacts*.json)가 없습니다
  11. 평가 결과로 계획 세우기 — out 폴더에 평가 결과(scan*.json)가 없습니다
  12. 조직 허용 목록 확인 — 실행 파일 옆에 서명된 목록(*.signed)이 없습니다
  13. 조직 허용 목록 반입 — 실행 파일 옆에 서명된 목록(*.signed)이 없습니다
  14. 폐기 목록 확인 — 실행 파일 옆에 서명된 목록(*.signed)이 없습니다
  15. 폐기 목록 반입 — 실행 파일 옆에 서명된 목록(*.signed)이 없습니다
  0. 메뉴로 돌아가기
```

**찾기만 하는 룰에서는 치료를 약속하는 줄이 서지 않는다** — `remediate` 가 없는 룰(리눅스
꾸러미의 *CWPdoor 점검 (탐지만)* · *Ebury 점검 (탐지만)*)을 고르면 첫 화면이 *1. 검사만 하기 ·
2. 더 보기* 다. 더 보기의 *승인한 계획을 수행하기* 는 *"이 룰은 찾기만 하고 치료하지 않습니다"* 를
달고 흐리게 선다. 1.2.0 까지는 1번 *검사하고 치료하기* 부터 그 까닭을 달고 흐렸다.

**두 OS 가 같은 메뉴다** (2026-11-06). 리눅스 꾸러미의 첫 메뉴도 같은 줄 · 같은
번호다 — `testbed/harness/linux/menu-verify.sh` 가 리눅스에서 지은 새
꾸러미의 첫 메뉴를 위 화면(A10)과 줄 목록으로 견준다(diff 0). OS 마다 다른 것은 둘뿐이다.

| | Windows | 리눅스 |
|---|---|---|
| 권한 줄 | *관리자 권한으로 실행 중입니다.* | *root 권한으로 실행 중입니다.* |
| 서명 없는 빌드의 알림 | *코드서명이 없어 공식 배포본인지 스스로 확인하지 못합니다. …* | *자기무결성을 확인하지 못했습니다 (이 플랫폼에는 Authenticode 가 없습니다). …* |

**내놓을 것이 없으면 메뉴를 열지 않는다.** 쓸 수 있는 꾸러미도, 되돌릴 회차도,
고를 파일도 없으면 지금까지처럼 사용법이다 — 개발 빌드를 그냥 띄운 자리에서
메뉴가 뜨면 잡음이고, 명령줄 시연의 첫 화면이 그 조건이다.

**첫 화면의 번호는 상태마다 다르다** (2026-11-08). 1.2.0 까지는 줄을 늘 세워 번호를 묶었는데,
그 값으로 받은 사람의 첫 화면이 개발자의 화면이 됐다. 번호가 움직이는 걱정은 두 자리가 받는다 —
치료하는 룰에서 1 · 2번은 늘 *검사하고 치료하기 · 검사만 하기* 이고(README 가 그 번호를 적는다),
작업 뒤 *다음 할 일* 은 **돌아갈 그 화면에서** 번호를 센다(`menu::line` — 그 화면에 서지 않는 줄은
가리키지 않는다). 더 보기의 번호는 늘 같다. 지금 고를 수 없는 줄(더 보기 · 권한으로 못 읽은 복원)의
번호를 고르면 까닭만 보이고 다시 묻는다. 그래도 **번호를 외워 적는 안내문은 쓰지 않는다** —
라벨로 가리킨다.

방향키 화면에서 줄이 창보다 높으면 머리말과 `0.` 줄 · 안내 줄은 두고 **번호 줄과 묶음 제목만 창
안에서 넘기며**, 가린 줄 수를 목록 위아래에 적는다(gh 가 한 화면 20개로 넘기는 것과 같은
결). 줄 입력 화면(아래 캡처)은 다시 그리지 않으므로 전부 찍는다.

### 항목이 여럿이면 먼저 고른다 — 1번은 모두 검사만

검사 항목이 여럿이면(1.3.0 부터 두 OS 의 배포 꾸러미가 다 그렇다) 작업 메뉴보다 **먼저** 어느 것을 볼지 묻는다.
그 1번이 **전부로 검사만**이다(목표 remedy_출시_20261111 기준 3) — 무엇에 감염됐는지 모르는
사람이 항목을 하나씩 골라 다시 띄우지 않게. 맨 위라 항목이 늘어도 번호가 그대로다.
아래 두 화면은 리눅스 기준선의 `A11` 절이다 — 배포 잡과 같은 룰 목록을 일회용 키로 서명해 지은
꾸러미를 pty 에서 띄웠다. Windows 기준선의 `A11` 은 같은 흐름을 룰 둘(EvilAI 룰과, 그것에서
`remediate` 를 뺀 실험 룰)로 받고, 찾기만 하는 룰의 메뉴까지 싣는다.

```
검사 항목 10개를 찾았습니다:
  1. 9개 모두 검사만 하기 (아무것도 바꾸지 않습니다)
  2. CWPdoor 점검 (탐지만)
  3. CWPdoor 제거
  4. Ebury 점검 (탐지만)
  5. Apache HTTP/2 점검 (CVE-2026-119618)
  6. Log4j 점검 (CVE-2021-44228 등)
  7. Node2Shell 점검 (CVE-2026-111497)
  8. OpenSSH 점검 (CVE-2026-123158 · Alpine)
  9. PHP 세션 업로드 진행 설정 점검 (CVE-2026-115560)
  10. PHP2Shell 점검 (CVE-2026-109618 · 109619)
  11. PHP2Shell 원격 점검 (웹서버 응답 헤더) [네트워크 사용]
  0. 그만두기
```

**하는 일로 묶어 늘어놓는다** (코어 1.16.0) — 악성코드 탐지 · 제거 → 취약점 점검(`kind: check`) → 원격
점검(`network`) 차례이고, 묶음 안에서는 룰 폴더 이름순이다. 묶음마다 머리줄은 세우지 않는다. 이름순 하나였을 때(1.15.0)는
새 룰이 이름이 놓이는 자리에 끼어 — Apache 점검이 2번 — 뒤 번호가 밀렸고 세 종류가 섞였다. 찾기만 하는 CWPdoor · Ebury
룰은 `kind` 를 적지 않아(감염을 보는 룰이다) 악성코드 묶음에 서고, 같은 사고의 점검 → 제거 차례는 폴더 이름
(`cwpdoor-1-check` · `cwpdoor-2-clean`)이 지킨다. 아래 *모두 검사만* 의 결과도 같은 차례다.

**찾은 항목은 열인데 1번은 아홉이다** (코어 1.4.0). 1번이 세는 것은 **이 기계를 검사하는 항목**이고,
네트워크로 점검하는 항목은 주소를 적어야 돌아 한꺼번에 돌릴 수 없다. 그 항목에는 고르기 전에 알도록
`[네트워크 사용]` 꼬리표가 붙는다. 꼬리표를 대시로 잇지 않는 것은 이 화면들에서 `이름 — 까닭` 이 **지금 고를
수 없는 줄**의 꼴이기 때문이다 — 색이 없는 이 줄 입력 화면에서는 둘이 똑같이 보여 꺼진 항목으로 읽힌다
(2026-11-10 랩의 메뉴 하네스가 그 줄을 꺼진 줄로 세어 드러났다).

1번은 항목마다 메뉴의 *검사만 하기* 와 같은 `scan` 을 차례로 돌고(항목마다 결과 폴더가
따로다), 끝에 결과를 한 덩어리로 다시 적는다 — 항목마다의 화면이 이어지면 앞 항목의 결과는
창 밖으로 밀린다. 아래는 CWP · PHP · Node.js · 자바 라이브러리 · Alpine 의 sshd · Apache 가 없는 컨테이너에서다
(CWPdoor 둘은 검사할 경로가 없어 6 — 설계대로, 점검 여섯은 0). 빼 둔 네트워크 점검도 **이 요약에** 한 줄로 선다 — 검사 앞에 적으면
같은 까닭으로 창 밖으로 밀리고, 적지 않으면 *모두* 가 그것까지 본 것으로 읽힌다. 종료 코드에는 들지 않는다.

```
모두 검사한 결과 — 룰 9개 · 아무것도 바꾸지 않았습니다
  CWPdoor 점검 (탐지만) — 해당 없음 (검사할 경로가 이 기계에 없습니다)
  CWPdoor 제거 — 해당 없음 (검사할 경로가 이 기계에 없습니다)
  Ebury 점검 (탐지만) — 위협이 발견되지 않았습니다.
  Apache HTTP/2 점검 (CVE-2026-119618) — 취약한 곳을 찾지 못했습니다.
  Log4j 점검 (CVE-2021-44228 등) — 취약한 곳을 찾지 못했습니다.
  Node2Shell 점검 (CVE-2026-111497) — 취약한 곳을 찾지 못했습니다.
  OpenSSH 점검 (CVE-2026-123158 · Alpine) — 취약한 곳을 찾지 못했습니다.
  PHP 세션 업로드 진행 설정 점검 (CVE-2026-115560) — 취약한 곳을 찾지 못했습니다.
  PHP2Shell 점검 (CVE-2026-109618 · 109619) — 취약한 곳을 찾지 못했습니다.
  PHP2Shell 원격 점검 (웹서버 응답 헤더) — 돌리지 않았습니다 (네트워크 점검은 그 항목을 골라 주소를 적어야 합니다)
```

종료 코드는 새로 만들지 않는다(불변식 I3) — 찾은 것(2)이 검사를 마치지 못한 것(4 · 5 · 7)
보다, 그것이 다 보지 못한 것(6)보다 앞선다. 치료하는 항목이 무언가를 찾았으면 다음 할 일이
*"찾은 것을 치료하려면 그 룰을 고른 뒤 — 1. 검사하고 치료하기"* 를 적는다. 작업 뒤에는 이
질문으로 돌아오고, `0` 이 그만두기다. 이 화면은 터미널에서만 선다 — 인자 없이 띄웠는데
터미널이 아니면 지금까지처럼 목록만 적고 아무것도 하지 않는다.

**방향키와 숫자 둘 다다** (2026-11-05). 사람이 앞에 있고 그 화면이 VT 를 알아들으면
(stdin · stdout 이 터미널 · `TERM` 이 `dumb` 이 아님 · `NO_COLOR` 없음) 고르는 동안만
원시 모드로 ↑↓ · Enter · 숫자를 받고, 고른 줄을 반전으로 강조하며, 맨 아래 한 줄이
쓰는 법을 알린다. 원시 모드는 crossterm 이 `unsafe` 를 크레이트 안에 가둔 채 든다.
**그리는 자리가 아니면 위 화면 그대로** 번호 한 줄을 받는다 — 이 캡처가 그 화면이다
(A10 은 stdout 을 파일로 받는다).

이 화면은 `A10` 이 **진짜 콘솔을 만들어**(`AllocConsole` + `WriteConsoleInput`)
받은 것이다. 캡처의 다른 절은 모두 stdin 을 닫으므로 **터미널에서만 나오는 화면은
여기와 아래 절에만 있다.**

### 네트워크를 쓰는 점검 — 알리고, 서명이 맞는 `remedy-net` 을 띄운다

**본체(`remedy`)는 통신하지 않는다.** 룰이 `network: url` 을 선언했으면(코어 1.4.0) 본체는 그 룰을 스스로
돌리지 않고, 실행 파일 옆 `remedy-net` 폴더의 프로그램을 띄워 맡긴 뒤 종료 코드만 받는다(설계-04 §1
*동반 모듈* 의 조건 다섯). 받는 사람은 `remedy` 하나만 실행한다 — 어느 프로그램이 네트워크를 쓰는지는
띄우기 **전에** 화면이 말한다.

아래는 리눅스 기준선의 `A12` 절이다 — `A11` 과 같은 꾸러미(동반 프로그램이 같은 일회용 키로 서명돼 들어
있다)에서 명령줄로 불렀다. 주소는 **닫힌 포트**(127.0.0.1:9)라 컨테이너 밖으로 나가는 요청이 없고, 응답이
없어 판정은 *확인 필요*(6)다. 6 은 동반 프로그램이 낸 코드를 본체가 그대로 돌려준 것이다.

```
 ESTsecurity 전용백신 1.17.0
 PHP2Shell 원격 점검 (웹서버 응답 헤더)  (php2shell-url-check 0.1.1)
────────────────────────────────────────────────────────
 시작 시각  : 2026-11-10 04:19:42 UTC
 실행 기계  : <host> (linux)

이 점검은 네트워크를 씁니다 — 적어 주시는 주소로 요청을 보냅니다.
이 프로그램(remedy)은 통신하지 않습니다. 서명을 확인한 동반 프로그램 remedy-net 을 실행해 맡깁니다.

이용 조건
1. 소유하거나 점검을 허락받은 서버에만 쓰십시오.
2. 적은 URL 에 HEAD 요청을 보내 응답 헤더만 읽습니다(HEAD 를 받지 않는 서버에만 GET 한 번).
   공격 요청이나 자동 수정은 하지 않습니다.
3. 요청은 2초 간격으로 보내지만 서버 접속 기록에 남고 부하가 생길 수 있습니다.
4. 헤더만으로는 패치 여부를 확인할 수 없어 '양호' 를 내지 않습니다. 취약이 나오지 않아도
   안전하다는 뜻이 아닙니다.
5. 결과는 지정한 폴더에 저장됩니다. 서버 주소 · 헤더 같은 내부 정보가 들어가니 공유하기 전에
   확인하십시오.
약관 동의: --consent y
점검 시작: URL 1개 — 요청은 2초 간격, URL 하나에 10초까지 기다립니다.
[1/1] http://127.0.0.1:9/
  확인 필요 — 응답 헤더만으로는 보안 패치 적용 여부를 확인할 수 없습니다.
  · HEAD 요청 실패: 서버가 연결을 거부했습니다.
  할 일: 그 서버에서 remedy 의 PHP2Shell 점검으로 직접 확인하십시오.

응답 헤더가 알리는 정보는 실제 설치 상태와 다를 수 있습니다.
URL 점검은 '양호' 를 내지 않습니다 — 그 서버에서 remedy 의 PHP2Shell · PHP 세션 점검으로 확인하십시오.
확인이 필요합니다. 위에 적은 항목은 '취약하지 않다' 를 가릴 근거가 없습니다.
결과 파일: /tmp/console-capture/scan-all/net-out/remedy-net-url-20261110T041942Z-1f3c085fecef8717.json
[exit=6]
```

위 두 줄(*이 점검은 네트워크를 씁니다* · *이 프로그램(remedy)은 통신하지 않습니다*)까지가 본체의 말이고,
*이용 조건* 부터는 동반 프로그램의 화면이다. **이 점검은 '양호' 를 내지 않는다** — 헤더는 서버가 스스로
적는 글자라 *취약*(2) 아니면 *확인 필요*(6)다.

**서명이 맞지 않으면 띄우지 않는다.** 같은 꾸러미의 사본에서 `remedy-net` 폴더의 서명 파일을 지우고 같은
명령을 부르면 가드 중단(5)으로 끝나고, 결과 폴더도 생기지 않는다(캡처가 *없다* 로 적는다) — 서명 확인이
어떤 손질보다 먼저다. 폴더가 없을 때 · 서명한 뒤 바뀌었을 때 · 다른 키로 서명했을 때 · 버전이 본체와 다를
때도 같은 5 이고 문장만 다르다(`crates/remedy-cli/tests/net_launch.rs` · 배포 잡의 `verify-companion`).

```
실패: remedy-net 에 서명이 없어 실행하지 않았습니다 — 배포처에서 받은 것이 맞는지 확인하십시오.
  (종료 코드 5: 안전 가드에 의한 중단 (상한 초과·보호 경로·서명 검증 실패))
[exit=5]
```

**메뉴에서 고르는 흐름**(고르는 화면의 `[네트워크 사용]` 항목 → *1. 원격 점검하기 (remedy-net 을 실행해
네트워크를 씁니다)* → 알림 → 이용 조건 동의 → 주소를 한 줄에 하나씩)은 이 캡처가 아니라 메뉴 하네스가
잰다 — 리눅스는 `linux/menu-verify.sh`(pty), Windows 는 `host/Invoke-MenuVerify.ps1`(진짜 콘솔)이고,
둘 다 닫힌 포트로 6 까지 간다. 리눅스에서 sudo 로 띄운 메뉴는 동반 프로그램을 **sudo 를 건 사용자의
권한으로** 내려 띄우고 그렇다고 한 줄 적는다. 그 사용자가 그 폴더에 닿지 못하면 내리지 못한다고 적고 root 로
띄운다 — 두 갈래 모두 그 하네스가 결과 파일의 소유자로 확인한다.

### 창이 곧바로 닫히지 않는다

더블클릭으로 띄운 창은 프로그램이 끝나는 순간 사라진다. 결과를 읽을 시간이 없다.
그래서 **stdin 이 터미널일 때만** 마지막에 한 줄을 세운다.

```
이 창을 닫으려면 Enter 를 누르십시오.
```

| 어떻게 불렀나 | 기다리는가 |
|---|---|
| 더블클릭 · 꾸러미 없음 (사용법) | **기다린다** — 프롬프트를 내고 Enter 를 받는다 |
| 더블클릭 · 메뉴 | 이 줄을 내지 않는다 — **작업 뒤 메뉴로 돌아온다** (아래) |
| 인자를 주고 부름 | 기다리지 않는다 |
| 파이프·리다이렉트 (스크립트) | 기다리지 않는다 |
| 재부팅 회차(RunOnce) | 기다리지 않는다 — 사람이 없다 |

**stdin 이 터미널인지로 가른다.** 무인 배포에서 이 줄이 뜨면 배포가 통째로 선다.
프롬프트는 stderr 로 내보내므로 `remedy … > out.txt` 의 결과 파일에는 섞이지 않고,
EOF 를 받아도(입력이 끊겨도) 그대로 끝난다.

### 끝내는 것은 사람이다 — 작업 뒤 메뉴로 · Ctrl+C 두 번

메뉴에서 고른 작업이 끝나면 구분선 · **다음 할 일** 을 남기고 *"Enter 를 누르면 메뉴로
돌아갑니다."* 에서 멈춘다 — 메뉴가 곧바로 다시 서면 결과 줄이 창 밖으로 밀리기
때문이다(2026-11-06). Enter 에 메뉴가 다시 서서 한 창에서 탐지 · 치료 · 복원을 잇는다.
다음 할 일은 결과에 맞는 메뉴 줄을 번호로 가리킨다 — 치료 뒤에는 *치료가 유지되는지
보려면 — 3. …* 이 먼저이고 *오탐이라면 — 4. 치료 전으로 복원하기* · *오탐을 신고하려면 —
5. …* 이 뒤다(되돌리기가 첫 줄이면 할 일 목록으로 읽혀 악성코드를 되살릴 수 있다 —
2026-11-07 적대적 검토). 검사가 찾았으면 *찾은 것을 치료하려면 — 1. …* 하나이고, 복원
뒤에는 *치료하려면 — 1. …*. 번호는 **돌아갈 그 화면의** 번호다 — 작업이 만든 · 지운 기록을 다시 읽어
세고, 그 화면에 서지 않는 줄은 적지 않는다(1.2.1 · 1.2.0 까지는 번호가 고정이라 접은 줄을 *14. 작성자·운영자
명령 보기 → 2. …* 처럼 두 걸음으로 적었다). 치료가 일부 실패하면
*까닭을 해결한 뒤 다시 검사하려면 — 1. …* · *신고하려면 — 5. …* 이다 — 실패한 Action 도 결과와
끝을 적으므로 이어서 하기는 '이미 적용됨'(5)으로 거절한다(1.1.0 까지는 *8. 중단된 작업 이어서
하기* 를 가리켰다 — 2026-11-07 적대적 검토). '남은 것을 치료' 라고 약속하지 않는다 — 판정의
근거가 이미 치워졌으면 다시 검사는 위협 없음(0)으로 끝나고 실패한 항목은 남는다(rc.2 실측:
CWPdoor 바이너리는 격리 · 유닛 삭제만 읽기 전용으로 실패 → 다시 검사 0 · 유닛 그대로). 복원이
일부 실패하면 신고만 권한다. 찾기만 하는 룰이 찾았으면
치료를 권하지 않고, 조치 차례가 있는 README 절(*위협별 안내*)과 받은 폴더 안 그 룰의
`RELEASE.md` 경로(인터넷이 막힌 서버의 몫)를 가리킨다. **깨끗하게 끝났을 때도 같은 두 곳을 가리킨다** —
*'위협 없음' 은 이 항목이 아는 유형을 찾지 못했다는 뜻입니다 — 무엇을 보는지:* (2026-11-08 · 룰 대 공개 보도
대조). 룰은 공개 보도가 밝힌 꼴을 찾고 같은 위협의 다른 설치 방법은 이름 그대로 찾지 못하는데, 화면이
*"위협이 발견되지 않았습니다"* 로만 끝나 그 결과가 기계의 무죄로 읽혔다. 종료 코드와 결과 줄은 그대로다.
관측 불완전(6)에는 내지 않는다 — 그쪽은 *주의* 줄이 까닭을 말한다(그래서 리눅스 배포 파일의 *모두 검사만*
은 CWP 가 없는 기계에서 이 줄을 내지 않는다: 집계가 6 이다). 치료가 끝났을 때도 같은 두 곳을 *치료 뒤에
할 일은 위협마다 다릅니다* 로 가리킨다(패널 다시 설치 · 자격 증명 · 다시 시작 — 2026-11-08 적대적
검토 4바퀴).

**룰이 여럿인 받은 폴더(리눅스)에서는 먼저 고를 룰을 앞에 적는다** — *오탐이라면 — 3. CWPdoor 제거
→ 4. 치료 전으로 복원하기*. 작업 뒤 Enter 는 룰을 고르는 화면으로 돌아가는데 메뉴 줄의 번호는 룰을
고른 뒤의 화면에서만 맞는다 — 전에는 치료 뒤 안내대로 `6` 을 누르면 고르는 화면이 범위 밖으로 읽고
끝냈고, 검사만 뒤 `1` 은 *모두 검사만* 을 돌렸다(같은 검토 · 리눅스 실측). 메뉴에서 **찾기만 하는 룰이
찾은 것은 *검사 완료* 줄 아래에 번호를 달아 경로만 적는다**(점검 룰의 줄과 같은 꼴 · 인자로 부른
실행에서는 내지 않는다 — 불변식 I1). 권한 없이 띄워 기록 폴더를 읽지 못하면 회차 줄의 까닭이
*치료한 기록이 없습니다* 가 아니라 *root 권한으로 실행해야 기록이 보입니다*(Windows 는 관리자)다.
*룰 서명 확인* 이 성공하면 끝줄의 *폐기 목록 없음* 을 *아직 폐기한 룰이 없다는 뜻입니다* 로 풀어 준다. 메뉴에서 고른 *검사만 하기* 는 시작에 *"검사만 합니다 — 아무것도 바꾸지 않습니다.
찾으면 치료할 계획을 세워 둡니다."* 를 남긴다(찾기만 하는 룰은 앞 문장만). 끝내는 것은
사람이다: `0. 그만두기` 를
고르거나 **Ctrl+C 를 두 번**(2초 안에) 누른다. 한 번은 끝내지 않고 *"Ctrl+C 를 한 번
더 누르면 끝납니다 (2초 안에)."* 를 띄운다. 작업 도중이면 *"… 누르지 않으면 지금 하는
일을 이어 갑니다."* 를 띄우고 그 작업을 끝까지 한다.

| 어떻게 끝났나 | 종료 코드 |
|---|---|
| 그만두기 · 작업 사이의 Ctrl+C 두 번 | 마지막 작업의 코드 (작업이 없었으면 0) |
| 시스템을 바꾸던 작업 도중의 Ctrl+C 두 번 | 3 (부분) — 끊긴 치료는 저널과 `resume` 이 받는다 |
| 읽기만 하던 작업 도중의 Ctrl+C 두 번 | 6 ('위협 없음' 을 말할 수 없음) |

**인자를 주고 부른 것과 무인 회차는 그대로다** — Ctrl+C 한 번에 끝나고, 메뉴로
돌아오지 않는다. 메뉴 세션 동안에는 치료가 띄운 도구(`sc.exe` · `systemctl` …)를 새
프로세스 그룹으로 띄워, 첫 Ctrl+C 가 그 도구를 끝내지 않게 한다.

이 절의 화면은 사람이 앞에 있는 터미널에서만 나온다 — 기준선(파일로 받는 캡처)에는
없고, 화면 이미지(`testbed/harness/host/Invoke-ScreenShot.ps1`)가 잰다.

## 3. 권한이 없을 때

시스템을 변경하는 명령은 전부 관리자(root)를 요구한다. **권한 없이 돌면 감염된 기계에서도
증거가 안 나오기 때문**이지, 형식 때문이 아니다. 그래서 화면이 그 이유를 말한다.

```
$ remedy run --plugin plugins\evilai-locust\plugin.yaml       (Windows · 비관리자)
알림: 코드서명이 없어 공식 배포본인지 스스로 확인하지 못합니다. 받은 파일은 체크섬으로 확인하십시오
실패: 관리자 권한이 필요합니다. 이 도구는 예약 작업, HKLM, 다른 사용자의 파일을 읽고
  고치며, 그것들은 관리자만 열 수 있습니다. 권한 없이 돌면 감염된 기계에서도
  증거가 나오지 않습니다.
  → remedy.exe 를 마우스 오른쪽 단추로 누르고 '관리자 권한으로 실행' 을 고르십시오.
     명령 창에서 부르는 중이라면 시작 단추를 오른쪽 단추로 누르고
     '터미널(관리자)' 또는 'Windows PowerShell(관리자)' 로 창을 연 뒤 다시 부르십시오.
  (종료 코드 5: 안전 가드에 의한 중단 (상한 초과·보호 경로·서명 검증 실패))
```

```
$ REMEDY_LANG=en remedy run …                                 (같은 자리, 영어)
Error: Administrator rights are required. This tool reads and fixes scheduled tasks,
  HKLM and other users' files, which only an administrator can open. Without
  them an infected machine yields no evidence.
  → Right-click remedy.exe and choose 'Run as administrator'.
     If you are calling it from a command window, right-click the Start
     button, choose 'Terminal (Admin)' or 'Windows PowerShell (Admin)',
     and run again.
  (exit code 5: stopped by a safety guard (limit, protected path, signature))
```

**이유를 말한 뒤 하는 법까지 적는다.** 앞의 세 줄은 *왜* 관리자여야 하는지를 말하고,
뒤의 세 줄은 관리자로 *어떻게* 다시 띄우는지를 말한다. 이유만 말하고 끝내면 "그래서
어떻게 하라는 것인가" 가 남는다.

**우클릭이 먼저인 이유.** 이 화면을 보는 사람의 다수는 **아무 명령도 치지 않았다.**
꾸러미를 옆에 두고 더블클릭하면 안내 모드(§2)가 열리고, 그 안에서 이 문이 닫힌다.
그에게 "명령 창을 열고 다시 부르라" 는 **따를 수 없는 처방**이다 — 경로도 인자도 그가
친 적이 없기 때문이다. 실제로 그렇게 되는지는 **캡처가 매번 잰다** — `A8` 절이
임시 키쌍을 만들고, 그 공개키를 박은 빌드로 서명된 꾸러미를 만들어 비관리자로
부른다.

```
$ remedy                                        (꾸러미 옆 · 비관리자)
EvilAI(Locust) 제거를 검사합니다.
실패: 관리자 권한이 필요합니다. …
  → remedy.exe 를 마우스 오른쪽 단추로 누르고 '관리자 권한으로 실행' 을 고르십시오.
```

**실행 파일 이름은 박아 두지 않고 읽는다.** 위 화면의 `remedy.exe` 는 문자열이 아니라
지금 도는 파일의 이름이다 — 받는 사람이 이름을 바꿨으면 바꾼 이름이 나온다. 화면에서
보는 이름과 같아야 그 파일을 집는다.

리눅스에서 같은 문이 닫히면 이렇게 보인다. **처방이 한 줄이다** — 리눅스에는 우클릭도
UAC 도 없고, 이 화면을 보는 사람은 이미 터미널 앞에 있다.

```
$ remedy run --plugin plugin.yaml                             (Linux · 비root)
알림: 이 OS 에는 코드서명 확인이 없어 공식 배포본인지 스스로 확인하지 못합니다. 받은 파일은 체크섬으로 확인하십시오
실패: root 권한이 필요합니다. 이 도구는 시스템 전역의 지속성, 설정을 읽고 고치며,
  그것들은 root 만 열 수 있습니다. 권한 없이 돌면 감염된 기계에서도 증거가
  나오지 않습니다.
  → sudo 로 다시 부르십시오.
  (종료 코드 5: 안전 가드에 의한 중단 (상한 초과·보호 경로·서명 검증 실패))
```

```
$ REMEDY_LANG=en remedy run …                                 (같은 자리, 영어)
Error: root is required. This tool reads and fixes system-wide persistence and
  configuration, which only root can open. Without it an infected machine
  yields no evidence.
  → Run again with sudo.
  (exit code 5: stopped by a safety guard (limit, protected path, signature))
```

**리눅스 화면은 기준선 안에 있다** (2026-09-10). 그 전까지는 아니었다 — 캡처가
컨테이너의 root 로 돌아 이 문이 닫히는 법이 없었고, 그래서 문구를 고쳐도
`console-diff` 는 아무 말도 하지 않았다. 이제 `capture-console.sh` 의 **A7** 절이
`setpriv` 로 권한을 내려놓고 한 번 부른다. 산출·상태 폴더가 생기지 않는 것도 함께
본다 — `admin_gate` 는 하위 명령을 파싱하기 전에 서므로, 폴더가 생겼다면 그것은
문이 뒤로 밀렸다는 뜻이다.

**두 플랫폼 다 기준선 안에 있다** (2026-09-10). 그 전까지는 어느 쪽도 아니었다 —
캡처가 관리자·root 로 돌아 이 문이 닫히는 법이 없었고, 그래서 문구를 고쳐도
`console-diff` 는 아무 말도 하지 않았다. 2026-09-09 에 우클릭 안내를 넣었을 때도
그랬다. 이제 캡처의 **A7** 절이 양쪽에서 권한을 내려놓고 한 번 부른다.

**계정을 새로 파지 않았다.** 리눅스는 `setpriv` 로 nobody 가 되고, Windows 는
`runas /trustlevel:0x20000` 이 SAFER 로 지금 토큰을 제한한 사본을 만든다 —
거기서 `BUILTIN\Administrators` 는 *거부 전용*이 되고, 그것이 정확히
`platform_elevated` 가 보는 조건이다(`System32\Tasks` 를 열어 보고 거부되면
권한 없음). 표준 사용자를 하나 파고 비밀번호를 들고 다니는 길도 있었지만,
그러면 랩에 자격 증명이 하나 더 생기고 스냅샷마다 다시 만들어야 한다.

**산출·상태 폴더가 생기지 않는 것도 함께 본다.** `admin_gate` 는 하위 명령을
파싱하기 전에 서므로, 폴더가 생겼다면 그것은 문이 뒤로 밀렸다는 뜻이다.

**안내 모드 화면도 들어왔다** (2026-09-11). 그것만은 조립이 하나 더 필요했다 —
꾸러미가 옆에 있어야 열리고, **서명이 통과해야** 열린다. `A6` 은 앵커가 없는 빌드로
돌아 거절만 재고 있었고, 그래서 **서명이 통과했을 때 안내 모드가 어떻게 열리는지는
저장소 어디에서도 재지 않았다.** 받는 사람이 실제로 만나는 갈래인데도 그랬다.

`A8` 이 그 조립을 만든다 — 임시 키쌍 → 그 공개키를 박은 빌드 → 서명된 꾸러미 →
비관리자. 개인키는 실행마다 새로 만들고 끝나면 버린다. **공유 릴리스 산출물은
앵커로 오염되지 않는다** — 백업하고 앵커 빌드를 한 뒤 곧바로 되돌린다. 그러지
않으면 다음 회차의 `A6` 이 거절 대신 통과를 내고 아무도 이유를 모른다.

`< NUL` 로 stdin 을 막는 이유는 §2 다. 안내 모드는 stdin 이 터미널이면 창을
붙잡으므로, 막지 않으면 이 절이 그대로 매달린다(2026-09-10 에 그랬다). 창 유지
갈래는 `A0` 이 따로 잰다.

**화살표는 언어가 아니라 터미널이 정한다** — UTF-8 이면 둘 다 `→`, `--ascii` 나 C
로케일이면 둘 다 `->`. 문구는 언어를 따르고 장식은 터미널을 따른다.

> **화면 옵션 셋의 플래그 경로를 이제 캡처가 잰다** (2026-09-20).
> 리눅스 `C4` · Windows `C3` 가 그 자리다.
>
> | 옵션 | 그전에는 | 이제 |
> |---|---|---|
> | `--ascii` | 효과는 `C1`(C 로케일)이 쟀고 **플래그 경로는 없었다** | 두 경로를 나란히 놓고 견준다 |
> | `--verbose` | **리눅스 `Q1`(§20)이 2026-09-09 부터 쟀다.** Windows 에만 없었다 | 두 운영체제 모두에서 잰다 |
> | `--lang` | 캡처가 언어를 `REMEDY_LANG` 으로만 줬다 | `REMEDY_LANG=ko` 에 `--lang en` 을 얹어 **플래그가 이기는 것**을 본다 |
>
> 설명과 동작이 갈려도 캡처에 나타나지 않던 자리다.
>
> **`--verbose` 칸은 2026-09-21 에 고쳤다.** 그 전날 이 표에 *"효과조차 재어진
> 적이 없다"* 고 적었는데 틀렸다 — 리눅스 `Q1` 이 `scan --verbose` 로 재고
> 있었고, 기준선에 `자세히: evidence 4 · groups 1 · verdicts 1` 이 그때부터
> 있었다. 캡처 스크립트를 **옵션 이름으로 훑으면서 그 한 줄을 놓쳤다.**
> Windows 에는 정말 없었고 `C3` 가 그 자리를 채웠다.

## 4. 검사 — Windows

### 룰 — 예약 작업에서 폴더를 뽑아낸다

`plugins/evilai-locust/plugin.yaml` 에서 화면과 관계된 부분만 뽑았다(주석은 줄였다).

```yaml
detect:
  # ① 예약 작업 — 이 위협의 뼈대. node.exe 가 AppData 의 .js 를 돌린다
  - id: task
    subject: persistence
    where:
      all:
        - { field: command,                op: matches,     value: '(?i)\\node\.exe$' }
        - { field: args,                   op: matches,     value: '(?i)\\AppData\\Local\\Programs\\[^"]+\\[^\\"]+\.js("|\s|$)' }
        - { field: win.task.register_path, op: starts_with, value: "\\Microsoft\\Windows\\" }
    capture:
      script_path: "args | first_path"          # 증거에서 경로를 뽑아
      payload_dir: "${script_path} | dirname"   # 그 폴더를 아래 규칙들이 쓴다
    score: 90        # 보고·우선순위 표시용일 뿐이다. 판정 게이트가 아니다

  # ②-a 본문을 담을 대상 — **경로로만** 매치한다
  - id: payload-file
    subject: file
    from: "${task.payload_dir}"
    where:
      - { field: path, op: ends_with, value: ".js" }

  # ②-b 드롭된 페이로드 — 내용(YARA)으로 확인한다
  - id: payload
    subject: file
    from: "${task.payload_dir}"           # ★ 증거에서 파생된 경로만 스캔한다
    where:
      - { field: path, op: ends_with, value: ".js" }
      - { yara: "rules/evilai.yar:evilai_locust_js" }

  - id: runkey                            # ③ Run 키 이중화
    subject: autorun
    where:
      - { field: command, op: contains, value: "${task.payload_dir}" }

  - id: av-exclusion                      # ④ 백신 예외에 자기 폴더를 넣었다
    subject: av_exclusion
    where:
      - { field: value, op: contains, value: "${task.payload_dir}" }

  - id: payload-process                   # ⑤ 지금 돌고 있는 그 프로세스
    subject: process
    where:
      all:
        - { field: image_path, op: matches,  value: '(?i)\\node\.exe$' }
        - { field: args,       op: contains, value: "${task.payload_dir}" }

verdict:
  require: "task and payload"             # 서로 다른 자리의 두 근거가 함께여야 위협이다

collect_extra:
  - { ref: payload-file, content: true }  # YARA 가 볼 본문을 담는다
```

**읽을 때 짚을 것 셋.**

  바뀌어 못박을 수 없으므로, *"예약 작업이 가리킨 바로 그 폴더"* 만 본다. 이것이
  없으면 무관한 `.js` 하나가 판정을 완성시킨다.
- **`score: 90` 은 판정과 무관하다.** 판정은 아래 `verdict` 하나가 한다. 점수
  임계값을 게이트로 쓰면 룰 하나의 오탐이 곧바로 삭제가 된다.
- **거의 같은 룰이 둘(`payload-file`·`payload`) 있다.** 본문을 담으려면 먼저 대상이
  잡혀야 하는데 `payload` 는 YARA 를 쓰므로 본문 없이는 잡히지 않는다. `collect_extra`

### 룰 — 설정 한 줄에서 폴더를 뽑아낸다

```yaml
detect:
  - id: cfgline                           # ① 검체가 덧붙인 한 줄. 파일 자체는 정상이다
    subject: text_config
    where:
      all:
        - { field: path, op: starts_with, value: "/etc/ld.so.conf.d/" }
        - { field: line, op: matches,     value: '^/[^\s#]*/\.[^/\s]+/?$' }   # 숨김 성분
    capture:
      dir: "line | first_path"            # 줄 내용이 곧 경로다

  - id: payload                           # ② 그 폴더의 .so — 판정 근거로만 쓴다
    subject: file
    from: "${cfgline.dir}"
    where:
      - { field: path, op: matches, value: '\.so(\.\d+)*$' }

  - id: contents                          # ③ 그 폴더의 파일 전부 — 제거는 이쪽이 맡는다
    subject: file
    from: "${cfgline.dir}"
    where:
      - { field: path, op: exists }

  - id: launcher                          # ④ 변조된 .desktop 실행기
    subject: shortcut
    where:
      - { field: args, op: contains, value: "${cfgline.dir}" }

verdict:
  require: "cfgline and payload"
```

**판정에 쓰는 규칙과 제거에 쓰는 규칙이 다르다.** `payload`(`.so` 하나)가 판정을
맡고, 제거는 `contents`(폴더의 파일 전부)가 맡는다. 폴더 전체가 검체가 만든 것이라는
관측이 그 근거다. 플러그인 주석이 그 이유를 적어 두었다.

> `dir.delete_recursive` 를 쓰지 않는 이유는 위험해서가 아니라 **리눅스에 없어서**다
> (`machine/ops.json` 의 `linux_from` 이 null). 그래서 폴더째가 아니라 파일 단위로
> 격리한다 — 없는 Op 을 쓰는 대신 있는 것으로 같은 일을 한다.

`powershell.exe` 가 잇따라 **둘** 돈다 — 고위험 Op 이 하나라도 있으면 치료 전에
만드는 **복원 지점**(`Checkpoint-Computer`)과, 계획 7번의 **예외 목록 원복**

라벨이 *이미지 이름 + 첫 인자*이기 때문이다. `도구` 뒤의 초는 **그 도구가** 돈
시간이고 `경과` 는 치료 전체가 돈 시간이라, 두 번째 줄의 `0초` 는 그 직전에 새
도구가 시작했다는 뜻이다.

리눅스 쪽에는 이 칸이 없다 — 그쪽 치료가 부르는 외부 도구는 CA 저장소 갱신뿐이고
캡처가 쓰는 위협은 그것을 밟지 않는다.

외부 도구가 오래 걸리면 **죽이지 않고 기다리면서** 그 사실을 알린다 —

300초, **`sc.exe` 는 30초**를 넘기면 알린다(결정 2026-09-07 · 09-13).

**`sc.exe` 만 이른 데는 까닭이 있다.** 정지를 붙드는 서비스를 세워 재 보니
`ControlService` 가 **60초에 포기하고 오류 1053** 을 낸다 — 예전 상한(60초)과
같은 값이라 그 경고는 영영 뜨지 않았다. 30초면 **SCM 이 손을 떼기 30초 전에**
말해 주고, 뒤따라올 1053 을 예고한다.

끊지 않는다는 결정 자체도 그 회차가 실증했다: 도구가 60초를 채우는 동안
실행기가 기다렸고 회차는 60.3초에 끝났으며, **서비스는 그 뒤 스스로 멈췄다**
(`testbed/harness/host/Invoke-SlowStopVerify.ps1`).

넘긴 뒤의 줄은 이렇게 된다.

```text
치료 중 · 도구 powershell.exe -NoProfile 0초 (상한 0초 넘음 — 끊지 않습니다) · 경과 1초
```

**상한을 낮춰 받은 화면이다.** 랩에서 60초를 진짜로 넘길 도구가 없어
`REMEDY_TOOL_WARN_SECS=0` 으로 *말하는 시점만* 앞당겼다(동작은 그대로 —
어떤 값에도 끊지 않는다). 진짜 상황에서는 `70초 (상한 60초 넘음 — 끊지
않습니다)` 처럼 된다. **끊지 않는다는 말이 같은 줄에 있는 것이 요점이다** —
없으면 사람이 먼저 끊고, 그것이 이 결정이 막으려던 일이다.

이 줄은 2026-09-11 에 랩 VM 에서 받았고 **화면과 회차 로그 양쪽**에 들어갔다.
어느 기준선에도 없다 — 캡처가 아니라 그날의 실측이다.

**심장박동 줄은 `console-diff` 가 대조하지 않는다.** 나오는지 자체가 시간에
달렸기 때문이다(§19). 캡처에 남기는 것은 **모양을 눈으로 보기 위해서**이지
회귀를 잡기 위해서가 아니다 — 검사 쪽 `A5` 절도 같은 이유로 있다.

## 7. 승인 — 네 갈래

**(a) 사람이 있다** — 터미널에서 `--yes` 없이 불렀을 때. 계획을 다 보인 뒤 묻는다.

```
위 계획을 수행합니다. 나중에 되돌릴 수 있습니다(메뉴의 '치료 전으로 복원하기' · restore 명령). 진행하려면 '예'(또는 y) 입력:   아무것도 하지 않았습니다.
```

**질문은 개행 없이 stderr 로 나간다** — 사람이 답을 그 줄에 이어 치기 때문이다.
위 화면은 `아니오` 로 답한 캡처(리눅스 `D4` 절)라서 결과 줄이 같은 줄에 붙어
보인다. 진짜 터미널에서는 콜론 뒤에 자기가 친 답이 오고 결과는 다음 줄에 온다.

`예`(영어면 `yes`) 를 정확히 쳐야 진행한다. Enter 만 치거나 다른 것을 치면
아무것도 하지 않고 끝난다 — **기본값이 "하지 않는다" 쪽**이다.

**(b) 승인할 사람이 없습니다** — 스크립트·원격 세션에서 `--yes` 없이 불렀을 때.

```
  주의: 승인할 사람이 없습니다 (터미널이 아닙니다).
     무인 배포에서는 --yes 를 명시하십시오. 아무것도 하지 않았습니다.
[exit=2]
```

터미널이 아니면 **묻지 않고 거절한다.** 아무도 못 보는 프롬프트 앞에서 기다리는 것이
가장 나쁜 결과다.

**(c) 드라이런** — 계획만 보고 끝낸다.

```
--dry-run — 아무것도 변경하지 않았습니다.
[exit=2]
```

**(d) `--yes`** — 아래 §8.

## 8. 치료 — Windows

### 룰 — "무엇이 남아 있으면 안 되는가" 만 적는다

```yaml
# 순서·백업·프로세스 종료를 여기 적지 않는다. 계획기가 도출한다.
remediate:
  remove:
    - { ref: payload-process }
    - { ref: task }
    - { ref: payload }
    - { ref: runkey }
    # recursive 는 guard 가 필수다. guard 는 "그 디렉터리 안에서 악성으로 판정된
    # 파일" 을 가리킨다. capture 해석이 어긋나 payload_dir 가 %LOCALAPPDATA%\Programs
    # 자체가 되더라도, 그 안에 악성 판정 파일이 없으므로 이 삭제는 계획에 들지 않는다.
    - { path: "${task.payload_dir}", recursive: true, guard: payload }
  restore:
    - av_exclusions                      # 원복은 파괴가 아니므로 별도 절이다
  verify:
    after_reboot: true
```

**첫 줄의 주석이 이 절의 전부다** — 플러그인은 *무엇*만 적고 *어떻게·어떤 순서로*
는 코어가 정한다. 그래서 아래 화면의 일곱 줄은 위의 다섯 줄과 개수도 순서도 다르다.

같은 문장을 수행할 때 또 찍으면 화면이 두 배가 되고 정작 봐야 할 `[k/7]` 이 묻힌다.
**설명은 결정 앞에 있어야 값이 있다** — 이미 승인한 뒤에는 진행만 보면 된다.

### 룰 다섯 줄이 Action 일곱이 된다

| 룰 | Action | 몇 개 |
|---|---|---|
| `{ ref: payload-process }` | 프로세스 종료 | 1 |
| `{ ref: task }` | 자동 실행 등록 **비활성화** → **삭제** | **2** |
| `{ ref: runkey }` | 시작 프로그램 항목 제거 | 1 |
| `{ ref: payload }` | 파일 격리 | 1 |
| `{ path: …, recursive: true }` | 폴더 삭제 | 1 |
| `restore: [av_exclusions]` | 보안 제품 예외 목록 원복 | 1 |

두 가지가 눈에 띈다.

- **예약 작업 하나가 Action 둘이 된다.** 지우기 전에 먼저 끈다 — 삭제와 실행이
  겹치는 창을 없애기 위해서다.
- **순서는 룰이 아니라 코어가 정한다.** 룰에는 `payload` 가 `runkey` 보다 먼저
  적혀 있지만 화면에서는 뒤다. 유발자(프로세스·자동실행)를 먼저 끊고 산출물(파일·
  폴더)을 나중에 치우는 것이 항상 옳기 때문에, 그 순서를 플러그인 작성자에게
  맡기지 않는다.

**마무리 표의 마지막 두 줄이 요점이다** — 되돌리는 법과 신고하는 법을 화면이 직접
말한다. 그 줄을 그대로 복사해 붙이면 된다.

## 9. 치료 — Linux

### 룰 — 세 줄이 세 가지 Op 이 된다

```yaml
remediate:
  # 차례는 코어가 정한다. 유발자(설정 줄·실행기)가 산출물보다 먼저 처리된다.
  remove:
    - { ref: cfgline }     # text_config.remove_line — 덧붙은 줄만
    - { ref: launcher }    # shortcut.strip_args     — 덧붙은 인자만
    - { ref: contents }    # file.quarantine_only    — 폴더의 파일 전부
```

`ref` 만 적었는데 Op 이 셋으로 갈린다. **대상의 subject 가 Op 을 정하기 때문**이다 —
`text_config` 는 줄을, `shortcut` 은 인자를, `file` 은 파일을 다룬다. 플러그인
작성자가 "이 줄은 지우고 저것은 격리하라" 를 고를 자리가 없다.

## 10. 재부팅 뒤 한 번 더 — 예약

```yaml
remediate:
  verify:
    after_reboot: true        # ← 이 한 줄이 아래 예약을 만든다
```

이 한 줄은 화면에도 두 번 나타난다. 먼저 **계획에**(§4) — 승인하기 전에 재시작 때
무슨 일이 생기는지 알아야 하기 때문이다.

```
  * 치료를 마친 뒤 이 PC 를 재시작하면 자동으로 한 번 더 검사합니다(관리자 계정으로 로그온했을 때).
```

**약속은 이 실행이 걸 수 있을 때만 한다.** 예약 명령에는 플러그인 경로가 들어가는데,
`apply --plan` 과 `resume` 은 `--plugin` 을 받지 않으면 그것을 모른다. 그런 실행은
승인 전에 약속 대신 이유와 할 일을 말한다 (Windows 캡처의 `D5` 절 · 결정 자료 나1).
기계가 걸 수 없는 곳(리눅스 컨테이너)도 같은 모양으로 그 이유를 말한다.

```
  * 재시작 뒤 자동 재검사를 걸 수 없습니다 (이 명령은 플러그인 경로를 모릅니다. `remedy run --plugin ...` 은 압니다).
    치료가 끝나면 직접 부를 명령을 알려 드립니다.
```

그리고 치료를 마친 뒤 **예약했다는 사실로**.

```
재부팅 후 재평가를 예약했습니다: HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce\remedy-verify (실행 뒤 OS 가 지웁니다)
```

심어지는 명령은 이렇게 생겼다.

```
"C:\remedy-lab\bin\remedy.exe" verify --run run-1788886775-240c-328eee3c --plugin "C:\remedy-lab\plugins\evilai-locust\plugin.yaml" --lang ko --state-dir "C:\remedy-lab\state-console"
```

한 줄이 길어 접지 않았다 — **접으면 기준선과 글자가 달라지고, 그러면
`cargo xtask console-doc` 이 이 줄을 대조하지 못한다.**

**`--lang ko` 가 실려 있다.** 재부팅 회차는 환경변수를 물려받지 못하므로, 싣지 않으면
한 회차의 로그가 앞은 한국어 뒤는 영어가 된다. 그리고 OS 가 실행 직전에 항목을
지우므로 **자동실행 흔적이 남지 않는다** — 치료 도구가 정체불명의 자동실행을 남기면
그 자체가 타 백신의 탐지 대상이 된다.

## 11. 재평가

`verify` 는 **경로 확인이 아니라 재판정**이다. "지운 자리가 여전히 비어 있는가" 만
보면 랜덤 이름을 쓰는 위협 앞에서 무력하다 — 재감염은 다른 이름으로 생기고 원래
경로는 계속 비어 있다. 그래서 수집과 평가를 처음부터 다시 돌린다.


판정이 `verify/<run_id>.jsonl` 에 남는다 — 재부팅 회차는 사람이 보지 못하므로 **그
파일이 유일한 답**이다.

**다 보지 못한 재평가는 "치료 성공" 으로 끝나지 않는다** (2026-10-26). 판정도 남은
증거도 없는데 `주의:` 줄이 섰으면(§15 의 관측 불완전과 같은 줄) 마지막 줄이 *"치료를
확인하지 못했습니다. 판정은 서지 않았지만 다 보지 못해 '치료 성공' 을 말할 수
없습니다."* 이고 종료 코드는 6 이다. 위 두 장면은 다 본 회차라 그대로다 — 이 장면은
기준선에 없다.

### 조직 복구 키 — 다른 기계에서도 연다

격리 컨테이너는 내용키를 **여러 겹으로 싸 둔다.** `local` 만 있으면 위에서 본
대로 *"이 격리물은 이 기계의 키로만 열립니다"* 라고 경고하지만, 치료할 때 `--org-public-file` 로
조직 공개키를 함께 실으면 겹이 하나 더 생긴다. 복원 화면의 `키` 줄이 어느
겹이 있는지 말한다.

```
 키         : local(…) · org(…)
```

넘겨받은 격리물은 **제자리에 쓰지 않는다.**

```
  제자리 복원은 원래 머신에서만 보장됩니다.
 결과       : 2건 복원 완료.
```

이 기계의 저널에 *"우리가 그 자리에서 담았다"* 는 기록이 없기 때문이다 —
`--extract-to` 로 지정한 곳에 꺼낸다. 캡처는 Windows `M` 절과 리눅스 `R` 절이
이 왕복을 잰다(2026-09-21). **그전에는 org 겹이 붙은 컨테이너가 전부 개발
도구(`xtask fixture`)가 만든 것이었고, 제품이 싣는 경로는 재어진 적이 없었다.**

## 15. 나머지 종료 코드 — 일부러 일으킨 화면

정상 회차에서는 볼 수 없는 것들이다(3 · 5 **셋** · 6 · 7). 각각을 만들 룰과 함께 싣는다.
**리눅스 캡처는 `--cap-add SYS_ADMIN` 으로 받는다** — 읽기 전용 마운트를 만들어야
종료 코드 3 을 밟는다.

### 관측 불완전 (6) — "위협 없음" 을 말하지 않는다

```yaml
scan_roots: ['/opt/does-not-exist-1', '/opt/does-not-exist-2']   # 없는 자리만 선언
```

```
검사를 시작합니다.
결과 폴더 : /tmp/console-capture/o6  (artifacts.json · scan.json · plan.json)
검사 완료 : 흔적 0건 · 위협 0건
  주의: 아래 까닭으로 '위협 없음' 이라고 판단할 수 없습니다:
     - 검사할 경로 2개가 이 기계에 전부 존재하지 않아 아무 곳도 열어 보지 못했습니다: /opt/does-not-exist-1 · /opt/does-not-exist-2

관측이 불완전해 '위협 없음' 을 말할 수 없습니다.
[exit=6]
```

**0건인데 0이 아니다.** 무인 배포에서 0 은 "이 PC 는 깨끗하다" 로 읽히고 그대로
종료된다. 절반만 본 실행이 0 을 내면 그 PC 는 검사받았다고 기록되지만 실제로는
아니다. 그래서 코드를 나눴다.

### "없다" 가 아니라 "모른다" 일 때 (B-9 · 2026-10-27)

**바로 위 절과 다른 것은 자리의 상태뿐이다.** 위는 선언한 자리가 **전부 없어**
아무 곳도 열지 못한 경우고, 여기는 **열린 자리 하나 + 물어볼 수조차 없는 자리
하나**다.

```yaml
scan_roots: ['/tmp/console-capture/openroot', '/tmp/console-capture/loop']   # 뒤는 도는 심링크
```

```
검사를 시작합니다.
결과 폴더 : /tmp/console-capture/o6b  (artifacts.json · scan.json · plan.json)
검사 완료 : 흔적 0건 · 위협 0건
  주의: 아래 까닭으로 '위협 없음' 이라고 판단할 수 없습니다:
     - 선언한 자리 1곳이 있는지조차 확인하지 못했습니다: /tmp/console-capture/loop

관측이 불완전해 '위협 없음' 을 말할 수 없습니다.
[exit=6]
```

**이 화면은 2026-10-27 까지 없었다.** `Path::exists()` 가 오류 전부를 *"없다"* 로
접어서, 열린 자리가 하나라도 같이 선언되면 `all_roots_missing()` 이 깨지고 **주의
한 줄 없이 종료 0 *"위협이 발견되지 않았습니다"***가 나갔다 — `denied_dirs` 도 0
이라 화면에 아무 흔적이 없었다. 막힌 자리를 **하나만** 선언했을 때는 우연히 6 이
나왔지만 사유가 *"전부 존재하지 않아"* 로 틀렸다.

현장에서 이 자리에 오는 것은 **부모까지 막힌 트리 · 끊긴 UNC 공유 · 준비되지 않은
장치**다. 캡처는 컨테이너에서 root 로 돌아 권한 거부를 만들 수 없으므로 **도는
심링크**로 같은 분류(*모른다*)를 밟는다. 사유를 `접근이 거부된 디렉터리` 쪽에
합치지 않은 이유는 그 줄이 *"관리자 권한으로 다시 돌리십시오"* 를 권하기 때문이다
— 끊긴 UNC 에는 틀린 조언이다.

### 점검으로 선언하면 같은 자리가 0 이 된다 (B-6 · 2026-10-26)

**바로 위 절과 같은 `scan_roots` 다.** 다른 것은 한 줄뿐이다.

```yaml
kind: check                                                      # 이 한 줄이 가른다
scan_roots: ['/opt/does-not-exist-1', '/opt/does-not-exist-2']   # 없는 자리만 선언
```

```
검사를 시작합니다.
결과 폴더 : /tmp/console-capture/ochk  (artifacts.json · scan.json · plan.json)
검사 완료 : 흔적 0건 · 취약 0건
  안내: 점검 대상이 이 기계에 없습니다 — 선언한 자리 2곳이 전부 존재하지 않습니다: /opt/does-not-exist-1 · /opt/does-not-exist-2
        경로가 틀린 것이 아닌지도 함께 보십시오.

취약한 곳을 찾지 못했습니다.
[exit=0]
```

**미설치 기계가 가장 흔한 경우다.** `/etc/php` 가 없는 기계를 *확인 필요*(6)로
내보내면 멀쩡한 기계를 두고 사람을 부른다. 그래서 점검에서는 그쪽으로 틀리지
않기로 했다 — 반대로 치료에서는 여전히 6 이다. 아무 곳도 열어 보지 못한 스캔이
*"위협 없음"* 을 내는 구멍의 회귀 방지가 그쪽에 걸려 있다.

**0 이 두 뜻을 담게 되어 화면이 갈라 말한다.** 머리말이 `주의:` 가 아니라
`안내:` 인 것은 불완전이 아니기 때문이고, 없던 경로를 함께 적는 것은 코어가
**미설치**와 **선언 오타**를 가릴 수 없기 때문이다 — 그 판단은 읽는 사람 몫이고,
재료가 화면에 없으면 0 은 그냥 침묵이 된다. `주의:` 와 달리 이 줄은 **stdout** 으로
나간다: 무인 배포는 stderr 를 버린다.

### 점검이 취약을 찾으면 — 위협이 아니라 취약이다 (B-2)

```
검사를 시작합니다.
결과 폴더 : /tmp/console-capture/ochk2  (artifacts.json · scan.json · plan.json)
검사 완료 : 흔적 1건 · 취약 1건
   1. /tmp/console-capture/chk/exposed.evil

취약합니다. 위에 적은 항목을 확인하십시오.
[exit=2]
```

> **항목 줄과 마지막 줄은 2026-10-28 에 생겼다.** 그전에는 `취약 1건` 이라는
> **수만** 내고 *"근거는 결과 폴더의 scan.json 에 있습니다"* 로 끝났다 — 무엇이
> 취약한지는 JSON 에만 있었고, 화면이 **사람에게 JSON 을 읽으라**고 했다.
> 치료 쪽은 계획을 줄줄이 적는데 **점검만 비어** 있었다. 항목은 판정이 선
> 그룹의 증거만 적고, 10건이 넘으면 `그 외 N건` 으로 접는다(`--verbose` 는 전부).

**판정 칸이 `위협 1건` 이 아니라 `취약 1건` 이다.** 같은 종료 코드 2 가 치료
플러그인에서는 *"감염됐다"* 이고 점검에서는 *"취약하다"* 인데, 취약한 서버에
*"위협 발견"* 이라고 말하면 감염된 줄 알고 기계를 내린다.

**`검사 완료` 와 `흔적` 은 바꾸지 않았다.** 하네스 둘이 그 줄 **수**로
*"한 회차는 한 언어"* 를 재고(`검사 완료|Scan done`), `trunc-verify` 가
`흔적 [0-9]*건` 을 읽는다. 갈라지는 것은 판정 칸과 결과 줄이다.

`kind: check` 를 적고 `remediate` 를 함께 두면 **린트가 오류로 막는다**(종료 4) —
코어가 점검 어휘로 보고하면서 파괴를 계획하는 모양이기 때문이다. 그 화면은
리눅스 캡처의 `L4` 절에 있다.

### 점검이 버전을 견주지 못하면 — 양호가 아니라 확인 필요다 (C-1)

```
검사를 시작합니다.
결과 폴더 : /tmp/console-capture/ochk3  (artifacts.json · scan.json · plan.json)

  주의 'value' 의 값 '8.2.28-1ubuntu1' 을 버전으로 읽지 못했습니다 — version_lt 는 점으로 나눈 숫자만 비교합니다(예: 8.2.29). 사전 배포 꼬리(RC1 · -dev)와 패키지 개정(-1ubuntu1)은 순서가 서로 반대여서 받지 않습니다
  주의: 아래 까닭으로 '취약하지 않다' 고 판단할 수 없습니다:

```

**이 화면이 없던 판은 종료 0 · *"취약한 곳을 찾지 못했습니다"* 였다**(실측
2026-10-27). 주의 줄은 찍히는데 결론이 *"없다"* 였고, 무인 배포는 그 줄이 실린
stderr 를 버린다. `version_lt` 는 점으로 나눈 숫자만 견주는데 **배포판이 패치한
PHP 가 바로 꼬리 붙은 모양**이라 그것이 가장 흔한 경우다 — `8.4.0RC1`(사전 배포)은
`8.4.0` 보다 낮고 `8.2.28-1ubuntu1`(패키지 개정)은 `8.2.28` 보다 높아 **모양이 같고
순서가 반대**여서 추측할 수 없다.

**그래서 *"안 맞았다"* 가 아니라 *"재지 못했다"* 로 센다.** 관측의
`unreadable_versions` 가 YARA 미평가와 같은 레일이고, 사유 줄이 **읽지 못한 값을
적는다** — 개정인지 사전 배포인지 가리는 것은 읽는 사람 몫이다.

> **영어 화면에서 첫 줄의 `주의` 는 한글로 남는다.** 평가기의 진단 채널
> (`scan.json` 의 `issues`)에는 i18n 이 **없다** — 7개 진단 전부 한국어이고,
> 번역하면 기록이 로케일에 따라 달라진다. **결론과 사유는 영어다**:
> `1 version could not be compared: 8.2.28-1ubuntu1` ·
> `Observation incomplete: cannot declare 'not vulnerable'.` 이 절이 그 간극을
> 기준선에서 처음 드러낸 자리다(C-1 · 보고만).


`거부된 자리` 는 **09-14 에 더했다.** 그 전에는 개수만 있었고, 개수는 *"이
스냅샷을 믿어도 되는가"* 에는 답하지만 *"그럼 어디를 봐야 하는가"* 에는
답하지 못한다. 경로는 `artifacts.json`·`scan.json`·`plan.json` 에 있었는데,
**계획이 만들어지지 않은 회차**(`scan` · `--dry-run` · 종료 코드 6)는
상태 디렉터리에 계획이 없어 `support-bundle` 이 담을 것도 없다 — 하필
관측이 불완전했던 회차에서만 경로가 사라졌다(09-14 실측). 화면에 적으면
`run.log` 가 그대로 복사하므로 모든 회차가 한 번에 덮인다.

여러 곳에서 막히면 **앞의 세 곳과 나머지 수**다. 전수는 산출물에 있고,
화면은 실마리만 준다.

```text
     - 접근이 거부된 디렉터리 열기 5회 (관리자 권한으로 다시 돌리십시오)
       거부된 자리:
         C:\remedy-lab\obs-deny\locked
         C:\remedy-lab\obs-deny\locked2
         C:\remedy-lab\obs-deny\locked3
         외 2곳
```

**만드는 데 이틀이 걸렸고, 까닭은 원인이 둘이었기 때문이다.** 09-11 에는
*"`SeBackupPrivilege` 때문"* 이라고 적었는데 절반만 맞았다 — 특권을 전부
끄고도(활성 특권 0개) 여전히 열렸다. 랩의 관리자 토큰은 **두 길**로 ACL 을
지나간다.

| 길 | 막는 법 |
|---|---|
| **소유권** — 폴더 소유자가 `BUILTIN\Administrators` 면 DACL 에 허용이 하나도 없어도 연다 | `icacls /setowner` 로 SYSTEM 에게 넘긴다 |
| **특권** — `SeBackupPrivilege` 등이 ACL 을 우회한다 | 자식 프로세스에서 전부 끈다 |

하나만 막으면 여전히 열린다. 둘을 함께 막은 회차에서 비로소 `denied_dirs` 1
· 종료 코드 6 이 나왔고, **잠긴 폴더의 파일은 `artifacts.json` 에 실리지
않았다** — 못 본 것을 없는 것으로 만들지 않았다는 뜻이다.

`C:\System Volume Information` 이 이 랩에서 열리는 것도 같은 이유다 —
소유자가 Administrators 다.

### 서명 검증 실패 (5) — 손댄 자리를 이름으로 댄다

서명된 꾸러미는 파일마다 해시가 매니페스트에 있고, 매니페스트는 서명돼 있다.
손대지 않았으면 이렇게 말한다.

```text
  서명  evilai-locust 0.1.0 (2026-09-11T00:00:00Z)
  파일  3 개 — 매니페스트와 전부 일치
  폐기  목록 없음 — 폐기 여부를 확인하지 못했습니다
```

한 바이트를 고치면 그 자리가 선다.

```text
실패: 서명과 실제 파일이 다릅니다 (1건)
  - rules/evilai.yar: 서명 이후 내용이 바뀌었습니다
  (종료 코드 5: 안전 가드에 의한 중단 (상한 초과·보호 경로·서명 검증 실패))
```

**무엇을 했는지에 따라 문구가 다르다.** 셋 다 종료 코드는 5 다.

| 손댄 것 | 문구 |
|---|---|
| 내용을 고쳤다 | `rules/evilai.yar: 서명 이후 내용이 바뀌었습니다` |
| 파일을 더했다 | `rules/extra.yar: 서명되지 않은 파일이 들어 있습니다` |
| 파일을 지웠다 | `rules/evilai.yar: 서명된 파일이 없습니다` |

**서명 파일 자체가 없으면 또 다른 문구다** — `MANIFEST.minisig 를 읽지
못했습니다 — 서명되지 않은 플러그인일 수 있습니다`. *"없는 것과 틀린 것을 나눈다"*
가 코드의 설계이고, 뭉뚱그리면 사람이 원인을 찾는 데 시간을 쓴다.

이 화면들은 기준선에 없다. `testbed/harness/host/Invoke-SignVerify.ps1` 이
임시 키로 서명하고 네 가지로 손대 판정 아홉으로 잰다 — **VM 이 필요 없다.**
`plugin verify` 는 파일을 읽어 해시를 견줄 뿐 기계를 만지지 않는다.

### 보호 경로 (5) — 목록에 없는 자리도 막는다

`C:\Windows` 는 보호 목록에 **없다**. 목록은 `System32`·`SysWOW64`·`WinSxS`·
`Boot` 이고, 그 위를 통째로 넣으면 첫 플러그인부터 아무것도 못 한다. 그래서
`C:\Windows` 를 막는 것은 목록이 아니라 **다른 조건**이다 — *대상이 보호
디렉터리를 품고 있는가.*

```text
검사를 시작합니다.
실패: 계획 실패: 안전 가드가 계획을 거부했습니다 (2):
  [G6] Action #1: 'C:\Windows' 이 읽기 상한 밖입니다. 선언된 상한: C:\Windows\Temp\remedy-lab-guard
  [G6] Action #1: 'C:\Windows' 을 통째로 지우면 보호 디렉터리 'c:\windows\system32' 가 함께 사라집니다
  (종료 코드 5: 안전 가드에 의한 중단 (상한 초과·보호 경로·서명 검증 실패))
```

**두 겹이 동시에 잡았다.** 읽기 상한 밖이라는 것과 보호 디렉터리를 품었다는
것 — 어느 하나만 있어도 섰다. 안전 가드는 그렇게 겹쳐 놓는다.

흉내낸 것은 **capture 가 얕게 풀린 모양**이다. 실제로 있었던 일이고(설계-03
§4 조건 5) 그때는 `%LOCALAPPDATA%\Programs` 가 통째로 대상이 됐다 — 사용자가
설치한 프로그램이 전부 거기 있다.

**가드는 계획 단계에서 선다.** `--dry-run` 도 `--yes` 도 같은 5 를 내고, 승인
화면조차 나오지 않는다. 잰 회차에서 `System32` 파일 4456개와 `C:\Windows`
항목 111개가 전후로 같았고 격리물도 저널도 0이었다 — **아무것도 시작되지
않았다.**

이 화면은 기준선에 없다. `testbed/harness/host/Invoke-GuardVerify.ps1` 이
판정 여덟로 잰다.

다음이다: 저널에 남은 계획의 해시와 대조해 **승인받은 것과 다르면 수행하지 않는다.**
확인해 보면 `x.evil` 은 그대로 있다.

### 크래시 (7) — 죽어도 사유가 남는다


영어도 같다 — `Error: internal error: the tool itself crashed. …`.

**어디서 죽었는지와 기록이 어디 있는지를 말하고 죽는다.** 저널은 줄마다 디스크에
내려쓰므로, 기계는 그 시점까지의 기록 그대로다.

**`panic = "abort"` 에서도 훅이 돈다**(2026-09-11 Windows 실측). 배포 프로필은
되감지 않고 죽으므로 훅이 없으면 이 화면 대신 OS 의 값(`0xC0000409`)이 나간다 —
2026-09-07 에 실제로 그랬고 그래서 훅을 세웠다. 릴리스 프로필에
`-C debug-assertions=on` 만 얹어 지은 바이너리로 재어 **7 과 위 화면**을 받았다.
한국어·영어 둘 다, 크래시 기록도 남았다.

**그래도 "배포 빌드로 쟀다" 고는 못 한다.** 패닉을 일으키는
`REMEDY_PANIC_TEST` 는 `cfg(debug_assertions)` 아래에 있고 `is_dev_build()` 도
같은 cfg 다 — **스위치가 있는 순간 제품은 자기를 개발 빌드로 분류한다.** 둘은
구조적으로 동시에 성립하지 않는다. 잰 것은 *"abort 프로필에서 훅이 7 을
내는가"* 이고 그 답은 예다. `testbed/harness/host/Invoke-PanicVerify.ps1` 이
판정 열로 잰다.

## 18. 두 운영체제의 차이

| | Windows | Linux |
|---|---|---|
| 권한 | 관리자 | root (`sudo`) |
| 언어의 기본 | PC 로케일(`HKCU\Control Panel\International\LocaleName`)이 한국어면 한국어, 아니면 영어 — 환경변수 없이 더블클릭해도 한국어가 나온다 | POSIX `LANG`·`LC_*` 가 한국어면 한국어, 아니면 영어 — C 로케일 컨테이너는 영어 |
| 권한 안내의 처방 | 실행 파일 우클릭 → '관리자 권한으로 실행' 을 먼저, 관리자 터미널을 그다음 | `sudo 로 다시 부르십시오.` 한 줄 |
| 장식 | 늘 UTF-8 (콘솔에 `WriteConsoleW` 로 그대로 간다) | 로케일 문자 집합이 UTF-8 이 아니면 ASCII |
| 자기무결성 | Authenticode 서명 확인 | 없음 — "확인하지 못했습니다" 알림 |
| 치료 Op | 프로세스·예약 작업·레지스트리·백신 예외·파일·폴더 | 설정 줄·바로가기 인자·파일·인증서 저장소 |
| 폴더째 삭제 | 있다 (`dir.delete_recursive`) | 없다 — 파일 단위로 격리한다 |
| 재부팅 예약 | RunOnce 에 `verify … --lang …` | 없다 |
| 복원 못 하는 것 | `ctime`, 담지 않은 `btime` | `ctime`, `btime`, 이미 있는 파일 |
| 창 유지(§2) | 있다 — 더블클릭이 흔한 자리다 | 있다 — 같은 규칙(stdin 이 터미널일 때만) |
| 안내 모드(§2) | 있다 | 있다 |

**권한 안내의 길이가 다른 것은 독자가 다르기 때문이다.** 리눅스에서 root 를 요구받는
사람은 `sudo` 를 안다. Windows 에서 이 화면을 보는 사람은 홈페이지에서 받아 더블클릭한
사람일 수 있고, 그에게 "관리자 권한으로 실행하라" 는 처방이 아니라 문제의 재진술이다.

## 19. 검사 시간 — 같은 파일인데 읽기만 수십 배

한 회차의 로그에서 뽑은 두 번의 검사다. **둘 다 같은 670.3 MB · 7,947개.**

| 회차 | 검사 | 걷기 | **읽기** | 해시 | 서명 |
|---|---|---|---|---|---|
| 치료 | 4.8초 | 0.2 | **2.2** | 0.4 | 1.4 |
| 재평가 | 112.1초 | 0.2 | **108.8** | 0.5 | 1.7 |

**우리 몫은 붙박이다** — 걷기 0.2 + 해시 0.4 + 서명 1.4 = 2.0초. 움직이는 것은
**읽기 하나**이고 그것이 **49배**로 늘었다. 파일을 여는 비용, 즉 설치된 백신의
온액세스 검사이고, 우리가 정할 수 있는 값이 아니다.

같은 기계에서 하루 전에 잰 값은 1.8초와 81.6초(45배)였다. **배수는 회차마다
달라지지만 갈라지는 자리는 늘 같다** — 우리 몫은 붙박이고 읽기만 움직인다.

그래서 이 줄이 회차 로그에 있다 — 다음에 "왜 느린가" 라는 물음이 오면 추측이 아니라
숫자로 답한다.

## 20. 알려진 지표 목록으로 잡는다 — 해시와 도메인

위협 정보가 준 **SHA-256 목록과 C2 도메인 목록**으로만 가려지는 위협이다. 자리·이름·
모양으로는 못 가르게 만들었다 — 검체와 **같은 폴더에 사용자 파일**(`notes.txt`)이
있고, **같은 모양의 정상 자동 시작 항목**(`vendor-update.desktop`)이 자기 도메인을
갖는다. 목록에 있는 것만 지워야 하고, 그 둘은 남아야 한다.

위협 `c2-beacon` · 리눅스 컨테이너 · 릴리스 빌드. `in` 연산자와 `indicator` 대상의
첫 사용례다(2026-09-09) — 그 전까지 둘은 엔진에만 있었다.

### 룰 — 목록 둘과 그것을 실은 항목 하나

```yaml
scan_roots:
  - "/opt"                        # 목록이 있어도 읽는 범위는 이것이 정한다
subjects: [autorun, file, indicator]

detect:
  - id: payload                   # ① 알려진 검체 — 피드의 SHA-256 목록 그대로
    subject: file
    where:
      - field: sha256
        op: in
        value:
          - fec8aa606ec99721bd2a5153d2973816484c18b755e23fd508b1146d954195c7   # agent.bin
          - 384670229c221ff5384c8b7691d711efe8763a41c48490f184727d334e95f5fe   # helper.so
          - 7a1c0e4d9b2f6853a0c7e1b4d8f2a6c9e3b5d7f1a4c8e0b2d6f9a3c5e7b1d4f8   # 변종 — 이 기계에 없다
          - c3e9a1f7b5d2064e8a0c2f4b6d8e1a3c5f7b9d0e2a4c6f8b1d3e5a7c9f0b2d4e6   # 변종 — 이 기계에 없다

  - id: beacon                    # ② 알려진 C2 — 수집이 명령줄에서 뽑아 둔 지표를 목록과 견준다
    subject: indicator
    where:
      - { field: kind, op: equals, value: "domain" }
      - field: value
        op: in
        value:
          - cdn.evil-metrics.example
          - api.evil-metrics.example
          - relay.evil-metrics.example

  - id: autostart                 # ③ 검체를 띄우는 자동 시작 항목 — 없앨 것은 이것이다
    subject: autorun
    where:
      - { field: command, op: starts_with, value: "/opt/.cache-9f2/" }

verdict:
  require: "autostart and payload and beacon"   # 셋이 다 서야 한다 — 목록 하나가 헛돌면 무너진다

remediate:
  remove:
    - { ref: autostart }   # autorun.remove — 항목 파일 하나
    - { ref: payload }     # file.quarantine_only — 목록에 있는 둘만
```

**지표(②)는 없앨 대상이 아니다.** 판정에만 쓰고, 없애는 것은 그 지표를 실은 항목(③)
이다. 그래서 `remove` 에 `beacon` 이 없다.

### 어느 목록의 어느 값에 맞았는지는 `scan.json` 에

결과 폴더의 `scan.json` 은 증거마다 **어느 규칙의 어느 조건이 어떤 값으로 맞았는지**
(`matched`)를 적는다. 도메인 하나와 해시 하나를 옮겼다 — 나머지 둘은 같은 모양이다.

```

    …
    {
      "id": "beacon#0",
      "rule": "beacon",
      "subject": "indicator",
      "target": {
```

| 읽을 것 | 뜻 |
|---|---|
| `source_ref: autorun[0].command` | 이 도메인이 **어디서 나왔는가** — 자동 시작 항목의 실행 줄. 지표는 늘 근거를 달고 온다 |
| `matched[].value` 의 목록 | 룰에 적은 목록 **전체**가 그대로 실린다. 어느 항목이 맞았는지는 `target` 과 견주면 안다 — 해시 넷 중 `target.sha256` 과 같은 것 하나 |
| 목록에 있는데 `target` 에 없는 값 | 변종 몫. 이 기계에 없어도 목록에 두는 것이 맞다 |

### 이 룰이 밟은 함정

- **systemd 서비스는 지표 원천이 아니다.** 처음에는 이 위협을 `.service` 로 세웠고,
  스냅샷의 지표가 **0건**이었다. `.service` 는 `service` 대상으로 모이고 지표 수집은
  persistence·autorun·process·설정·hosts 에서만 거둔다. 서비스 실행 줄의 C2 는 도메인
  목록에 절대 닿지 않는다 — 자동 시작 항목으로 바꿨다.
- **해시는 소문자로.** 수집이 소문자 16진수로 내고, 리눅스 비교는 대소문자를 가린다.
- **`sha256` 뿐이고 32 MiB 까지다.** MD5·SHA-1 피드는 못 쓰고, 큰 검체는 경로·YARA 로.
- **목록은 범위를 넓히지 않는다.** `scan_roots` 밖은 읽지 않는다 — `/opt` 로 넓힌 것은
  폴더 이름이 감염마다 바뀌어서다(린트 경고 하나가 그것을 짚는다).

레시피와 원천 표는 `docs/plugin-guide/20-detect-recipes.md` §알려진 지표 목록.
