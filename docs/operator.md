# 운영자 가이드 — 현장에서 remedy 를 쓰는 법

시연을 보고 *"우리도 써 보겠다"* 는 사람을 위한 한 장. 룰을 **쓰는** 사람은
[`plugin-guide/`](plugin-guide/README.md) 로 간다.

> **배포물은 실행 파일 하나와 룰 한 벌이다.** 설치하지 않고, 재배포 패키지가
> 필요 없고, **네트워크를 말하는 코드가 링크되어 있지 않다** — 임포트 전수를
> `cargo xtask static` 이 매 빌드 확인한다. 폐쇄망에서 그대로 돈다.

## 0. 시작 전에 셋

| | |
|---|---|
| **받는 것** | 꾸러미 폴더 하나 — `remedy.exe` · `README.txt` · `plugins\<위협>\`(그 안에 `plugin.yaml` · `rules\*.yar` · 서명). **통째로 풀고 파일을 옮기지 않는다** |
| **권한** | **관리자로 연 창에서 돌린다.** 아니면 시작하지 않고 그렇게 말한다(종료 코드 5). 예약 작업·HKLM·다른 사용자의 파일이 관리자 없이는 열리지 않고, 그러면 감염된 PC 에서도 증거가 나오지 않는다 |
| **서명** | **서명이 없어도 전부 동작한다**(2026-09-02) — 다만 공식 배포본이 아니라는 알림이 매 실행에 뜬다. 거절하는 것은 **서명해 둔 뒤 내용이 바뀐** 바이너리다: 스캔·보고는 하고 치료는 하지 않는다(종료 코드 5). 자세한 것은 §5 |

상태(격리물·감사 로그·회차 로그 `logs\<run_id>.log`)는 기본으로 `%PROGRAMDATA%\remedy` 에 쌓인다.
`--state-dir` 로 옮길 수 있다. **되돌리려면 이 디렉터리가 있어야 한다.**

## 1. 순서 — 보고 나서 지운다

```
scan   무엇을 지울지 계획을 만든다.        아무것도 건드리지 않는다
  ↓    사람이 계획을 읽는다
run    수집부터 치료까지 한 번에            승인을 묻는다
```

**두 단계인 이유**: `scan` 이 낸 `plan.json` 은 사람이 읽고 승인하는 문서이고,
**다른 기계로 옮겨 `apply --plan` 에 그대로 먹일 수 있다.** 실행기는 계획에
있는 것만 한다 — 스스로 새 대상을 찾지 않는다.

```powershell
# 0) 이 꾸러미가 우리 것인가 — 서명과 파일이 하나도 안 바뀌었는지 본다
.\remedy.exe plugin verify --dir .\plugins\evilai-locust

# 1) 본다
.\remedy.exe scan --plugin .\plugins\evilai-locust\plugin.yaml --out-dir .\out

# 2) .\out\plan.json 을 읽는다

# 3) 고친다 (승인을 묻는다)
.\remedy.exe run --plugin .\plugins\evilai-locust\plugin.yaml --out-dir .\out
```

`run` 은 콘솔에서 이렇게 묻는다. `예` 를 쳐야 진행한다.

```
위 계획을 수행합니다. 되돌리려면 restore 를 써야 합니다. 진행하려면 '예' 입력:
```

## 2. 명령 일곱

| | |
|---|---|
| `scan --plugin <p> --out-dir <d>` | 관찰 → 판정 → 계획. **건드리지 않는다** |
| `run --plugin <p> --out-dir <d>` | 위 + 치료 |
| `apply --plan <plan.json>` | 이미 만든 계획만 수행 |
| `resume --run <id> [--plugin <p>]` | 저장된 계획을 이어 실행한다. **재스캔하지 않는다** — 승인받은 것과 다른 일이 벌어지면 안 되기 때문이다. 계획이 재부팅 뒤 재평가를 원하면 `--plugin` 이 있어야 그것을 건다 |
| `restore --list` | 되돌릴 수 있는 회차를 보여 준다. **읽기만 한다** |
| `restore --run <id>` | 되돌린다 |
| `verify --plugin <p> --run <id>` | 치료가 유지됐는가. 다 보지 못하면 *"치료 성공"* 대신 `6` 이다(§3) |
| `support-bundle --run <id>` | 신고에 붙일 것을 모은다 |

인자 없이 `remedy` 를 치면 **옆에 꾸러미가 있는지 먼저 본다.** 있으면 그것으로
검사를 시작하고(아래 안내 모드), 없으면 **자주 쓰는 것만 추린 사용법**이 나온다.
전체 명령과 종료 코드는 `remedy --help-all` 이다 — 첫 화면에 다 쏟으면 처음 온
사람이 무엇을 해야 하는지 못 찾는다.

### 안내 모드 — 받아서 더블클릭한 사람

**꾸러미를 받은 사람의 기본 경로다.** 통째로 풀고 `remedy.exe` 를 더블클릭하면
옆의 `plugins\` 를 찾아 **검증을 통과한 꾸러미만** 고를 거리에 올리고, 고른
것으로 `run` 과 **같은 문**을 지난다 — 권한 검사도 승인 질문도 같다. 두 벌이
되면 갈라지고, 갈라지면 이 경로로 들어온 사람만 다른 판정을 받기 때문이다.

| 상황 | 무엇이 나오나 |
|---|---|
| 꾸러미 하나 | 작업 메뉴(*무엇을 할까요?*) — 고른 작업이 끝나면 메뉴로 돌아온다. 터미널이 아니면 그것으로 바로 검사 |
| 여럿 | 번호로 고른다 |
| 쓸 수 있는 것이 **하나도 없음** | 왜 못 쓰는지 적고 **종료 코드 5** |
| 꾸러미가 **아예 없음** | 사용법 (종료 코드 0) |

> **쓸 수 있는 것이 없을 때 0 으로 끝내지 않는다.** 꾸러미가 있는데 하나도 못
> 썼다면 검사를 한 적이 없는 것이고, `0` 은 *"이 PC 는 깨끗하다"* 로 읽힌다.

**창은 깜빡이고 사라지지 않는다.** 메뉴에서는 작업이 끝나면 메뉴로 돌아오고,
**끝내는 것은 사람이다** — `0. 그만두기` 를 고르거나 Ctrl+C 를 두 번(2초 안에)
누른다. 한 번은 끝내지 않고 *"Ctrl+C 를 한 번 더 누르면 끝납니다"* 를 띄운다. 메뉴는
↑↓ · Enter 로도, 번호로도 고른다. 꾸러미가 없어 사용법이 나온 창은 `이 창을 닫으려면
Enter 를 누르십시오.` 에서 기다린다.

> 파일로 받는 출력에는 처음부터 없고, `NO_COLOR=1` 이면 터미널에서도 끈다.

> 무인 배포에서 **재부팅 회차는 `REMEDY_LANG` 을 물려받지 못한다.** `run` 이
> 예약할 때 이 회차의 언어를 실어 보내므로(§6) 한 회차의 로그가 두 언어로
> 갈리지 않는다.

## 3. 종료 코드로 판단한다

**무인 배포에서는 이것이 전부다.** 화면의 문구는 사람이 읽는 것이고, 스크립트는
코드를 본다.

| 코드 | 뜻 | 그래서 무엇을 |
|---|---|---|
| **0** | 위협 없음 | 끝. 다만 §5 의 `6` 과 헷갈리지 말 것 |
| **1** | 발견 · **치료 완료** | 끝. 재부팅 뒤 `verify` 로 확인하면 더 좋다 |
| **2** | 발견 · **치료 안 함** | 사람이 거절했거나 드라이런. 계획을 읽고 다시. `verify` 에서는 **재발**이다 — 같은 치료를 되풀이하지 말고 새 증거를 사람이 본다 |
| **3** | **부분 실패** | 일부 Action 이 실패했다. 화면의 `실패 [n]` 줄을 보라 — 대개 파일 잠금이다. 재부팅 뒤 다시. `verify` 에서는 원래 증거의 일부가 남았다는 뜻이다(`실패 [n]` 줄은 없다) |
| **4** | 사용법·입력 오류 | 명령이나 룰이 잘못됐다. 배포 문제다 |
| **5** | **안전 가드 중단** | 도구가 **일부러 멈췄다.** §5 |
| **6** | **관측 불완전** | *"위협 없음"* 을 말할 수 없다 — 다 보지 못했다(수집이 잘렸다 · 접근이 거부됐다 · 선언한 자리가 전부 없다 · 선언한 자리를 **있는지조차 물어보지 못했다**(막힌 트리 · 끊긴 UNC · 준비되지 않은 장치) · YARA 규칙을 재지 못했다 · 버전을 견주지 못했다 등). **0 으로 취급하면 안 된다.** 무엇이 모자랐는지는 화면의 `주의:` 아래 줄이 말한다(무인 배포면 회차 로그 `logs\<run_id>.log` 에 같은 줄이 남는다). `verify` 에서는 *"치료 성공"* 을 말할 수 없다는 뜻이다 |
| **7** | **내부 오류** | 도구 자체가 멈췄다(크래시). `logs\crash-*.txt` 가 남는다 — 그것을 신고에 붙인다. 기계는 저널이 기록한 상태 그대로다 |

## 4. 되돌리기 — 이 도구의 핵심

오탐이라고 보면 **먼저 되돌리고** 그다음 신고한다.

치료가 끝나면 화면 마지막에 되돌릴 명령이 그대로 나온다.

```
격리소 : ...\state\quarantine\run-1788142329-32a4-2673442c.rq
되돌리려면: remedy restore --run run-1788142329-32a4-2673442c
```

**창을 닫아 `run_id` 를 잃어버렸어도 괜찮다.** 되돌릴 수 있는 회차를 도구가 직접
보여 준다 — 키 없이 평문 헤더만 읽으므로 무엇이 들었는지는 나오지 않고, 어느
회차가 있는지만 나온다.

```powershell
remedy restore --list
```

```
되돌릴 수 있는 회차 2건
  2026-09-08 02:11:43 UTC  run-1788833503-aa48-38a6a7b0 · 1528 바이트
  2026-09-08 01:56:30 UTC  run-1788832578-1054-21a88b28 · 7443 바이트

되돌리려면 : remedy restore --run run-1788833503-aa48-38a6a7b0
```

깨진 격리물이 있어도 목록은 선다 — 못 읽은 것은 못 읽었다고 적고 나머지를 보인다.

```powershell
# --yes 없이 부르면 **계획만 보인다.** 아무것도 되돌리지 않는다
remedy restore --run <run_id>

# 확인했으면
remedy restore --run <run_id> --yes
```

계획에는 **복원할 수 없는 항목**이 함께 나온다. 조용히 빠지지 않는다.

```
  [e3] C:\...\preload.js
        복원 불가  ctime — 운영체제가 관리하는 값이라 복원할 수 없습니다
```

### 누가 열 수 있는가

컨테이너는 내용키를 **여러 겹으로 싸 둔다.** 어느 겹이든 하나만 풀면 열린다.

| 겹 | 열쇠 | 어떻게 |
|---|---|---|
| `local` | 이 기계의 봉인 키 | 기본 경로 |
| `pass` | 사용자 패스프레이즈 | `restore --passphrase-file <파일>` |
| `org` | 조직 복구 키 | `restore --org-key-file <파일>` — **다른 기계에서도 연다** |

> **`local` 뿐이면 재설치 전에 되돌려라.** 그 경우 도구가 *"로컬 wrap 뿐입니다.
> 이 머신을 재설치하면 이 격리물은 열 수 없습니다."* 라고 말한다. 조직 복구 키를
> 함께 싸 두면 그 제약이 없다.

### 더 고를 수 있는 것

| | |
|---|---|
| `--entry <id>` | 회차 전부가 아니라 **항목 하나씩** 되돌린다 |
| `--container <파일>` | 회차 기록 없이 **컨테이너 파일로** 연다 |
| `--extract-to <디렉터리>` | 원래 경로가 아니라 **지정한 폴더로** 내보낸다 |

**넘겨받은 격리물은 `--extract-to` 로 꺼낸다.** 제자리 복원은 원래 기계에서만
보장된다 — 이 기계의 저널에 *"우리가 그 자리에서 담았다"* 는 기록이 없기
때문이다. 이 머신의 키로 열리지 않으면 도구가 *"다른 머신에서 만든 컨테이너입니다.
`--org-key-file` 로 열고 `--extract-to` 로 꺼내십시오"* 라고 안내한다.

## 5. 막혔을 때

검사가 5초를 넘기면 화면에 `검사 중 · <단계> · 폴더 N개 · 항목 M개 · 처리 K개 · 경과 S초` 가
5초마다 나온다(1분 뒤에는 30초마다). 파일 단계에는 지금 보는 폴더나 파일이 뒤에 붙는다 —
걷기는 몇 초지만 항목마다 하는 읽기·해시·서명 확인이 `처리 K개` 로 올라간다.
**단계도 숫자도 바뀌지 않으면 그 자리에서 멈춘 것**이고, 줄 자체가 멎으면 프로세스가
멈춘 것이다. 크래시 기록(`logs\crash-*.txt`)에도 마지막 단계와 폴더가 적힌다.

치료 중에도 같다 — 외부 도구(`sc.exe`·`taskkill`·복원 지점)가 오래 돌면 `치료 중 · 도구
sc.exe stop 65초 · 경과 S초` 가 나온다. **도구는 죽이지 않는다.** 서비스 중지처럼 1분을
넘겨도 끝나는 일은 끝나게 둔다. 진짜 멈췄다고 판단되면 사람이 끊는다(Ctrl+C).

검사 시간의 대부분은 **파일 열기**다 — 실기기(파일 7,947개 · 670 MB)에서 검사 95초 중
읽기 91초, 해시 0.5초, 서명 1.5초였다. 백신의 실시간 감시가 파일을 열 때마다 검사하는
비용이고, 그 시간은 받아 준다. 회차 로그의 `# 검사 시간` 줄이 그 내역이다.

| 증상 | 뜻 | 할 것 |
|---|---|---|
| 받자마자 · *"Windows의 PC 보호"* 파란 창 | **SmartScreen 이다. remedy 가 낸 것이 아니다.** 인터넷에서 받은 실행 파일 중 평판이 쌓이지 않은 것에 뜬다 — 서명해도 배포 초기에는 남는다 | 창의 **추가 정보** → **실행**. 그 전에 받은 파일이 배포처의 것인지 확인한다(§5 의 서명 항목) |
| `exit 5` · *"이 바이너리의 서명을 신뢰할 수 없다"* | 서명해 둔 뒤 **내용이 바뀌었다** — 부분 다운로드·디스크 손상·변조 중 하나다 | 배포처에서 원본을 다시 받는다. 조직 내부 CA 로 서명해 신뢰 저장소에 앵커해도 된다 |
| 알림 · *"이 바이너리에 서명이 없습니다"* | **막지 않는다.** 서명은 공식 배포의 절차이지 기능의 조건이 아니다(2026-09-02). 다만 공식 배포본이 아니라는 뜻이므로 그 사실이 매 실행에 표시된다 | 운영 배포라면 서명된 것을 받는다. 시연·검증이라면 그대로 써도 된다 |
| `exit 5` · *"보호 경로"* · *"상한 초과"* | 계획이 건드리면 안 되는 것을 지목했다 | **룰 문제다.** `plan.json` 과 함께 룰 작성자에게 |
| `exit 5` · *"관리자 권한이 필요합니다"* | 권한 없이 불렀다 | 관리자로 창을 다시 열고 같은 명령을. 무인 배포면 §6 |
| `exit 7` · *"내부 오류"* | 도구가 **깨졌다** — 가드가 막은 것이 아니다 | `logs\crash-*.txt` 와 `logs\<run_id>.log` 를 신고에 붙인다. `support-bundle` 이 둘 다 담는다 |
| `exit 6` · *"YARA 규칙 N개를 평가하지 못했습니다"* | YARA 규칙을 재지 못했다. 왜 못 쟀는지는 그 위의 `주의` 줄들이 말한다 — 본문이 상한을 넘었으면 *"해소되지 않았습니다"* 블록, 룰 파일이 없거나 룰 이름이 틀렸으면 그 줄. 그 둘은 **다시 돌려도 같다** | 상한 · 룰이면 **룰 문제다** — `scan.json` 과 회차 로그(`logs\<run_id>.log`)를 룰 작성자에게. *"읽지 못했습니다"* 면 잠금 · 권한 문제다 — 재부팅 뒤 다시 |
| `exit 6` · *"버전 N개를 견주지 못했습니다"* | 버전 점검 룰이 만난 값이 **점으로 나눈 숫자가 아니었다** — 사유 줄이 그 값을 적는다. `8.2.29-1ubuntu1`(배포판이 패치한 판)이나 `8.4.0RC1`(사전 배포)이면 둘은 **순서가 서로 반대**라 도구가 추측하지 않는다. **다시 돌려도 같다** | **룰 문제이자 판단 문제다.** 그 값이 수정판 이상인지는 공급사 공지로 사람이 가린다 — `scan.json` 과 함께 룰 작성자에게 |
| `exit 6` · *"있는지조차 확인하지 못했습니다"* | 선언한 자리를 **물어보지도 못했다** — 그 자리가 없는 것과 다르다. 부모 폴더·부모 키까지 막혔거나, 끊긴 네트워크 공유(`\\호스트\공유`)이거나, 준비되지 않은 장치다. 사유 줄이 **그 경로를 적는다** | 적힌 경로를 사람이 본다 — 공유라면 연결을, 잠긴 자리라면 권한을. **관리자로 다시 도는 것으로는 안 되는 경우가 많다**(끊긴 공유가 그렇다) |
| `exit 6` · 그 밖의 사유 | 사유 줄이 원인을 댄다 — 수집이 잘렸다 · 접근이 거부됐다(**관리자로 돌려도 남는다** — 변조 방지가 막는 자리 등) · 선언한 자리가 전부 없다(대상이 설치되지 않은 기계) · 선언한 subject 를 모으지 못했다 | 한 번 더 돌려 같은 값이면 그 사실을 보고에 남긴다 |
| `exit 3` · *"다른 프로세스가 파일을 사용 중"* | 잠긴 파일 | 재부팅 뒤 다시. 그래도 남으면 안전 모드 |
| *"승인할 사람이 없습니다 (터미널이 아닙니다)"* | 스크립트·원격 세션에서 `--yes` 없이 불렀다 | 무인이면 `--yes` 를 명시한다 (§6) |
| *"재시작을 권할 수 없는 상태"* | 안전 모드가 온전하지 않거나 확인되지 않았다 | 아래 §5-1 |

### 5-1. 안전 모드를 못 쓴다고 할 때

remedy 는 재시작을 권하기 **전에** 안전 모드 진입 가능 여부를 본다. 악성코드가
안전 모드를 막아 둔 기계에 *"안전 모드로 재시작하세요"* 라고 하면 사용자는
부팅되지 않는 컴퓨터를 받기 때문이다.

**두 가지가 다르다.**

| 화면 | 뜻 |
|---|---|
| `진입 가능 여부: no` 또는 `partial` | 키가 **없는 것을 봤다.** 복원은 OS 복구 도구의 영역이다 — 이 도구는 부팅 구성을 고치지 않는다 |
| `진입 가능 여부: unreadable` | 키는 **있는데 읽히지 않는다.** 권한이 막혔다 — 악성코드일 수도, 보안 정책일 수도 있다 |

`unreadable` 이면 손으로 풀 수 있다. **다만 정책이 잠근 것일 수 있으니 먼저
담당자에게 확인하라** — remedy 는 *잠겼다* 는 것만 알고 *누가 잠갔는지* 는 모른다.

관리자 PowerShell:

```powershell
$sub  = 'SYSTEM\CurrentControlSet\Control\SafeBoot\Minimal'   # 또는 ...\Network
$Hive = [Microsoft.Win32.Registry]::LocalMachine
$Rt   = [System.Security.AccessControl.RegistryRights]

# 1. 소유권을 가져온다. Deny 가 읽기를 막아도 이것은 된다.
$k = $Hive.OpenSubKey($sub, 'ReadWriteSubTree', $Rt::TakeOwnership)
$a = New-Object System.Security.AccessControl.RegistrySecurity
$a.SetOwner([System.Security.Principal.NTAccount]'BUILTIN\Administrators')
$k.SetAccessControl($a); $k.Close()

# 2. 소유자가 되면 ACL 이 읽힌다. Deny 규칙을 걷는다.
$k = $Hive.OpenSubKey($sub, 'ReadWriteSubTree', $Rt::ChangePermissions)
$a = $k.GetAccessControl()
foreach ($rule in @($a.Access | Where-Object { $_.AccessControlType -eq 'Deny' })) {
    $a.RemoveAccessRuleSpecific($rule)
}
$k.SetAccessControl($a); $k.Close()

# 3. 소유자를 되돌린다. 빠뜨리면 소유자가 바뀐 채 남는다.
$k = $Hive.OpenSubKey($sub, 'ReadWriteSubTree', $Rt::TakeOwnership)
$a = New-Object System.Security.AccessControl.RegistrySecurity
$a.SetOwner([System.Security.Principal.NTAccount]'NT AUTHORITY\SYSTEM')
$k.SetAccessControl($a); $k.Close()
```

**1 을 건너뛰고 2 부터 하면 실패한다** — 읽지 못하면 고칠 수도 없다.
`Set-Acl` 로 권한을 바로 쓰는 것도 실패한다. 소유자를 **먼저** 바꾸는 것이
이 절차의 전부다. 풀렸는지는 `scan` 을 다시 돌려 `unreadable` 이 `yes` 로
바뀌는 것으로 본다.

> 변수 이름에 `$r` 을 쓰지 말 것. PowerShell 은 변수명 대소문자를 구분하지
> 않아 `foreach ($r in ...)` 이 `$R` 을 덮어쓴다.

## 6. 무인 배포

```powershell
remedy run --plugin .\plugin.yaml --out-dir .\out --yes --events .\out\run.ndjson
```

- **`--yes` 는 "묻지 말라" 가 아니라 "화면 앞에 사람이 없다" 는 선언이다.**
  계획기가 이 값으로 이동식 매체 대상을 가른다 — 무인에서는 수행하지 않는다.
- `--yes` 없이 터미널이 아닌 곳에서 돌면 **아무것도 하지 않고 거절한다.**
- `--events <파일>` 은 진행 상황을 NDJSON 으로 낸다. **사람이 읽는 출력과 다른
  스트림이다** — 문구를 파싱하지 말고 이것을 읽어라.
- `run --plugin` 으로 돌리면 **재부팅 뒤 재평가가 자동 예약된다**
  (`HKLM\...\RunOnce\remedy-verify`, 실행 뒤 OS 가 지운다).
  `apply --plan` 은 룰 경로를 몰라 예약하지 못하고, 그 사실을 경고로 말한다.
  `resume` 도 같은 자리에서 예약한다 — `--plugin <p>` 를 함께 주면 이어받은 회차에도
  걸고, 주지 않으면 같은 경고를 낸다.
  그 예약에는 **이 회차의 언어가 실린다**(`--lang ko` 등) — 재부팅 회차는
  `REMEDY_LANG` 을 물려받지 못하므로, 싣지 않으면 한 회차의 로그가 두 언어가 된다.
- 재부팅 회차의 판정은 상태 디렉터리의 `verify\<run_id>.jsonl` 에 한 줄로 남는다
  (`support-bundle` 이 `verify.jsonl` 로 담는다). **`outcome` 이 `clean`(종료 0)일
  때만 치료가 유지된 것이다** — `recurred`(2)는 재발, `partial`(3)은 일부 잔존,
  `incomplete`(6)는 다 보지 못해 확인하지 못한 것이다. 무엇을 못 봤는지는 같은 줄의
  `observation` 과 회차 로그(`logs\<run_id>.log`)의 `주의:` 줄이 말한다.

## 7. 신고할 때

```powershell
remedy support-bundle --run <run_id> --out .\bundle
```

담긴 것과 **일부러 담지 않은 것**을 함께 보여 준다.

| 담긴다 | |
|---|---|
| `plan.json` | 무엇을 하려 했는가 |
| `journal.jsonl` | 무엇을 했는가 · **어떤 바이너리가 했는가**(`self_integrity`) · 줄마다 시각(`at`) — 어느 Action 에서 오래 걸렸는지 |
| `verify.jsonl` | 치료가 유지됐는가 |
| `run.log` | **사람이 본 화면** — 배너·계획·경고·실패 문구·마무리 표, 줄마다 시각 |
| `environment.json` | 어떤 코어에서 돌았는가 |

| 담기지 않는다 | 왜 |
|---|---|
| 격리 컨테이너 (`.rq`) | 검체와 **사용자 파일 내용**이 들어 있다. 오탐 복구는 보내지 않고 이 기계에서 `restore` 로 한다 |
| `machine.key` | 격리물을 여는 봉인 키. **어떤 경우에도 첨부하지 마십시오** |

> 보내기 전에 `README.txt` 를 열어 볼 것 — **경로·호스트명·사용자명은 가려지지
> 않는다.** 제출은 도구가 하지 않는다. 사람이 올린다.

## 8. 이 도구가 하지 않는 것

- **네트워크로 나가지 않는다.** 조회도 제출도 없다.
- **실시간 감시를 끄지 않는다.** 치료 도구가 백신을 무력화하는 기능을 가지면
  그 기능 자체가 표적이 된다. 대신 실패를 정확히 진단한다.
- **부팅 구성을 고치지 않는다.** 손상을 알리는 데까지 한다.
- **새 대상을 찾지 않는다.** 실행기는 승인된 계획에 있는 것만 수행한다.
- **롤백하지 않는다.** 중간에 실패해도 나머지를 계속하고, 되돌리기는
  `restore` 로 사람이 결정한다.

## 9. 새 위협이 오면

**룰만 배포한다.** `plugin.yaml` 과 그 옆 `rules/*.yar` 을 바꾸면 된다 —
`remedy.exe` 는 그대로다. 룰을 쓰는 법은 [`plugin-guide/`](plugin-guide/README.md).

받은 룰이 도는지 먼저 확인한다.

```powershell
remedy plugin lint .\새룰\plugin.yaml
```

### 배포 꾸러미를 만드는 쪽이라면

**위협 하나당 꾸러미 하나**다. 받는 사람이 고를 일이 없고, 자기에게 없는 위협까지
검사하며 시간을 쓰지 않는다.

**태그로 내면 Actions 가 같은 차례를 돈다.** `v<코어 버전>` 태그를 밀면
`.github/workflows/release.yml` 이 아래 1) ~ 3) 을 돌고 받는 쪽의 확인(`plugin
verify`)까지 해서 **초안** Release 에 올린다. 시험판은 `v<코어 버전>-rc.<N>`
태그로 내고, 그 초안은 시험판(pre-release)으로 표시된다. 아래는 손으로 할 때의
차례다.

**한 사고에 역할이 둘이면 `--plugin` 을 여러 번 준다** — 점검만 하는 룰과 치료까지
하는 룰처럼. **두 번 불러 같은 폴더에 담을 수는 없다**: 출력 경로에 무엇이든 있으면
`package` 가 거부한다(지우고 다시 만든다). 앞 회차의 파일이 남으면 무엇이 담겼는지
알 수 없게 되기 때문이다.

폴더 이름이나 id 가 겹치면 **붓기 전에** 거부한다. 폴더 이름이 겹치면 꾸러미 안에서
한 폴더로 합쳐지고 — **대소문자만 다른 이름도 Windows 에서는 같은 폴더다** — 섞인 쪽이
받는 사람의 `plugin verify` 에서 거부되거나, 더 나쁘게는 한 룰이 통째로 사라진 채
통과한다. id 가 겹치면 기록·격리물·복원 지점이 어느 룰에서 나온 것인지 구별되지 않고,
폐기 판정도 둘을 한 플러그인으로 본다.

```powershell
# 1) 룰에 서명한다. 개인키는 저장소에 두지 않는다
$env:REMEDY_SIGN_PASSWORD = "<암호>"
cargo xtask sign plugin --dir plugins\evilai-locust `
    --secret-key <키> --signed-at 2026-09-08T09:20:17Z

# 2) 앵커를 박아 빌드한다. 이것이 없으면 받는 사람이 서명을 확인할 수 없다
$env:REMEDY_TRUST_ANCHOR = "<공개키 base64 한 줄>"
cargo build --release --target x86_64-pc-windows-msvc -p remedy-cli

# 3) 꾸러미를 붓는다
cargo xtask package --plugin plugins\evilai-locust `
    --bin target\x86_64-pc-windows-msvc\release\remedy.exe `
    --out dist\remedy-evilai-locust-windows-x64 --public-key <공개키 파일>

# 역할이 둘이면 --plugin 을 여러 번. 둘 다 1) 에서 서명해 두어야 한다
cargo xtask package --plugin <점검 플러그인> --plugin <치료 플러그인> `
    --bin target\x86_64-pc-windows-msvc\release\remedy.exe `
    --out dist\remedy-<사고 이름>-windows-x64 --public-key <공개키 파일>
```

`package` 는 **서명이 맞지 않으면 만들지 않는다.** 여기서 통과시키면 그다음
방어선은 고객의 화면이고, 거기서 실패하면 배포 사고와 변조를 구별할 수 없다.

> **2·3 을 같은 창에서 한다.** `package` 는 `REMEDY_TRUST_ANCHOR` 가 자기 환경에
> 있는지로 앵커 여부를 판단해 `README.txt` 의 **쓰는 법을 갈라 적는다** — 앵커가
> 있으면 *"실행 파일을 우클릭해 관리자 권한으로 실행"*, 없으면 *"관리자 터미널에서
> 명령으로"*. 창을 바꿔 붓으면 앵커가 박힌 바이너리에 "앵커가 없다" 는 README 가
> 붙고, 받는 사람은 더 쉬운 길을 쓰지 못한다.

나오는 모양은 이렇다. **플러그인이 자기 폴더에 있는 것이 중요하다** — 서명 검사는
그 폴더의 *모든* 파일이 매니페스트에 있기를 요구하므로(몰래 추가한 룰을 막는
장치다), `remedy.exe` 를 같은 폴더에 두면 꾸러미가 자기 검증에 실패한다.

```
remedy-evilai-locust-windows-x64\
  remedy.exe
  README.txt
  plugins\evilai-locust\
    plugin.yaml
    rules\evilai.yar
    MANIFEST
    MANIFEST.minisig
```

**여럿을 담으면 `plugins\` 아래가 여럿이 된다.** 폴더 이름은 `--plugin` 으로 준
원본 디렉터리의 이름을 그대로 쓴다 — `README.txt` 의 `run` 줄과 `plugin verify`
줄도 그 이름으로 하나씩 적힌다. 받는 사람이 실행 파일을 우클릭으로 띄우면 안내
모드가 *"여럿이면 고르게 한다"* 로 번호를 묻는다.
