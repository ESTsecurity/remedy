## 1.8.0 — 2026-11-12

- **리눅스의 PHP · Node.js 점검이 고친 뒤 다시 시작하지 않은 프로세스를 알립니다**(바꾸지 않고 알려만 드립니다) — 패키지를 올리면 옛 파일이 지워지고 새 파일이 들어서는데, 다시 시작하지 않은 php-fpm · 웹 서버 · Node.js 앱은 지워진 옛 파일을 실은 채 돕니다. 그 프로세스의 경로를 적어 *확인 필요*(종료 코드 6)로 알려 드립니다. 이전 버전은 디스크의 파일이 고친 버전이면 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.
- 리눅스에서 직접 빌드한 PHP 를 흔히 두는 `/usr/local/php` · `/opt/php` 도 봅니다 — 공식 빌드의 해시로 버전을 가리고, 가리지 못하면 *확인 필요* 로 알려 드립니다. 이전 버전은 그 자리의 PHP 가 실행 중이 아니면 보지 못했습니다.
- 점검 결과에서 프로세스 항목은 그 프로세스의 경로만 적습니다(실린 모듈 목록을 늘어놓지 않습니다).
- 다른 룰과 `remedy-net` 의 판정과 종료 코드는 1.7.0 과 같습니다.

## 1.7.0 — 2026-11-11

- **리눅스의 PHP · Node.js 점검이 패키지가 깐 실행 파일을 패키지 기록과 대조합니다**(바꾸지 않고 알려만 드립니다) — 패키지 버전은 그대로인데 실행 파일의 내용이 패키지 기록과 다르거나 기록이 없으면, 그 버전으로 판정하지 않고 경로를 적어 *확인 필요*(종료 코드 6)로 알려 드립니다. 이전 버전은 바뀐 실행 파일도 패키지 버전대로 *취약한 곳을 찾지 못했습니다* 로 끝났습니다. 대조하는 것은 PHP · Node.js 실행 파일 자리뿐이고, 같은 폴더의 다른 프로그램 파일은 결과에 들지 않습니다.
- Debian · Ubuntu 에서 `apt install php-cli` 처럼 메타패키지로 깐 PHP 가 고친 버전이면 *취약한 곳을 찾지 못했습니다* 로 끝납니다. 이전 버전은 메타패키지(`php-cli` · `php-fpm` 등)를 '기준 없는 PHP 패키지' 로 세어 *확인 필요* 였습니다.
- 점검 결과의 문구를 다듬었습니다 — 확인할 경로를 *위 경로* 로 가리키고(항목이 *주의* 줄보다 위에 있습니다), 확인할 고친 버전을 계열마다 적습니다(예: PHP 8.2 는 8.2.35, Node.js 22 는 22.23.4). 패키지 항목에는 버전을, 설정 항목에는 그 값을 적고 프로그램 안의 칸 이름(`manager` · `value`)은 적지 않습니다.
- 치료 계획의 설명이 정확해졌습니다 — 폴더 삭제도 격리소에 담아 두어 되돌릴 수 있고, 시작 프로그램 항목은 로그온할 때 실행되던 것이며, Windows 에서 재시작 뒤 자동 재검사는 관리자 계정으로 로그온했을 때 돕니다.
- 컨테이너 안에서 다른 사용자의 프로세스를 들여다보지 못했을 때의 *주의* 줄이 할 일(`docker exec --privileged` 로 들어가 다시 실행)만 적고, 거부된 경로 목록이 그 줄 바로 아래에 붙습니다.
- 다른 룰(EvilAI · CWPdoor · Ebury · 원격 점검)과 `remedy-net` 의 판정과 종료 코드는 1.6.0 과 같습니다. Windows 점검 룰 셋과 리눅스 세션 점검의 판정도 같고 문구만 바뀌었습니다.
- 바뀐 리눅스 PHP2Shell · Node2Shell 점검 룰은 프로그램 1.7.0 이상이 필요합니다. 룰만 옮기지 말고 받은 파일을 통째로 쓰십시오.

## 1.6.0 — 2026-11-11

- **PHP · Node.js 점검이 정해 둔 자리 밖에서 쓰이는 PHP · Node.js 도 알립니다**(바꾸지 않고 알려만 드립니다) — Windows 에서는 IIS 설정(`applicationHost.config`)이 쓰는 PHP 와 실행 중인 `php.exe` · `php-cgi.exe` · `node.exe`, 리눅스에서는 실행 중인 `php` · `php-fpm` · `node` 를 봅니다. 그 PHP · Node.js 는 판정하지 않고 경로를 적어 *확인 필요*(종료 코드 6)로 알려 드립니다. 이전 버전은 취약한 PHP 가 정해 둔 자리 밖에 있으면 IIS 가 그것을 써도 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.
- IIS 가 공유 설정을 쓰면 그 설정은 다른 자리에 있어 *확인 필요* 로 알립니다. *취약* 한 PHP · Node.js 가 나온 회차에는 자리 밖 항목이 나오지 않을 수 있고, 고친 뒤 다시 검사하면 나옵니다.
- 컨테이너 안에서 실행해 다른 사용자로 도는 프로세스를 들여다보지 못하면 *다 보지 못해 '취약하지 않다' 를 말할 수 없습니다*(종료 코드 6)로 끝나고, *주의* 줄이 `docker exec --privileged` 로 들어가 다시 실행하라고 안내합니다.
- 점검 결과의 *취약* 아래에는 그 판정의 근거만 적습니다 — 전에는 판정하지 않은 PHP 를 가리키는 IIS 설정 줄도 함께 섰습니다. 설정 파일에서 찾은 것은 그 자리의 값(예: IIS 가 쓰는 PHP 경로)을 적습니다.
- 다른 룰(EvilAI · CWPdoor · Ebury · 원격 점검)과 `remedy-net` 의 판정과 종료 코드는 1.5.0 과 같습니다.
- 바뀐 Windows 점검 룰은 프로그램 1.6.0 이상이 필요합니다. 룰만 옮기지 말고 받은 파일을 통째로 쓰십시오.

- 사용법은 README 의 *이미지 파일 · 컨테이너* 와 `remedy-net image --help` · `remedy-net container --help` 에 있습니다.
- `remedy` 의 메뉴 · 검사 · 치료와 룰(EvilAI · CWPdoor · Ebury · PHP · Node.js 점검 · 원격 점검)은 1.4.0 과 같고, 그 판정과 결과 · 종료 코드도 바뀌지 않았습니다.

- **네트워크를 쓰지 않으려면 받은 폴더의 `remedy-net` 폴더를 지우십시오** — 그 항목만 꺼지고 나머지는 그대로 씁니다.
- *모두 검사만 하기* 는 이 기계를 검사하는 항목만 돌립니다(화면의 항목 수도 그 수입니다). 원격 점검은 주소를 적어야 해서 들지 않습니다.
- 기존 룰(EvilAI · CWPdoor · Ebury · PHP · Node.js 점검)은 1.3.0 과 같고, 그 판정과 결과 · 종료 코드도 바뀌지 않았습니다.
