## 1.25.3 · 룰 2026.11.20.4 — 2026-11-21

### PHP 11월 보안 업데이트 점검

* **패키지 밖 PHP 실행 파일의 확인 필요 표시** (Linux)\
  RPM 계열의 PHP 자리(`/usr/bin/php` · `/usr/sbin/php-fpm` 등)에 어느 패키지도 깔지 않은 PHP 실행 파일이 있으면 그 경로를 적어 *확인 필요* 로 알립니다. 이전 버전은 RPM 의 PHP 패키지가 고친 버전이면 그 옆에 따로 놓은 파일이 있어도 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.
* **바뀐 PHP-FPM 실행 파일의 확인 필요 표시** (Linux)\
  Fedora 42 이후처럼 `/usr/bin/php-fpm` 을 패키지로 까는 배포판에서 그 파일이 패키지 기록과 다르면 패키지의 버전으로 판정하지 않고 *확인 필요* 로 알립니다. 이전 버전은 그 파일을 보지 않았습니다.

### PHP 세션 업로드 진행 설정 점검

* **패키지 밖 PHP 실행 파일의 확인 필요 표시** (Linux)\
  RPM 계열의 PHP 자리에 어느 패키지도 깔지 않은 PHP 실행 파일이 있으면 고친 버전으로 세지 않아 *확인 필요* 로 알립니다. 이전 버전은 RPM 의 PHP 패키지가 고친 버전이고 설정에서 직접 켜지 않았으면 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.
* **바뀐 PHP-FPM 실행 파일의 확인 필요 표시** (Linux)\
  Fedora 42 이후처럼 `/usr/bin/php-fpm` 을 패키지로 까는 배포판에서 그 파일이 패키지 기록과 다르면 고친 버전으로 세지 않고 *확인 필요* 로 알립니다. 이전 버전은 그 파일을 보지 않았습니다.

## 1.25.2 · 룰 2026.11.20.3 — 2026-11-20

### PHP 11월 보안 업데이트 점검

* **정식 출시 전 버전의 확인 필요 표시** (Linux)\
  패키지로 깔지 않은 PHP 의 버전이 시험판(`8.6.0RC7`)이나 개발 빌드(`8.6.0-dev`)이면 *확인 필요* 로 알립니다. 이전 버전은 `8.6.0RC7` 을 정식 8.6.0 으로 읽어 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.
* **버전을 읽지 못한 PHP 마다 확인 필요 표시** (Linux)\
  패키지로 깔지 않은 PHP 가 둘 이상이고 그 가운데 하나라도 버전을 읽지 못했으면 *확인 필요* 로 알립니다. 이전 버전은 버전을 읽은 다른 PHP 가 있으면 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.
* **Alpine 의 옛 PHP 패키지 이름 인식** (Linux)\
  지원이 끝난 Alpine(3.15 · 3.16)의 `php7` · `php8` 패키지(7.4 · 8.0)를 *취약* 으로 알립니다. 이전 버전은 이 이름의 버전을 보지 않아 *취약한 곳을 찾지 못했습니다* 로 끝났습니다.

### PHP 세션 업로드 진행 설정 점검

* **11월 보안 업데이트로 고친 PHP 인식**\
  2026-11-19 보안 업데이트(8.5.13 · 8.4.28 · 8.3.37 · 8.2.36)가 이 결함(CVE-2026-115560)도 고쳤습니다. 찾은 PHP 가 모두 그 계열의 고친 버전 이상이고 `session.upload_progress.enabled` 를 설정에서 직접 켜지 않았으면 *취약한 곳을 찾지 못했습니다* 로 끝납니다. 이전 버전은 PHP 가 있으면 늘 *확인 필요* 로 알렸습니다.
* **직접 켠 설정의 안내**\
  고친 버전이어도 설정에서 직접 켰다면 *확인 필요* 로 남고, 같은 세션을 쓰는 앱 · 풀 · 가상 호스트 · CLI 의 `session.serialize_handler` 를 같게 맞추도록 안내합니다. 고친 버전도 설정끼리 다른 직렬화기는 막지 않습니다. 켠 설정은 `php.ini` 꼴 외에 PHP-FPM 풀(`php_admin_flag[…]`)과 Apache 설정(`php_admin_flag …`)에서도 찾습니다.

<details>
<summary><b>알아두실 점 및 자세한 내용 보기</b></summary>

* 버전은 PHP 11월 보안 업데이트 점검과 같은 규칙으로 봅니다 — 배포판 패키지는 상류 버전으로 보므로, 배포판이 고친 코드를 버전 번호를 그대로 두고 넣은 패키지는 아직 *확인 필요* 입니다. 버전을 확인하지 못한 PHP(정식 출시 전 버전 · 보는 자리 밖을 가리키는 링크만 있는 PHP 등)도 *확인 필요* 입니다.

- **다른 계정으로 치료해도 남지 않습니다** — 담당자의 관리자 계정이나 배포 도구(SYSTEM)로 치료할 때, 로그온해 있는 감염 사용자의 시작 프로그램 항목까지 지웁니다. 이전 버전은 그 항목을 남긴 채 *치료 완료* 로 끝났습니다.
- **Ebury** — ESET 가 공개한 점검 방법인, 돌고 있는 백도어가 여는 **창구**(이름 24개)도 봅니다. 가짜 라이브러리의 파일 이름이 알려지지 않은 경우에도 그 sshd 가 떠 있으면 찾습니다.
- 룰이 요구하는 프로그램 버전을 검사 전에 확인합니다. 더 새 프로그램이 필요한 룰이면 시작하지 않고 그 까닭을 알려 드립니다(종료 코드 4). 이전 버전은 확인하지 않고 그대로 돌렸습니다.
- 이 버전의 룰(`evilai-locust` 0.2.0 · `ebury-check` 0.2.0)은 프로그램 1.2.0 이상이 필요합니다. 1.1.3 이하 프로그램은 이를 확인하지 않으므로, 룰만 옮기지 말고 받은 파일을 통째로 쓰십시오.
