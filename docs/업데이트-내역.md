# 업데이트 내역

버전마다 **이전 버전과 달라진 점**입니다. 최신 버전이 맨 위에 있습니다.

## 룰 2026.11.18 · 프로그램 1.23.0 — 2026-11-18

- **Java4Shell(CVE-2026-114938) 점검을 더했습니다** — 이 기계에 깔린 자바 런타임(JDK · JRE)의 버전이 영향을 받는 버전인지 봅니다. 2026-11-17 에 나온 **고친 버전(17.0.21.1 · 21.0.13.1 · 25.0.5.1 · 27.0.1.1)보다 낮으면 취약**, 그 버전 이상이면 해당 없음입니다. Java 8 과 11 은 해당하지 않고(공지의 표), 지원이 끝난 버전(18 ~ 20 · 22 ~ 24 · 26)은 고친 버전이 나오지 않으므로 취약으로 적습니다. ARM 빌드와 32비트 빌드는 해당 없음입니다 — 빌드 종류가 적혀 있지 않은 런타임(프로그램이 담아 쓰는 자바)은 버전으로 판정합니다.
- **버전을 올린 뒤 다시 시작하지 않은 자바도 알려 드립니다**(리눅스) — 올려도 다시 시작하지 않으면 그 프로그램은 고치기 전 코드로 계속 돕니다. 이 경우와, 이 점검이 보는 자리 밖에서 돌고 있는 자바는 *확인 필요* 로 경로를 적습니다.
- 자세한 안내는 [위협별 안내의 Java 절](위협별-안내.md#java--자바-런타임-점검만-합니다)에 있습니다. 프로그램은 1.23.0 과 같습니다 — 바뀐 것은 룰뿐입니다.

## 1.23.0 · 룰 2026.11.16 — 2026-11-18

- **폐기한 룰로는 검사 · 치료하지 않습니다** — 반입한 폐기 목록(`remedy revocation import`)이 겨누는 룰 버전으로 검사 · 치료 · 유지 확인을 하면 시작하지 않고 폐기 사유와 함께 종료 코드 5 로 끝납니다(이전 버전은 `plugin verify` 만 그 목록을 봤습니다). 메뉴는 실행 파일 옆 `state` 와 기본 상태 폴더의 목록을 함께 봅니다. 목록이 없으면 전과 같습니다 — 아직 발행한 폐기 목록은 없습니다.
- **명령줄 오타로 치료 · 복원 · 반입이 시작되지 않습니다** — 값이 빠진 옵션(`--extract-to --yes` 등), 스위치 뒤의 낱말(`--yes false`), 값이 빠진 `--lang`(`--lang --dry-run`)을 이제 실행하지 않고 종료 코드 4 로 끝냅니다. 이전 버전은 이것들을 다르게 읽어 실제로 치료 · 복원했습니다. `plugin verify` · `revocation` · `allowlist` · `support-bundle` 도 모르는 옵션을 거절하고, `remedy-net url` 은 `image` · `container` 와 같은 규칙으로 읽습니다. 문서에 적힌 꼴(`--이름 값`)은 전과 같습니다.
- **리눅스에서 UTF-8 이 아닌 이름의 경로를 넘겨도 멈추지 않습니다** — 이전 버전은 그 자리에서 비정상 종료(종료 코드 134)했습니다. 이제 어느 인자인지 알리고 종료 코드 4 로 끝냅니다. 실행 파일이 그런 이름의 폴더에 있어도 검사 · 치료가 끝까지 갑니다.
- **Debian · Ubuntu 패키지 버전을 dpkg 와 똑같이 견줍니다** — 이전 버전은 한 자리에서 숫자와 글자가 만나는 경우(`1.1` 대 `1.a`)를 dpkg 와 반대로 읽었습니다. 진짜 dpkg · rpm · apk 의 답 1,211 짝과 견줘 모두 같습니다.
- 룰은 1.22.0 과 같습니다(룰 2026.11.16) — 판정과 종료 코드가 바뀐 룰은 없습니다.

## 1.22.0 · 룰 2026.11.16 — 2026-11-17

- **메뉴 화면을 간결하게 다듬었습니다** — 첫 화면은 경고 대신 제품 · 버전 · 권한으로 시작하고, 코드서명 알림은 그 아래 한 줄입니다. 빠른 · 정밀 검사는 항목마다 되풀이하던 배너(구분선 · 시각 · 기계)를 빼고 `[1/5] 이름` 머리만 세웁니다 — 시각과 기계는 회차 기록에 그대로 남습니다. 치료 끝은 표 대신 `결과 — … · 걸린 시간` 한 줄이고, 되돌리기 · 신고는 바로 아래 *다음 할 일* 이 메뉴 번호로 가리킵니다. 명령줄의 결과 표 · 배너 · 종료 코드 · 결과 파일은 전과 같습니다.
- **관리자 권한 없이 열리면 다시 열기를 권합니다** — Windows 에서 `remedy.exe` 를 더블클릭하면 관리자 권한 없이 뜹니다. 이제 첫 화면이 **1. 관리자 권한으로 다시 열기** 를 권하고, 고르면 사용자 계정 컨트롤 창을 거쳐 같은 폴더에서 관리자 권한으로 다시 엽니다.
- **고른 항목의 메뉴에서 0 은 뒤로 갑니다** — 검사 항목을 고르는 화면으로 돌아갑니다(이전 버전은 프로그램이 끝났습니다). 끝내기는 고르는 화면의 0 입니다.
- **잘못 친 번호로 끝나지 않습니다** — 번호를 치는 화면에서 없는 번호나 글자를 치면 범위를 알려 드리고 다시 묻습니다. *더 보기* 머리줄을 줄여 80칸 창에서도 방향키로 고릅니다.
- **다음 할 일을 빠짐없이** — 먼저 고를 항목을 한 번만 적고 그 아래에 메뉴 줄을 적습니다(이전: 줄마다 `3. EvilAI(Locust) 제거 → 4. …`). 복원한 뒤에는 *오탐을 신고하려면* 이 먼저이고, 이어서 한 치료 뒤에도 유지 확인 · 복원 · 신고를 가리킵니다(이전: 비어 있었습니다). 신고 묶음을 만든 뒤에는 보낼 곳(이 도구를 나눠 준 담당자 · GitHub 에서 받았다면 `security@estsecurity.com`)을 적습니다. 쓸 검사 항목이 없으면 최신 버전을 다시 받으라고 알려 드립니다.
- **화면의 말을 고쳤습니다** — 검사 전 첫 화면은 *무엇을 검사할까요? (검사 항목 N개)* · 검사 줄은 '룰' 대신 '항목' · 계획 머리는 `N건을 수행합니다`(이전: `N 건`)이고 검사만 하는 화면 · `scan` · `--dry-run` 에서는 *치료하면 N건을 수행합니다 (지금은 바꾸지 않습니다)* · 승인 질문은 두 줄 · 회차를 고르는 물음은 하는 일마다(*어느 치료를 되돌릴까요?* 등)입니다. 하나도 바꾸지 못한 치료는 *일부 실패 (0건 수행 완료)* 대신 *치료하지 못했습니다 (바꾼 것 없음)* 입니다(종료 코드 3 은 같습니다). 치료 직후 다시 검사가 방금 격리한 파일을 *'…' 가 없습니다* 로 적습니다. 관리자 권한 없음 오류는 까닭 한 줄과 하는 법만(이전: 권한과 상관없는 까닭까지 일곱 줄) · 신고 묶음의 설명과 이동식 매체 확인 질문은 합쇼체입니다. 압축 파일을 연 채 실행하면 안내 한 줄만 보입니다(이전: 명령줄 사용법 20줄이 이어졌습니다). 리눅스 SSH 에서 끝날 때는 *끝내려면 Enter* 입니다(이전: 닫을 창이 없는데 *이 창을 닫으려면*).
- **명령줄에서 모르는 옵션을 거절합니다** — 이전 버전은 모르는 옵션을 조용히 넘겨, `run --plugin … --dryrun --yes` 처럼 `--dry-run` 을 잘못 치면 실제로 치료했습니다. 이제 실행하지 않고 *모르는 옵션입니다* 와 함께 종료 코드 4 로 끝납니다. 옵션은 `remedy --help-all` 에 있습니다.
- 룰 작성자: 작성 안내의 생성 문서(`docs/plugin-guide/machine/`)가 capture 함수 `expand_env` 를 쓸 수 있는 것처럼 적었는데, 평가기는 늘 거절합니다. 이제 문서와 평가 오류가 *평가하지 않는다* 고 적습니다(이전 오류는 이미 지난 개발 단계에 쓸 수 있게 된다고 했습니다).
- 룰은 1.21.0 과 같습니다(룰 2026.11.16) — 판정과 종료 코드가 바뀐 룰은 없습니다.

## 1.21.1 · 룰 2026.11.16 — 2026-11-17

- **화면 출력을 받는 쪽이 먼저 끝나도 검사 · 치료를 끝까지 합니다** — `remedy … | head` 처럼 화면 출력을 넘겨받는 프로그램이 먼저 끝나면, 이전 버전은 그 뒤 화면에 한 줄을 쓰는 순간 *내부 오류*(종료 코드 7)로 멈췄습니다. 치료 중이었다면 일부만 한 채였습니다(예: 서비스는 멈췄는데 파일은 격리하지 않음). 이제 화면 출력만 멈추고 검사 · 치료는 끝까지 하며, 종료 코드는 그 작업의 것입니다. 화면에 나가지 못한 줄은 회차 로그(상태 폴더의 `logs`)에 남기고, 그 로그에 화면이 끊긴 까닭을 한 줄 적습니다.
- 첫 줄만 읽는 `remedy --version | head -1` 도 이제 0 으로 끝납니다 — 이전 버전(1.21.0)은 30번 중 20번 *내부 오류*(7)로 끝나며 크래시 기록을 남겼습니다.
- `remedy-net` 도 같습니다 — 이전 버전은 같은 경우 종료 코드 표에 없는 값으로 갑자기 끝났습니다.
- 룰은 1.21.0 과 같습니다(룰 2026.11.16) — 판정과 종료 코드가 바뀐 룰은 없습니다.

## 1.21.0 · 룰 2026.11.16 — 2026-11-17

- **빠른 검사와 정밀 검사로 나눴습니다** — 받은 폴더에 디스크 전체를 뒤지는 항목(*Log4j 점검*)과 다른 항목이 함께 들어 있으면, 고르는 화면 맨 위가 **1. 빠른 검사**(권장 · 디스크 전체를 뒤지는 항목만 빼고 모두)와 **2. 정밀 검사**(전부 · 오래 걸릴 수 있습니다)이고 항목은 3번부터입니다. 빠른 검사의 결과는 뺀 항목을 *정밀 검사에서만 합니다* 로 적고, *다음 할 일* 이 2번을 가리킵니다. 그런 항목이 없는 폴더는 전처럼 *N개 모두 검사만 하기* 한 줄입니다. *찾은 것 모두 치료하기* 는 두 검사 뒤 모두 섭니다.
- **같은 제품의 취약점을 모아 올리면 해결되는 버전을 적습니다** — 검사 결과 밑의 *제품마다 — 올리면 해결되는 버전* 이 같은 제품(예: PHP)에서 찾은 취약점을 모아, 몇 버전 이상으로 올리면 어느 항목이 해결되는지 한 번 적습니다. 같은 설치본에서 여러 항목이 취약하면 가장 높은 버전 하나로 모두 풀린다고 적고, 버전으로 판정하지 않는 항목(설정)은 그 밑에 따로 적습니다 — 올려도 남을 수 있습니다. 판정과 종료 코드는 항목마다 전과 같습니다.
- **리눅스에서 디스크 전체 검사가 같은 자리를 두 번 걷지 않습니다** — 같은 디스크를 다른 자리에 다시 붙인 마운트(Docker Desktop · WSLg 등)는 한 번만 걷습니다. WSL 에서 걷는 자리가 2,761곳 → 4곳으로 줄고, 같은 파일을 두 경로로 내던 일이 없어졌습니다.
- 룰 2026.11.16 — 점검 룰 열(PHP 넷 · Node.js 둘 · Apache 둘 · Log4j · OpenSSH)에 같은 제품을 묶는 열쇠(`product`)를 적었습니다. 판정과 종료 코드가 바뀐 룰은 없고, 이 룰들은 프로그램 1.21.0 이 필요합니다.
- 룰 작성자: 매니페스트에 선택 칸 `product` 가 생겼습니다(점검 룰만 · 없으면 `plugin lint` 경고). 작성 안내(`docs/plugin-guide/24-check-plugins.md`)에 같은 제품에 새 CVE 가 나왔을 때의 규칙을 적었습니다 — 판정이 같은 꼴이면 갱신도 새 룰도 되고, 다른 꼴이면 새 룰이며, 대체 관계는 적지 않습니다.

## 1.20.0 · 룰 2026.11.15 — 2026-11-16

- **모두 검사한 뒤 찾은 것을 한 번에 치료합니다** — 메뉴의 *모두 검사만 하기* 가 치료할 수 있는 항목에서 무엇을 찾으면, 고르는 화면의 항목 목록 뒤에 *찾은 것 모두 치료하기* 가 섭니다. 고르면 찾은 항목마다 다시 검사해 바꿀 것을 모두 보여 드리고, **한 번 승인**하시면 항목마다 치료한 뒤 다시 검사해 결과를 한 화면에 적습니다. 되돌리기는 전처럼 항목마다입니다(메뉴의 *치료 전으로 복원하기* · `restore`). 취약점 점검 항목이 찾은 것은 바꾸지 않고 할 일만 알려 드립니다.
- **모두 검사만 하기는 찾은 것이 있는 항목의 결과 파일만 남깁니다** — 찾은 것이 없거나 해당 없는 항목은 결과 폴더를 만들지 않고, 그 항목의 화면에 *결과 폴더* 줄도 적지 않습니다(룰이 많을 때 한 번에 수백 MB 가 쌓였습니다). 명령줄 `scan` 과 메뉴의 *검사만 하기* 는 전과 같습니다.
- **항목이 많으면(20개 넘게) 고르는 화면을 묶어 보여 드립니다** — 하는 일 묶음(악성코드 탐지 · 제거 · 취약점 점검 · 원격 점검)과 *이름 · 제품 · CVE 로 찾기* 로 고르고, *모두 검사만 하기* 는 항목마다 한 줄로 진행을 알린 뒤 찾은 것만 줄로 요약합니다. 지금 배포 파일은 항목이 20개보다 적어 화면이 그대로입니다.
- **버전을 둘로 나눴습니다** — 프로그램 버전(1.20.0)과 룰 버전(날짜 · 2026.11.15)입니다. 화면 맨 위 첫 줄(`ESTsecurity 전용백신 1.20.0 · 룰 2026.11.15`) · `--version` 의 둘째 줄 · 받은 폴더의 `README.txt` 에 둘을 함께 적습니다. 앞으로 룰만 더하거나 고친 버전은 프로그램 버전이 그대로이고 룰 버전만 오릅니다(릴리스 이름 `룰 <날짜> · 프로그램 <버전>`).

- **다른 계정으로 치료해도 남지 않습니다** — 담당자의 관리자 계정이나 배포 도구(SYSTEM)로 치료할 때, 로그온해 있는 감염 사용자의 시작 프로그램 항목까지 지웁니다. 이전 버전은 그 항목을 남긴 채 *치료 완료* 로 끝났습니다.
- **Ebury** — ESET 가 공개한 점검 방법인, 돌고 있는 백도어가 여는 **창구**(이름 24개)도 봅니다. 가짜 라이브러리의 파일 이름이 알려지지 않은 경우에도 그 sshd 가 떠 있으면 찾습니다.
- 룰이 요구하는 프로그램 버전을 검사 전에 확인합니다. 더 새 프로그램이 필요한 룰이면 시작하지 않고 그 까닭을 알려 드립니다(종료 코드 4). 이전 버전은 확인하지 않고 그대로 돌렸습니다.
- 이 버전의 룰(`evilai-locust` 0.2.0 · `ebury-check` 0.2.0)은 프로그램 1.2.0 이상이 필요합니다. 1.1.3 이하 프로그램은 이를 확인하지 않으므로, 룰만 옮기지 말고 받은 파일을 통째로 쓰십시오.
