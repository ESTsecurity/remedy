# 업데이트 내역

버전마다 **이전 버전과 달라진 점**입니다. 최신 버전이 맨 위에 있습니다.

새 버전은 [최신 버전](https://github.com/ESTsecurity/remedy/releases/latest)에서 받습니다. 설치하지 않는 프로그램이라 새로 받은 폴더를 그대로 쓰시면 됩니다 — 각 릴리스 페이지의 맨 위에도 같은 내용이 있습니다.

## 1.3.0 — 2026-11-10

- **취약점 점검을 더했습니다**(바꾸지 않고 알려만 드립니다) — **PHP2Shell**(CVE-2026-109618 · 109619) · **PHP 세션 업로드 진행 설정**(CVE-2026-115560) · **Node2Shell**(CVE-2026-111497 — Node.js 와 PHP for Windows 의 Brotli). Windows 와 리눅스 파일에 각각 들어 있습니다.
- 점검 결과에 **확인 필요**가 생겼습니다 — 버전 · 공식 빌드 · 배포판 공지로 판정할 근거가 없는 설치본은 '취약하지 않다' 로 넘기지 않고, 무엇을 확인할지 함께 적습니다(종료 코드 6).
- **Windows 파일에도 검사 항목이 넷이라** 처음에 무엇을 볼지 묻습니다. 1번 *4개 모두 검사만 하기* 는 아무것도 바꾸지 않고, EvilAI(Locust) 치료는 그 항목을 고른 뒤 *1. 검사하고 치료하기* 로 합니다.
- 리눅스에서 **RPM 패키지 목록**(RHEL · Oracle Linux · Rocky · CentOS · SLES 등)을 읽습니다 — 이전 버전은 dpkg · apk 만 읽었습니다.
- 기존 룰(EvilAI · CWPdoor · Ebury)은 1.2.1 과 같고, 그 판정과 결과도 바뀌지 않았습니다.
- 새 점검 룰은 프로그램 1.3.0 이상이 필요합니다. 룰만 옮기지 말고 받은 파일을 통째로 쓰십시오.

## 1.2.1 — 2026-11-09

- **처음 메뉴가 짧아졌습니다** — 치료한 적이 없는 PC 에서는 *검사하고 치료하기 · 검사만 하기 · 더 보기 · 그만두기* 만 보입니다. 이전 버전은 14줄을 늘 보였고, 그 가운데 다섯 줄이 *치료한 기록이 없습니다* 를 달고 흐리게 섰습니다.
- *치료 전으로 복원하기 · 치료가 유지됐는지 다시 보기 · 신고에 붙일 것 모으기* 는 치료한 기록이 있을 때, *중단된 작업 이어서 하기* 는 치료가 중간에 끊겼을 때만 나타납니다. 치료한 뒤 화면의 *다음 할 일* 이 그 번호를 알려 드립니다.
- 프로그램 자체 점검 · 버전 · 명령줄 사용법 · 룰 검사 · 룰 서명 확인과 운영자 명령은 **더 보기** 에 모았습니다.
- 찾기만 하는 항목(리눅스의 CWPdoor 점검 · Ebury 점검)을 고르면 치료 줄 없이 *1. 검사만 하기* 가 맨 위에 섭니다.
- 검사 · 치료의 판정과 결과, 명령줄로 실행할 때의 출력과 종료 코드는 바뀌지 않았습니다. 룰도 1.2.0 과 같습니다.

## 1.2.0 — 2026-11-08

- **EvilAI(Locust)** — 공개 보고(Trend Micro)가 적은 변종도 찾아 치료합니다. 페이로드가 임시 폴더(`TEMP`) 바로 아래에 있거나, 예약 작업이 다른 폴더에 등록됐거나, `cmd.exe` 를 거쳐 실행되는 경우입니다. 이전 버전은 이 셋 가운데 하나만 달라도 *위협이 발견되지 않았습니다* 로 끝났습니다.
- **EvilAI(Locust)** — 그 보고가 이름을 밝힌 시작 메뉴 바로 가기와 시작 프로그램 항목도 감염이 확인된 PC 에서 함께 격리합니다(되돌릴 수 있습니다). 가짜 앱 자체는 *설정 → 앱* 에서 제거하십시오 — README 의 EvilAI 안내에 보고가 밝힌 이름과 서명자가 있습니다.
- **다른 계정으로 치료해도 남지 않습니다** — 담당자의 관리자 계정이나 배포 도구(SYSTEM)로 치료할 때, 로그온해 있는 감염 사용자의 시작 프로그램 항목까지 지웁니다. 이전 버전은 그 항목을 남긴 채 *치료 완료* 로 끝났습니다.
- **Ebury** — ESET 가 공개한 점검 방법인, 돌고 있는 백도어가 여는 **창구**(이름 24개)도 봅니다. 가짜 라이브러리의 파일 이름이 알려지지 않은 경우에도 그 sshd 가 떠 있으면 찾습니다.
- 룰이 요구하는 프로그램 버전을 검사 전에 확인합니다. 더 새 프로그램이 필요한 룰이면 시작하지 않고 그 까닭을 알려 드립니다(종료 코드 4). 이전 버전은 확인하지 않고 그대로 돌렸습니다.
- 이 버전의 룰(`evilai-locust` 0.2.0 · `ebury-check` 0.2.0)은 프로그램 1.2.0 이상이 필요합니다. 1.1.3 이하 프로그램은 이를 확인하지 않으므로, 룰만 옮기지 말고 받은 파일을 통째로 쓰십시오.

## 1.1.3 — 2026-11-08

- **Ebury** — ESET 가 적은 설치 방법 가운데 이름이 알려진 파일과 자리(`tls/` 아래 포함)를 모두 봅니다. 이전 버전은 그 가운데 한 가지만 봤습니다.
- 검사가 깨끗하게 끝나도 메뉴 화면이 그 항목이 무엇을 보았는지 한 줄로 알려 드립니다 — *위협 없음* 이 *이 기계가 깨끗하다* 는 뜻은 아닙니다.
- 위협별 안내에 공개 보고의 확인 절차를 더했습니다 — CWPdoor 는 최신 버전으로 올리기와 소켓 확인, Ebury 는 ESET 점검 스크립트.

## 1.1.2 — 2026-11-08

- **EvilAI(Locust)** — 이 PC 의 모든 사용자 계정을 검사합니다. 이전 버전은 담당자가 자기 관리자 계정으로 실행하면 감염된 사용자의 것을 보지 못해 *위협 없음* 으로 끝났습니다.
- 메뉴 화면의 다음 할 일 · 찾은 것 · 권한이 없을 때의 까닭을 고쳤습니다. 명령으로 부른 출력은 그대로입니다.
- README · 운영자 가이드 · 받은 폴더의 안내문 · 릴리스 본문을 처음 쓰는 사람의 실측에 맞췄습니다.
