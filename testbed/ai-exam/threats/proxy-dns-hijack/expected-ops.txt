# 감염 스냅샷에서 반드시 나와야 하는 Op (채점 4번).
#
# 형식은 `appinit-implant/expected-ops.txt` 의 머리를 볼 것 — (Op, 대상) 이고
# `::` 뒤는 match 다.
#
# **이 목록은 정답 플러그인의 계획을 그대로 옮긴 것**이고(2026-09-21, 랩 VM
# 스냅샷 위에서 `evaluate` → `plan`), 사람이 한 줄씩 위협 설명과 맞춰 읽었다.
#
# # `hosts` 를 Windows 에서 처음 밟는다
#
# 리눅스 쪽 `tls-intercept` 가 `/etc/hosts` 를 밟고 있었지만 Windows 재료에는
# 그 자리가 없었다. 그래서 **채점기도 `line=` 매치를 볼 줄 몰랐다** — 같은
# 것을 재는 두 하네스가 비대칭이었고, 2026-09-21 에 Windows 쪽
# (`Invoke-ExamApply.ps1`)에 그 검사를 더했다.
#
# 아래 두 줄의 `line=` 안에는 **탭**이 들어 있다. 실기기의 hosts 가 쓰는
# 것이고, 계획기가 줄을 재구성하면 여기서 어긋난다.
#
# # 조직이 넣은 줄은 여기 없다
#
# `192.168.10.14	buildserver …` 한 줄이 같은 파일에 있고 **남아야 한다.**
# 채점기가 "지목한 줄만 빠지고 나머지는 그대로인가" 로 재므로, 그 줄이 함께
# 사라지면 여기서 걸린다. 파일을 통째로 치우는 답안도 마찬가지다.
#
# # `ProxyEnable` 은 여기 없다 — 그것이 설계다
#
# 검체가 켜짐 플래그도 1 로 바꿨지만 계획에 나오지 않는다. `derive.rs` 의
# `proxy_targets` 가 적는다: *"켜짐 플래그를 0 으로 쓰는 것은 카탈로그 밖의
# 임의 값 쓰기이고, 서버·PAC 가 사라지면 가로채기는 이미 멈춘다."*
# 그 자리는 `must-remain.txt` 로 갔다 — 건드리면 부수 피해다.

autorun.remove HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\NetOptimizer
file.quarantine_only C:\ProgramData\NetOpt\netopt.exe
hosts.restore_line C:\Windows\System32\drivers\etc\hosts :: line_no=23, line=10.20.30.40	update.microsoft.com
hosts.restore_line C:\Windows\System32\drivers\etc\hosts :: line_no=24, line=10.20.30.40	login.bank-example.co.kr
proxy.restore HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ProxyServer
