## 관측 보고 — 서비스로 등록되어 부팅마다 살아나는 채굴기

감염된 Debian 계열 기계를 확보해 다음을 관측했다.

### 지속성 — 시스템 서비스 정의

시스템 서비스 정의 폴더 `/etc/systemd/system/` 에 정의 하나가 등록돼 있다.

```
/etc/systemd/system/sys-metrics.service         ← 검체가 만들었다  (226 B)
  표시 이름   System metrics collector
  실행       /usr/local/lib/.metrics/xmrig --config /usr/local/lib/.metrics/config.json
  다시 시작   언제나 (죽이면 곧바로 살아난다)
  등록 상태   부팅 시 시작하도록 등록되어 있지 않다
```

이름(`sys-metrics`)과 표시 이름(*"System metrics collector"*)은 시스템 구성
요소처럼 지었다. **이름과 자리로는 가릴 수 없다** — 아래 정상 정의와 같은
폴더에 같은 틀로 들어 있다.

같은 폴더에 정상 서비스 정의가 하나 더 있다. **손대면 안 된다.**

```
/etc/systemd/system/vendor-agent.service        ← 정상. 남아야 한다  (180 B)
  표시 이름   Vendor agent
  실행       /usr/local/lib/vendor/agent --daemon
  다시 시작   실패했을 때만
  등록 상태   부팅 시 시작하도록 등록되어 있지 않다
```

배포가 심어 둔 기본 서비스 정의도 **열둘** 함께 관측됐다(`apt-daily` ·
`e2scrub` 계열 · `fstrim` · `gpg-agent` · `ssh-agent` 등). 그것들은
`/lib/systemd/system` 과 `/usr/lib/systemd/user` 에 있다. **전부 남아야 한다.**

### 페이로드 — 숨김 이름의 폴더

```
/usr/local/lib/.metrics/xmrig                   ← 검체  (204,800 B)
/usr/local/lib/.metrics/config.json             ← 검체  (1,024 B)
```

폴더 이름이 점으로 시작해 목록에서 눈에 띄지 않는다. 위의 서비스 정의가
실행하는 것이 바로 이 둘이다.

같은 상위 폴더(`/usr/local/lib`)에 정상 실행 파일이 있다. **손대면 안 된다.**

```
/usr/local/lib/vendor/agent                     ← 정상. 남아야 한다  (40,960 B)
```

### 이 기계가 하고 있던 일

`config.json` 에 채굴 풀 주소와 지갑이 들어 있고, 서비스가 *"언제나 다시
시작"* 으로 등록되어 있어 프로세스를 죽여도 곧바로 살아난다. CPU 가 상시
점유되어 사용자는 *"컴퓨터가 느려졌다"* 로만 인지한다.

## 요구 사항

1. **부팅마다 살아나는 자리를 없앤다.** 서비스 정의가 남아 있으면 페이로드를
   지워도 다음 부팅에서 실행이 시도된다.
2. **페이로드 둘을 되돌릴 수 있게 치운다.** 오탐이었을 때 되돌릴 수 없으면 안
   된다.
3. **정상 서비스 정의와 그 실행 파일은 그대로 둔다.** 같은 폴더에 있다는
   사실은 악성의 근거가 아니다.
4. 배포 기본 서비스 정의 열둘도 그대로 둔다.

## 이 위협이 재는 것

- **무엇으로 가르는가.** 자리(`/etc/systemd/system`)로 가르면 정상 정의가
  함께 걸린다. 이름의 그럴듯함으로도 가를 수 없다 — 둘 다 그럴듯하다.
  갈라지는 지점은 **그 정의가 무엇을 실행하는가** 하나다.
- **리눅스에 없는 동작을 요구했을 때 화면이 무엇을 말하는가.** 서비스를
  없애는 데 필요한 동작 중 둘은 리눅스에 개념이 없다. 그 경우 이 프로그램은
  조용히 넘어가지 않고 *"이 계획은 치료의 전부가 아니다"* 라고 적는다.
