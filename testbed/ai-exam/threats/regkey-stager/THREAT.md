# 지정 위협 설명 — 설정 자리에 경로를 감춰 두고 로그온마다 띄운다

**출제자 주의 — 다섯.**

1. 아래 본문에 매니페스트 필드명·연산자 이름이 **한 개도 없다.**
2. 본문의 값은 `infected/regkey-stager.json` 에서 실측해 썼다. **문제와 채점
   데이터가 갈라지면 응시자는 도달할 수 없다.**
3. **이 스냅샷은 랩 VM 에서 떴다** (2026-09-21). 아래 감염 상태를 실제로
   세우고 수집을 돌린 것이다
   (`testbed/harness/host/New-ThreatSnapshot.ps1 -Threat regkey-stager`).
   **실검체는 없다** — 두 파일 모두 크기만 맞춘 무해한 자리 채우기다.
4. **검체가 만든 설정 자리 자체는 치료 대상이 아니다.** 이 도구는 그 자리를
   통째로 지우지 못한다 — 까닭은 아래 '치료 범위 밖' 에 적었다.
5. **경로가 감춰져 있다는 사실은 악성의 근거가 아니다.** 옆의 정상 제품도
   같은 방식으로 적는다.

## 관측 보고 — 설정 자리 둘이 닮았고, 하나만 검체다

감염된 Windows 10 기계를 확보해 다음을 관측했다.

### 사용자 설정 자리에 새 자리가 하나 생겼다

`HKCU\Software` 아래 이름이 닮은 자리가 둘 있다.

```
HKCU\Software\NetSyncAgent          <- 검체가 만들었다. 청정 기계에는 없던 자리다
  Payload      QzpcUHJvZ3JhbURhdGFcTmV0U3luY0FnZW50XG5ldHN5bmMuZGxs
  Stub         "C:\ProgramData\NetSyncAgent\stub.exe"

HKCU\Software\NetSync               <- 정상 제품. 남아야 한다
  Token        Y2hhbm5lbD1zdGFibGU7YnVpbGQ9MjAyNi45
  InstallDir   "C:\ProgramData\NetSync"
```

**둘 다 한쪽은 base64 로, 한쪽은 따옴표로 적었다.** 모양만으로는 가를 수
없다. 풀어 보면 갈린다 —

```
QzpcUHJvZ3JhbURhdGFcTmV0U3luY0FnZW50XG5ldHN5bmMuZGxs
   -> C:\ProgramData\NetSyncAgent\netsync.dll      (실제로 있는 파일)

Y2hhbm5lbD1zdGFibGU7YnVpbGQ9MjAyNi45
   -> channel=stable;build=2026.9                  (경로가 아니다)
```

### 파일 셋 — 둘은 검체의 것이고 하나는 정상이다

```
C:\ProgramData\NetSyncAgent\netsync.dll      <- 검체  (188,416 B)
C:\ProgramData\NetSyncAgent\stub.exe         <- 검체  (271,360 B)
```

```
C:\ProgramData\NetSync\netsync.exe           <- 정상. 남아야 한다  (412,672 B)
```

폴더 이름도 앞부분이 같다 — `NetSyncAgent` 와 `NetSync`.

### 다시 뜨게 하는 자리

로그온할 때 실행되는 항목 **열일곱** 중 하나가 검체의 것이다.

```
NetSyncAgent    "C:\ProgramData\NetSyncAgent\stub.exe" -k netsvc
```

나머지 열여섯은 이 기계에 설치된 정상 소프트웨어의 것이다(보안 제품 ·
브라우저 · VPN 클라이언트 · 전자서명 도구 등). **전부 남아야 한다.**

### 이 기계가 하고 있던 일

로그온할 때마다 위의 항목이 `stub.exe` 를 띄우고, 그것이 검체가 만든 설정
자리에서 감춰진 경로를 읽어 `netsync.dll` 을 싣는다. **설정 자리를 남기면
파일을 치워도 다음 검체가 파일만 다시 놓고 그대로 쓴다.**

## 치료 범위 밖 — 설정 자리 자체는 지우지 못한다

이 도구는 설정 자리를 **통째로** 지우지 않는다. 지울 수 있는 것은 그 안의
값 하나하나다. 자리를 통째로 지우는 것은 그 아래 전부를 지우는 일이고, 그
자리가 읽기 상한으로 선언된 곳이면 상한 자체를 지우는 것이 되어 안전 장치가
거부한다.

그래서 치료가 끝나도 **값이 없는 빈 자리가 남는다.** 그 자리는 아무것도
하지 않는다 — 읽을 값이 없기 때문이다. 이것을 없애려는 계획은 할 수 없는
일을 하겠다고 말하는 것이다.

## 요구 사항

1. **감춰진 경로를 풀어 파일 둘을 되돌릴 수 있게 치운다.** 자리를 리터럴로
   적어 맞히지 말 것 — 같은 검체가 다른 폴더를 쓰면 아무것도 찾지 못한다.
2. **검체가 만든 설정 값 둘을 지운다.** 값 단위다(위의 '치료 범위 밖').
3. **다시 뜨게 하는 자리를 없앤다.** 남으면 로그온마다 다시 돈다.
4. **정상 제품의 설정 값 둘과 파일, 정상 자동 실행 항목 열여섯은 그대로
   둔다.**

## 이 위협이 재는 것

- **증거인 것과 치울 것을 구별하는가.** 검체가 만든 자리의 존재는 판정의
  근거이지만 치료 대상이 아니다. 그것을 지우려는 계획은 안전 장치에 막혀
  **아무것도 하지 못한 채 끝난다** — 값 다섯을 지우는 답안과 자리 하나를
  지우려는 답안의 차이가 여기서 갈린다.
- **감춘 것을 풀어야 닿는다.** 파일 경로는 매니페스트에 적을 수 없다. 값을
  풀어서 얻어야 하고, 두 값이 서로 다른 방식으로 감춰져 있다.
- **감춤의 모양으로 가르지 않는가.** 정상 제품도 base64 로 적고 따옴표로
  감싼다. 갈라지는 지점은 **푼 결과가 실제 파일을 가리키는가**다.
- **이름이 닮은 이웃을 건드리지 않는가.** `NetSyncAgent` 와 `NetSync` 는
  앞부분이 같다. 설정 자리에서도 폴더에서도 그렇다.
