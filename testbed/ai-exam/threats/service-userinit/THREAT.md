## 관측 보고 — 서비스로 자리잡고 로그온 경로를 덧붙이는 로더

감염된 Windows 10 기계를 확보해 다음을 관측했다.

### 지속성 1 — 서비스

자동 시작 서비스가 하나 등록되어 있다.

```
서비스 이름   SvcHostCache
표시 이름     Host Cache Service
시작 유형     자동
상태          실행 중
실행 파일     C:\ProgramData\SvcHostCache-3f8a\svc.exe
```

> **넷 중 셋만 보고서에 실린다.** 관측 도구는 등록된 정의를 읽을 뿐이라
> **돌고 있는지는 담지 못한다** — 그 사실이 기계에 적혀 있지 않기 때문이다.
> 위 "실행 중" 은 분석가가 화면에서 본 것이고, 넘겨받은 보고서에는 그 자리가
> *"알 수 없음"* 으로 온다. 나머지 셋은 그대로 실린다.

이름이 Windows 자신의 `svchost` 를 흉내 내지만 **그 자리가 아니다.** 정상
시스템 서비스는 `C:\Windows\system32` 에 있다.

폴더 이름(`SvcHostCache-3f8a`)의 꼬리는 감염마다 바뀐다. 고정된 것은 자리 —
`C:\ProgramData` 아래에 폴더 하나를 만들고 그 안에 실행 파일을 둔다 — 뿐이다.

### 지속성 2 — 로그온 경로

Winlogon 의 `Userinit` 값 끝에 그 실행 파일이 덧붙어 있다.

```
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon
  Userinit = C:\Windows\system32\userinit.exe,C:\ProgramData\SvcHostCache-3f8a\svc.exe
```

정상 값은 `C:\Windows\system32\userinit.exe,` 로 끝난다(쉼표까지가 원래
모습이다). 검체가 뒤에 자기 경로를 이어 붙였다.

> **이 값을 지우면 안 된다.** Windows 는 로그온할 때 이 값이 가리키는 것을
> 실행한다. 값이 비면 **사용자 셸이 뜨지 않아 로그인이 완료되지 않는다.**
> 원래 값으로 되돌려야 한다.

**둘 중 하나만 처리하면 나머지가 다시 살린다.** 서비스를 지워도 로그온할 때마다
실행되고, 로그온 값을 되돌려도 서비스가 부팅 때 뜬다.

### 서비스 복구 설정

그 서비스에는 실패 시 재시작이 걸려 있다. **중지만 하면 곧바로 다시 뜬다.**

### 페이로드

`C:\ProgramData\SvcHostCache-3f8a\` 안에 두 파일이 있다.

```
svc.exe     219,136 바이트
cache.db      8,192 바이트
```

**폴더 전체가 검체가 만든 것**이고, 감염 전부터 있던 사용자 파일이 섞여 있는
경우는 관측되지 않았다.

실행 파일에는 코드 서명이 없다.

### 오탐 위험 — 반드시 읽을 것

`C:\ProgramData` 는 **정상 벤더도 쓰는 자리다.** 조사한 기계에 이런 것들이
있었다.

- `C:\ProgramData\Acme\updater.exe` 를 가리키는 `Acme Update Service` — 정상
  설치 프로그램의 업데이트 서비스다. **자동 시작이 아니고 수동이며, 로그온
  값을 건드리지 않는다**
- Windows 자신의 서비스들은 대부분 `C:\Windows\system32\svchost.exe` 를 공유한다

이 기계에 등록된 서비스는 **713개**이고 그중 자동 시작이 **95개**다. 시작
유형만으로는 아무것도 가르지 못한다.

**서비스가 `ProgramData` 아래를 가리킨다는 사실만으로 판정하면 정상 벤더
서비스가 곧바로 오탐이 된다.**

### 요구

이 검체를 탐지하고, **두 지속성을 모두** 처리하고, 페이로드를 제거해야 한다.
서비스는 재시작 설정 때문에 중지만으로 끝나지 않는다.
