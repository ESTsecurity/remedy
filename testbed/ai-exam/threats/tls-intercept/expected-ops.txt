# 감염 스냅샷에서 반드시 나와야 하는 Op (채점 4번).
#
# 처음 밟는 자리가 둘이다 — cert_store.remove 와 hosts.restore_line.
# 앞의 세 위협이 밟은 것은 13종이고, 코퍼스에 오탐 압력이 있는데도
# 한 번도 쓰이지 않은 subject 가 이 둘이었다(cert_store 263건 ·
# hosts_entry 21건).
#
# **hosts 는 remove 가 아니라 restore 다.** remove 에 넣으면 계획이
# text_config.remove_line 을 내고 이 목록을 채우지 못한다. 줄을 지우는
# 것과 원래대로 되돌리는 것은 다른 일이고, 카탈로그의 RESTORE_NAMED 가
# 그 구분을 들고 있다. service-userinit 의 to: default 와 같은 부류의
# 질문이다 — 판단은 맞는데 절을 틀리면 계획이 달라진다.
#
# dir.delete_recursive 는 여기 없다. Linux 다(ldso-preload 와 같은 이유).

# ── 2026-09-04: Op 이름만 적던 것을 (Op, 대상)으로 조인다 ──────────────
#
# 그전까지 이 파일은 `registry.delete_value` 처럼 **종류만** 적었고, 그것은
# "그 종류가 하나라도 있으면 통과" 를 뜻했다. appinit-r3 회차의 사전 기준에
# 실측으로 적었듯 — AppInit_DLLs 만 지우고 LoadAppInit_DLLs 를 남긴 변형이
# 네 판정을 전부 통과하고 경고도 0이었다.
#
# 개수를 세는 것으로는 부족하다. 그러면 AppInit_DLLs 와 Spooler 를 지운 답이
# 2건으로 통과한다 — 절반짜리 치료보다 나쁜 실패다. 그래서 **대상**을 적는다.
#
# 대상 문자열은 응시자가 아니라 코어가 증거에서 조립한다(`derive.rs`). 룰을
# 어떻게 적었든 같은 레코드를 짚으면 같은 문자열이 나오므로, 답안마다 표기가
# 달라 비교가 무너지지 않는다. `::` 뒤는 `match` 다 — 대상만으로는 구분되지
# 않는 Op 이 있다(`structured_config.remove_key` 는 어느 항목을 빼는가가
# 거기에만 있고, `process.kill` 은 대상 자체가 없다).
#
# 아래 목록은 **정답 플러그인의 계획을 그대로 옮긴 것**이고, 사람이 한 줄씩
# 읽어 위협 설명의 요구와 맞는지 확인했다.

cert_store.remove /usr/local/share/ca-certificates/netguard-proxy.crt
file.quarantine_only /opt/netguard/ca.key
file.quarantine_only /opt/netguard/netguard-proxyd
hosts.restore_line /etc/hosts :: line_no=8, line=127.0.0.1	updates.example-av.com sig.example-av.com
hosts.restore_line /etc/hosts :: line_no=9, line=127.0.0.1	telemetry.example-av.com
