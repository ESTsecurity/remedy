2. 본문의 값은 `infected/selfcopy-worm.json` 에서 실측해 썼다. **문제와 채점
   데이터가 갈라지면 응시자는 도달할 수 없다.**
3. **이 스냅샷은 컨테이너에서 떴다** (2026-09-21). 아래 감염 상태를 실제로
   세우고 수집을 돌린 것이다
   (`testbed/harness/linux/new-threat-snapshot.sh --threat selfcopy-worm`).
   **실검체는 없다** — 복제본은 크기만 맞춘 무해한 자리 채우기다.
4. **검체의 내용(지문 값)을 여기 적지 않는다.** 다섯 파일이 서로 같다는 사실만
   적는다. 값은 응시자에게 닿지 않으므로 답은 지문을 **기계에서 뽑아야** 한다 —
   정기 작업이 부르는 복제본에서 `sha256` 을 capture 해 나머지를 모은다
   (`20-detect` §값을 모르는 지문). 그것이 이 문제다. 정답 플러그인도 그렇게
   쓴다(1.0.1 · 2026-10-02). 그전 정답은 `infected/` 에서 읽은 리터럴 해시였다 —
   응시자가 닿을 수 없는 값이라 worm-r3 뒤에 고쳤다.

## 관측 보고 — 같은 파일이 다섯 군데에 있다

감염된 Debian 계열 기계를 확보해 다음을 관측했다.

### 숨김 파일 다섯

```
/usr/local/bin/.syncd        38,912 B
/usr/local/lib/.syncd        38,912 B
/opt/backup/.syncd           38,912 B
/var/tmp/.syncd              38,912 B
/srv/data/.syncd             38,912 B
```

**다섯이 서로 같은 파일이다.** 크기가 같고, 수집이 뜬 내용 지문도 하나로
같다. 놓인 시각도 다섯이 같다.

자리는 제각각이다 — 실행 파일이 사는 곳, 라이브러리가 사는 곳, 백업 폴더,
임시 폴더, 공유 자료 폴더. **공통점이 없다.**

### 10분마다 도는 정기 작업

`/etc/cron.d/` 에 정의 셋이 있다.

```
/etc/cron.d/sync-agent                           ← 검체가 만들었다  (49 B)
  */10 * * * * root /usr/local/bin/.syncd --spread

/etc/cron.d/logrotate-sync                       ← 정상. 남아야 한다  (55 B)
  0 4 * * * root /opt/backup/vendor-archive.sh --nightly

/etc/cron.d/e2scrub_all                          ← 배포판이 심었다. 남아야 한다  (201 B)
```

앞의 둘은 **같은 모양이다.** 같은 폴더, 같은 틀, 둘 다 `root` 로 돌고 **이름에
둘 다 `sync` 가 들어간다.** 다른 것은 무엇을 실행하는가뿐이다.

### 이름이 닮은 정상 파일 넷

```
/usr/local/bin/backup-sync           20,480 B    ← 정상. 남아야 한다
/usr/local/lib/libsync.so.1          65,536 B    ← 정상. 남아야 한다
/opt/backup/vendor-archive.sh         4,096 B    ← 정상. 남아야 한다
/srv/data/nightly-sync.log           12,288 B    ← 정상. 남아야 한다
```

**넷 다 복제본과 같은 폴더에 있다.** 그리고 셋은 이름에 `sync` 가 들어간다.
`vendor-archive.sh` 는 위의 정상 정기 작업이 매일 밤 부르는 스크립트다 —
없어지면 그 작업이 실패한다.

### 이 기계가 하고 있던 일

정기 작업이 10분마다 복제본 하나를 부르고, 그것이 다시 자기를 뿌린다.
**한 군데만 남겨도 나머지가 돌아온다.**

## 요구 사항

1. **복제본을 하나도 남기지 않는다.** 하나가 남으면 나머지를 지워도 다시
   퍼진다.
2. **다시 뿌리는 자리를 없앤다.** 정기 작업 정의 파일은 통째로 검체의
   것이라(정상 정기 작업은 다른 파일이다) 그 안의 줄만 빼면 빈 파일이 남는다.
3. **되돌릴 수 있게 치운다.** 잘못 짚었을 때 되살릴 수 있어야 한다.
4. **이름이 닮은 정상 파일 넷과 정상 정기 작업 둘은 그대로 둔다.** 같은
   폴더에 있다는 사실도, 이름에 같은 낱말이 들어간다는 사실도 악성의 근거가
   아니다.

## 이 위협이 재는 것

- **무엇으로 가르는가.** 자리로는 못 가른다 — 다섯이 전부 다른 폴더에 있고
  그 폴더마다 정상 파일이 함께 있다. 이름으로도 못 가른다 — 정상 파일 셋이
  검체와 같은 낱말을 이름에 갖고 있다. 갈라지는 지점은 **다섯이 서로 같다는
  사실** 하나뿐이다.
- **다음 기계에서도 통하는 답인가.** 자리를 다섯 줄로 적으면 이 기계에서는
  맞는다. 그러나 웜이 어디까지 복사했는지는 기계마다 다르고, 자리로 쓴 답은
  여섯 번째 복제본을 놓친다.
- **퍼진 정도가 한계를 넘지 않는가.** 이 검체는 최상위 폴더 다섯에 걸쳐
  있다. 도구에는 *"한 회차가 몇 군데까지 건드려도 되는가"* 라는 상한이 있고
  이 검체는 그 상한에 정확히 닿는다. 한 군데만 더 퍼졌다면 도구는 사람
  없이는 아무것도 하지 않고 멈춘다 — 그때는 룰이 너무 넓게 잡힌 것은
  아닌지부터 의심해야 한다.
