## 관측 보고 — 설정 하나가 바뀌었고 덤프가 남아 있다

감염된 Windows 10 기계를 확보해 다음을 관측했다.

### 인증 공급자 설정에 값 하나가 늘었다

`HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest` 자리에 값
여섯이 있다.

```
UseLogonCredential            1          ← 검체가 만들었다. 청정 기계에는 없던 값이다
Debuglevel                    0
Negotiate                     0
UTF8HTTP                      1
UTF8SASL                      1
DigestEncryptionAlgorithms    3des,rc4
```

**첫 줄만 검체의 것이다.** 그 값이 켜지면 로그온 자격 증명이 메모리에
평문으로 남고, 덤프를 뜨면 그대로 읽힌다. 나머지 다섯은 이 배포판이 원래
넣어 둔 값이라 청정 기계에도 그대로 있다 — **자리째 지우면 다섯이 함께
사라지고 이 기계의 인증 구성이 망가진다.**

### 덤프 도구와 그 산출물

```
C:\ProgramData\SysDiag\dump.exe            ← 검체        (  892,928 B)
C:\ProgramData\SysDiag\lsass_0914.dmp      ← 검체        (4,194,304 B)
```

`dump.exe` 가 메모리를 훑어 `.dmp` 로 떨어뜨렸다. **그 덤프 안에는 위의 설정
때문에 평문으로 남은 자격 증명이 들어 있다.**

바로 옆 폴더에 이름이 닮은 정상 도구가 있다.

```
C:\ProgramData\SysMon\perfcheck.exe        ← 정상. 남아야 한다  (  331,776 B)
```

`SysDiag` 와 `SysMon` 은 앞 세 글자가 같다. 폴더 이름의 앞부분만 보고
겨누면 이 정상 도구가 함께 걸린다.

### 다시 뜨게 하는 자리

로그온할 때 실행되는 항목 **열일곱** 중 하나가 검체의 것이다.

```
SysDiagnostics    "C:\ProgramData\SysDiag\dump.exe" /quiet     ← 검체
```

나머지 열여섯은 이 기계에 설치된 정상 소프트웨어의 것이다(보안 제품 ·
브라우저 · VPN 클라이언트 · 전자서명 도구 등). **전부 남아야 한다.** 이
항목이 남으면 덤프 도구가 로그온마다 다시 돈다.

## 요구 사항

1. **평문 자격 증명을 남기게 하는 값 하나를 지운다.** 검체가 새로 만든
   값이므로 지우면 그 자리가 청정 기준과 같아진다. **같은 자리의 다른 다섯은
   건드리지 않는다.**
2. **덤프 도구와 덤프 파일을 되돌릴 수 있게 치운다.** 덤프 안에 사용자의
   자격 증명이 들어 있어도 그 파일 자체는 검체가 만든 것이다.
3. **다시 뜨게 하는 자리를 없앤다.** 남으면 로그온마다 덤프 도구가 다시 돈다.
4. **이름이 닮은 정상 도구와 정상 자동 실행 항목 열여섯은 그대로 둔다.**

## 이 위협이 재는 것

- **키가 아니라 값 하나를 겨누는가.** 검체가 만든 것은 그 키의 값 하나뿐이고,
  같은 자리에 배포판이 넣어 둔 값 다섯이 함께 산다. 자리째 겨누는 답안은
  다섯을 함께 지우고 인증 구성을 망가뜨린다.
- **값의 내용까지 보는가.** 이 값이 켜져 있어야 위협이다. 조직이 그 값을 꺼
  둔(0) 기계를 치료가 건드릴 이유가 없다 — 꺼져 있는 기계에서 아무것도
  맞히지 않아야 한다.
- **이름이 닮은 이웃을 건드리지 않는가.** `SysDiag` 와 `SysMon` 은 앞 세
  글자가 같다.
- **누가 만든 파일인가로 가르는가.** 덤프 파일 안에는 사용자의 자격 증명이
  들어 있다. 그래도 그 파일은 검체가 만든 것이라 치운다 — 사용자가 만든
  문서가 망가진 경우(암호화된 사용자 문서)와는 정반대 판단이고, 가르는 것은
  **안에 무엇이 들었는가**가 아니라 **누가 만든 파일인가**다.
