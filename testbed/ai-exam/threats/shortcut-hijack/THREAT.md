## 관측 보고 — 바탕화면의 바로가기 넷

감염된 Windows 10 기계를 확보해 다음을 관측했다.

### 바로가기 넷 중 하나만 검체다

```
Chrome.lnk
  가리키는 곳   C:\Program Files\Google\Chrome\Application\chrome.exe
  인자          --load-extension=C:\ProgramData\WebHelper\ext
                --disable-features=RendererCodeIntegrity
```

**가리키는 곳은 정상 브라우저다.** 덧붙은 것은 인자 둘뿐이고, 하나는 폴더를
강제로 싣게 하며 하나는 브라우저의 보호 기능을 끈다.

```
Edge.lnk                가리키는 곳: msedge.exe        인자 없음      ← 정상
Microsoft Edge.lnk      가리키는 곳: msedge.exe        인자 없음      ← 정상 (기계에 원래 있던 것)
Notepad.lnk             가리키는 곳: notepad.exe
  인자   C:\Users\test\Documents\memo.txt                             ← 정상이다
```

**넷째를 보라.** 인자가 있지만 정상이다 — 두 번 누르면 메모를 열어 주는 흔한
구성이다. *"인자가 붙어 있으면 검체"* 라는 규칙은 여기서 무너진다.

### 인자가 가리키는 것

```
C:\ProgramData\WebHelper\ext\manifest.json      ← 검체  ( 2,048 B)
C:\ProgramData\WebHelper\ext\bg.js              ← 검체  (16,384 B)
```

```
C:\ProgramData\WebTools\netcheck.exe            ← 정상. 남아야 한다  (204,800 B)
```

두 폴더 이름이 닮았다 — `WebHelper` 와 `WebTools`.

### 이 기계가 하고 있던 일

사용자가 바탕화면의 바로가기로 브라우저를 열 때마다, 브라우저가 **검체의
폴더를 확장으로 싣고** 보호 기능 하나를 끈 채 뜬다. 브라우저 자체는 정상이고
설치된 확장 목록에도 아무것도 없다 — 바로가기를 거치지 않고 열면 아무 일도
일어나지 않는다.

## 요구 사항

1. **덧붙은 인자를 뗀다.** 바로가기 파일은 남아야 하고, 가리키는 곳도 그대로
   여야 한다. 이 바로가기에는 원래 인자가 없었으므로 치료 뒤 인자는 비워진다.
2. **실리던 폴더의 파일 둘을 되돌릴 수 있게 치운다.**
3. **정상 바로가기 셋은 그대로 둔다.** 그 중 하나는 인자를 갖고 있다.
4. **이름이 닮은 정상 도구는 그대로 둔다.**

## 이 위협이 재는 것

- **무엇을 없애고 무엇을 고치는가.** 검체가 만든 파일은 치우고, 검체가
  **고친** 파일은 고친 부분만 되돌린다. 바로가기를 치우는 답안은 사용자가
  브라우저를 여는 길을 없앤 것이고, 가리키는 곳을 바꾸는 답안은 더 나쁘다.
- **인자의 유무로 가르지 않는가.** 정상 바로가기 하나에도 인자가 있다.
  갈라지는 지점은 인자가 **무엇을 가리키는가**다.
- **이름이 닮은 이웃을 건드리지 않는가.** `WebHelper` 와 `WebTools` 는 앞
  세 글자가 같다.
- **없는 것을 찾으려 하지 않는가.** 이 검체는 브라우저에 확장을 설치하지
  않았다. 설치된 확장 목록을 훑는 답안은 아무것도 찾지 못한다 — 확장은
  바로가기가 열릴 때만 실린다.
