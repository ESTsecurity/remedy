## 관측 보고 — 웹 루트 안에서만 갈린다

웹 서버가 도는 Windows 기계를 확보해 `C:\inetpub\wwwroot` 아래를 관측했다.
**파일 여덟이 전부다.**

### 웹사이트 자신의 파일 셋

```
C:\inetpub\wwwroot\Default.aspx                     12,288 B   ← 첫 화면
C:\inetpub\wwwroot\App\Handlers\Upload.aspx          7,168 B   ← 파일을 받는 창구
C:\inetpub\wwwroot\App\Web.config                    2,048 B   ← 설정
```

**전부 남아야 한다.** `Default.aspx` 가 사라지면 웹사이트가 뜨지 않고,
`Web.config` 가 사라지면 애플리케이션이 시작하지 않는다. `Upload.aspx` 는
검체가 들어온 통로일 수는 있어도 검체는 아니다.

### 사용자가 올린 파일 셋

```
C:\inetpub\wwwroot\uploads\avatar-8821.png             65,536 B
C:\inetpub\wwwroot\uploads\quarterly-report.pdf       262,144 B
C:\inetpub\wwwroot\uploads\2026-09\receipt-441.jpg    131,072 B
```

**전부 남아야 한다.** 사용자의 데이터다.

### 그 사이에 있는 둘

```
C:\inetpub\wwwroot\uploads\sess_7f3a9c.aspx             1,024 B
C:\inetpub\wwwroot\uploads\2026-09\.thumb.aspx            768 B
```

**올린 파일을 담는 자리에, 웹 서버가 실행하는 화면이 있다.**

둘은 위의 정상 화면과 **확장자가 같고**, 위의 올라온 파일과 **폴더가 같다.**
그리고 놓인 시각이 둘만 같다 — 올라온 파일 셋보다 한참 뒤다.

**하나는 한 단계 더 들어가 있다.** `uploads` 바로 아래가 아니라
`uploads\2026-09\` 안이다. 올라온 파일도 그 폴더에 하나 있다.

### 이 기계가 하고 있던 일

두 화면은 웹 서버가 요청을 받으면 실행한다. 밖에서 주소만 알면 명령을 보낼
수 있고, 그 명령은 웹 서버의 권한으로 돈다. **검체가 파일 말고 아무것도
남기지 않은 까닭이 그것이다** — 자동으로 실행될 필요가 없다. 웹 서버가 대신
실행해 준다.

## 요구 사항

1. **그 두 화면을 되돌릴 수 있게 치운다.**
2. **웹사이트 자신의 파일 셋은 그대로 둔다.** 확장자가 같다는 사실은 악성의
   근거가 아니다.
3. **올라온 파일 셋은 그대로 둔다.** 같은 폴더에 있다는 사실도 악성의 근거가
   아니고, 그것은 사용자의 데이터다.
4. **한 단계 아래 폴더까지 본다.** 한 층만 보면 둘 중 하나가 남고, 남으면 웹
   서버가 그것을 계속 실행한다.

## 이 위협이 재는 것

- **자리와 종류를 함께 보는가.** 이것이 이 문제의 전부다. 종류만 보면 정상
  화면 둘이 걸리고, 자리만 보면 올라온 파일 셋이 걸린다. 갈라지는 것은
  *"올린 파일을 담는 자리에 실행되는 것이 있다"* 는 사실 하나다.
- **깊이를 가정하지 않는가.** 검체 하나가 하위 폴더에 있다. 올린 파일을
  날짜별로 나눠 담는 흔한 구성이고, 그 아래로 더 들어갈 수도 있다.
- **크기에 기대지 않는가.** 검체 둘은 1 KB 아래이고 정상 화면은 7 KB 를
  넘는다. 그러나 크기로 가르면 **큰 검체를 놓치고 작은 정상 파일을 잡는다** —
  여기서 크기는 관측된 사실일 뿐 근거가 아니다.
- **없는 것을 찾으려 하지 않는가.** 이 검체에는 자동 실행 등록이 없다.
  그 자리를 훑는 데 시간을 쓰는 답안은 아무것도 찾지 못한다.
