## 관측 보고 — 폴더 하나에 파일 다섯

감염된 Windows 10 기계를 확보해 다음을 관측했다.

### 정상 제품의 폴더인데 파일 둘이 더 있다

`C:\ProgramData\AcmeSync` 는 파일 동기화 제품이 쓰는 폴더다. 그 안에 파일
다섯이 있다.

```
파일                크기        마지막으로 고쳐진 시각
AcmeSync.exe       262,144 B   2025-12-03T08:20:41Z   <- 제품의 주 실행 파일
ui.dll              65,536 B   2025-12-03T08:20:41Z   <- 정상
core.dll           786,432 B   2026-09-05T03:12:44Z   <- 정상
netcache.dll        45,056 B   2026-09-19T21:40:33Z   <- 검체
svcstub.exe         28,672 B   2026-09-19T21:40:33Z   <- 검체
```

**주 실행 파일과 `ui.dll` 은 같은 시각이다** — 제품이 설치된 시각이다.
`core.dll` 만 그보다 뒤인데, 제품이 스스로 갱신한 것으로 보인다(그 시각의
갱신 기록이 제품 로그에 있다).

검체 둘은 **설치보다 훨씬 뒤에 놓였고, 제품의 어느 모듈보다도 작다.**

### 둘 중 하나만 보면 정상 파일이 걸린다

```
'설치보다 뒤에 놓인 것' 만 보면   ->  core.dll 이 함께 걸린다 (정상 갱신)
'모듈보다 작은 것'   만 보면   ->  ui.dll   이 함께 걸린다 (설치 때부터 있었다)
```

**둘을 함께 보아야 검체 둘만 남는다.**

### 다시 뜨게 하는 자리

로그온할 때 실행되는 항목 **열일곱** 중 하나가 검체의 것이다.

```
AcmeSyncUpdate    "C:\ProgramData\AcmeSync\svcstub.exe" -q
```

나머지 열여섯은 이 기계에 설치된 정상 소프트웨어의 것이다(보안 제품 ·
브라우저 · VPN 클라이언트 · 전자서명 도구 등). **전부 남아야 한다.**

제품 자신은 로그온 항목을 쓰지 않는다 — 사용자가 열 때만 뜬다. 그래서 이
항목은 제품의 것이 아니다.

### 이 기계가 하고 있던 일

로그온할 때마다 위 항목이 `svcstub.exe` 를 띄우고, 그것이 같은 폴더의
`netcache.dll` 을 싣는다. **폴더가 정상 제품의 것이라 경로만 보는 검사에는
익숙한 자리로 보인다.**

## 요구 사항

1. **끼어든 파일 둘을 되돌릴 수 있게 치운다.** 어느 것이 끼어든 것인지는
   제품의 주 실행 파일을 기준으로 재어 판단해야 한다.
2. **다시 뜨게 하는 자리를 없앤다.** 남으면 로그온마다 다시 돈다.
3. **제품의 파일 셋은 그대로 둔다.** 그 셋 가운데 하나는 기준보다 새롭고,
   하나는 기준보다 작다.
4. **정상 자동 실행 항목 열여섯은 그대로 둔다.**

## 이 위협이 재는 것

- **두 성질을 함께 보는가.** 이것이 이 문제의 전부다. 시각만 보면 제품의
  갱신된 모듈이 걸리고, 크기만 보면 제품이 설치 때부터 갖고 있던 작은 모듈이
  걸린다. 둘 다 정상이고, 둘 다 치우면 제품이 깨진다.
- **기준을 기계에서 얻는가.** 절대 시각이나 바이트 수를 답안에 적으면 같은
  검체가 다른 기계에 놓일 때 아무것도 찾지 못한다 — 제품의 설치 시각과 모듈
  크기는 기계마다 다르다. 기준은 **그 기계의 주 실행 파일**에 있다.
- **자를 치우지 않는가.** 기준으로 쓴 파일은 정상 제품의 주 실행 파일이다.
  그것을 함께 치우는 답안은 제품을 실행할 수 없게 만든다.
- **폴더가 정상이라는 사실에 속지 않는가.** 이 폴더는 정상 제품의 것이다.
  *"알려진 제품 폴더는 건너뛴다"* 는 규칙은 여기서 검체 둘을 놓친다.
