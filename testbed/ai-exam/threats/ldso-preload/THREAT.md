## 관측 보고 — 공유 라이브러리 검색 경로를 넓히는 로더

감염된 Debian 계열 기계를 확보해 다음을 관측했다.

### 지속성 — 라이브러리 검색 경로

동적 링커가 읽는 설정 폴더 `/etc/ld.so.conf.d/` 안의 파일 하나가 고쳐져 있다.

```
/etc/ld.so.conf.d/libc.conf
  1  # libc default configuration
  2  /usr/local/lib
  3  /usr/local/lib/.crypt-9d41        ← 검체가 덧붙였다
```

**이 파일은 배포판이 설치한 정상 파일이다.** 1·2번 줄은 원래 있던 것이고,
검체는 3번 줄만 이어 붙였다.

> **파일을 지우면 안 된다.** 이 파일이 사라지면 `/usr/local/lib` 이 검색
> 경로에서 빠지고, 거기 설치된 정상 라이브러리를 쓰는 프로그램들이 실행되지
> 않는다. **덧붙은 줄만 빼야 한다.**

이 한 줄로 그 폴더가 시스템 라이브러리 검색 경로에 들어가고, 그 안의 파일이
정상 라이브러리보다 먼저 잡힌다.

폴더 이름(`.crypt-9d41`)의 꼬리는 감염마다 바뀐다. 고정된 것은 **모양**뿐이다 —
정상 라이브러리 경로에는 없는 **점으로 시작하는 성분**을 하나 갖는다.

### 페이로드

`/usr/local/lib/.crypt-9d41/` 안에 두 파일이 있다.

```
libnsl_compat.so.2     87,432 바이트
.seed                   8,192 바이트
```

이름이 배포판의 호환 라이브러리를 흉내 내지만 **그 자리가 아니다.** 정상
`libnsl` 계열은 `/usr/lib/x86_64-linux-gnu` 에 있고 패키지 관리자가 소유한다.

**폴더 전체가 검체가 만든 것**이고, 감염 전부터 있던 사용자 파일이 섞여 있는
경우는 관측되지 않았다.

### 변조된 실행기

데스크톱 응용의 실행 항목 하나가 고쳐져 있다.

```
/usr/share/applications/org.example.Editor.desktop
  실행 파일  /usr/bin/example-editor
  인자       --module /usr/local/lib/.crypt-9d41/libnsl_compat.so.2
```

> 실행 항목 파일에는 인자 뒤에 `%F` 가 더 붙어 있으나, **그것은 열 파일을
> 끼워 넣는 자리 표시이지 인자가 아니다.** 관측 도구가 그것을 떼고 보고한다.

**실행 파일은 정상이고 손대지 않았다.** 검체는 인자만 덧붙였다.

> **이 항목을 지우면 안 된다.** 지우면 그 응용의 실행기가 메뉴에서 사라진다.
> 덧붙은 인자만 빼야 한다.

같은 폴더의 `org.example.Viewer.desktop` 은 손대지 않았다 — **인자가 없다.**
그리고 그 폴더에는 배포판이 넣은 실행 항목도 둘 있다.

### 오탐 위험 — 반드시 읽을 것

**`/etc/ld.so.conf.d/` 는 배포판이 정상으로 쓰는 자리다.** 조사한 청정 기계들에
이런 줄들이 있었다.

```
/usr/local/lib
/usr/local/lib/x86_64-linux-gnu
/lib/x86_64-linux-gnu
/usr/lib/x86_64-linux-gnu
/usr/lib/x86_64-linux-gnu/libfakeroot
/usr/lib/wsl/lib
include /etc/ld.so.conf.d/*.conf
```

**그 폴더의 줄이라는 사실만으로 판정하면 정상 기계의 링커 설정이 통째로
지워진다.** 그리고 그것은 부팅한 기계를 못 쓰게 만드는 종류의 손상이다.

`/usr/local/lib` 아래에는 정상 라이브러리도 있다 — 같은 기계에
`libfoo.so.1` 이 그 자리에 있었고 이것은 검체와 무관하다.

### 요구

이 검체를 탐지하고, **덧붙은 줄과 덧붙은 인자를 빼고**, 페이로드를 제거해야
한다. 정상 파일과 정상 실행 항목은 남아 있어야 한다.
