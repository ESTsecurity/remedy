# AI 합격 시험 — 절차

설계-09 P11 의 검증 한 줄이 이 폴더다.

> 고정 프롬프트 + 지정 위협 설명 → 룰 생성 → `plugin lint` 통과 + 청정 코퍼스 0건.
> **누가 언제 돌려도 같은 절차.**

## 무엇을 재는가

**가이드를 잰다. 모델을 재지 않는다.**

AI 가 틀리면 그것은 대개 가이드의 빈칸이다. 설계-06 §10 이 그렇게 적었다 —
*"AI 가 무엇을 틀리는가가 관측되고, 그 관측이 나머지 문서의 목차를 정한다."*
이 시험의 산출물은 합격/불합격이 아니라 **틀린 목록**이다.

## 고정되는 다섯

| 무엇 | 어디 |
|---|---|
| 프롬프트 | [`PROMPT.md`](PROMPT.md) — 한 글자도 고치지 않고 그대로 붙인다 |
| 위협 설명 | `threats/<위협>/THREAT.md` — 분석가가 쓴 관측 보고다. 매니페스트 필드명이 한 개도 없다 |
| 주입할 가이드 파일 | 아래 목록. **더 넣지도 빼지도 않는다** |
| 기대 Op 목록 | `threats/<위협>/expected-ops.txt` — 계획에 반드시 있어야 하는 것 |
| 합격 판정 | `cargo xtask exam` 넷 전부. 사람 판단이 들어가지 않는다 |

### 고정할 수 없는 것 — 모델

**모델은 고정할 수 없다.** 판이 바뀌고, 같은 판도 같은 답을 두 번 내지 않는다
(temperature 0 도 제공자 쪽 변경까지 막지는 못한다).

그래서 이것은 **회귀 시험이 아니다.** "지난번 합격이 이번에도 합격" 을 요구하지
않는다. 요구하는 것은 *같은 절차로 다시 물을 수 있다* 는 것뿐이다. 기록할 때
모델 이름과 날짜를 반드시 함께 적는 이유가 그것이다 — 결과는 **그 모델의 그 날**
관측이지 이 저장소의 성질이 아니다.

## 위협 — 시험은 여럿이다

```
cargo xtask exam --bundle --threat <이름>          # 기본: evilai-locust
cargo xtask exam --dir <답> --threat <이름>
```

| 위협 | 무엇을 재는가 | 감염 스냅샷 | 분석가 룰 |
|---|---|---|---|
| `evilai-locust` | 예약 작업 + 랜덤 폴더 + 난독화 JS. **본문 판정(YARA)** | `corpus/infected/` (격리 VM 실측) | 있음 |
| `service-userinit` | 서비스 + 레지스트리. **삭제하면 안 되는 값을 되돌리는 판단** | `threats/service-userinit/infected/` (**합성**) | 없음 |
| `ldso-preload` | **리눅스.** 설정 파일 한 줄 + 바로가기 인자. **지우지 말고 빼야 하는 것** | `threats/ldso-preload/infected/` (**합성**) | 없음 |
| `tls-intercept` | **리눅스.** 심어진 루트 CA + 돌려진 이름. **지우기와 되돌리기를 가르는 판단** | `threats/tls-intercept/infected/` (**합성**) | 없음 |
| `appinit-implant` | 모든 프로세스 주입 + 방화벽 + 에이전트 설정. **Windows 키에서 값만 빼는 판단** | `threats/appinit-implant/infected/` (**합성**) | 없음 |
| `search-hijack` | 브라우저 확장 + 경로 목록 + 부팅 목록 + 프록시. **한 값 안에 정상과 검체가 섞여 있을 때 절을 고르는 판단** | `threats/search-hijack/infected/` (**합성**) | 없음 |

> **네 번째 위협이 재는 것.** 앞의 셋이 밟은 Op 은 스물아홉 중 열셋이다.
> 청정 코퍼스에 **오탐 압력이 실제로 있는데도** 한 번도 쓰이지 않은 대상이 둘
> 남아 있었다 — 신뢰 저장소의 인증서(263건)와 이름 해석 항목(21건). 둘 다
> **경로로 파생시킬 수 없는 대상**이라 앞선 셋의 방식(증거에서 폴더를 뽑아
> 자식을 좁힌다)이 통하지 않는다.
>
> 그리고 이 위협의 실패는 **채점 4번만 잡는다.** `hosts` 를 `restore` 가 아니라
> `remove` 에 넣은 답은 린트·코퍼스·판정을 전부 통과하고 계획에서만 갈린다
> (실측: `hosts.restore_line` 빠짐 · `text_config.remove_line` 기대 밖).

> **세 번째 위협이 리눅스인 이유.** `10-manifest.md` 의 표에서 *"`scan_roots`
> 가 범위를 정한다"* 쪽 subject — 설정 파일 · 바로가기 — 를 앞의 둘이 하나도
> 밟지 않았다. 그런데 그 subject 의 오탐 압력은 **리눅스 스냅샷에만 있다**:
> 청정 코퍼스의 `text_config` 4,217건이 전부 리눅스 것이고 Windows 쪽은 0건이다.
> `structured_config` 는 코퍼스 전체에 0건이라 그것으로 위협을 만들면 채점
> 2번이 공허해진다 — 그래서 `text_config` 를 골랐다.

**위협마다 채점 재료가 다르다** — 위협 설명 · 분석가 룰 · 감염 스냅샷 · 기대 Op.
청정 코퍼스는 공유한다(모든 위협이 같은 정상 환경에서 0건이어야 한다).

### 합성 스냅샷을 코퍼스에 넣지 않는다

`corpus/infected/` 는 *"격리 VM 에서 `remedy collect` 가 실제로 뜬 것"* 이라는
성질을 갖는다(설계-04 §3). 실검체가 없는 위협의 스냅샷은 **위협 폴더에만** 두어
그 성질을 지킨다.

합성이라도 시험은 성립한다 — 여기서 재는 것은 *"규격을 지켜 룰을 쓰는가"* 이고,
실검체 탐지는 `cargo xtask yara` 가 따로 잰다.

### 위협마다 참조 답안이 있다

`REFERENCES` 표(`xtask::exam` 테스트)가 위협 목록과 대조된다. **정답이 자기
기준을 못 넘으면 그 기준이 틀린 것**이고, 없으면 응시자만 떨어진다.

## 절차

**1. 꾸러미를 만든다.**

```
cargo xtask exam --bundle [--threat <이름>]
# → testbed/ai-exam/exam-bundle.txt  (--out 으로 자리를 바꿀 수 있다)
```

주입 파일 21개 + 분석가 룰 + 프롬프트를 한 덩어리로 조립한다(122 KB).
`{{THREAT}}` 치환도 여기서 된다.

> **`> 파일` 로 받지 않는다.** 셸이 그 바이트를 세 번 손댄다 — 콘솔 코드페이지로
> 디코드(CP949 면 **한글이 깨진다**) · 리다이렉트 기본 인코딩으로 재인코딩
> (BOM · UTF-16) · 줄 단위 재작성(LF → CRLF).
>
> 실측된 사고다. 같은 명령이 Bash 에서 93,884 바이트, PowerShell 에서 96,405
> 바이트를 냈고, 어떤 환경에서는 응시자가 **산문의 절반이 `?` 로 소실된**
> 꾸러미를 받았다. 지금은 `xtask` 가 파일에 직접 쓰므로 셸이 개입할 자리가
> 없다.

> **왜 기계가 조립하는가.** 손으로 하면 17 개 조각을 순서대로 붙여야 하고,
> **조립 실수가 곧 회차 오염이다** — 파일 하나가 빠지면 그 회차는 다른 시험인데
> 아무도 눈치채지 못한다. 그리고 이 시험은 모델이 바뀔 때마다 다시 돌려야
> 가치가 있다. 한 번은 할 수 있어도 반복되지 않는 절차는 절차가 아니다.
>
> 꾸러미는 `PROMPT.md`·`THREAT.md` 의 **구분선 아래만** 취한다. 위쪽은 출제
> 메모이고, 거기에는 지난 회차가 어떻게 무너졌는지가 적혀 있다 — 응시자가
> 보면 힌트다. `xtask guide` 가 그것이 새지 않는지 검사한다.

**2. 새 대화를 연다.** **이 저장소를 읽은 적 없는 대화여야 한다.** 문맥에 남은
정답이 결과를 끌어올린다 — 지금까지의 세 회차가 전부 그렇게 무너졌다.

**3. 꾸러미를 통째로 붙인다.** 나눠 붙이지 않는다. 잘라야 한다면 파일 경계에서
자르고, 그 사실을 기록에 적는다.

**4. 답을 받아 저장한다.**

```
testbed/ai-exam/runs/<날짜>-<모델>-r<회차>/plugin.yaml
testbed/ai-exam/runs/<날짜>-<모델>-r<회차>/rules/*.yar      (YARA 를 썼다면)
```

**5. 채점한다.**

```
cargo xtask exam --dir testbed/ai-exam/runs/<날짜>-<모델>-r<회차> [--threat <이름>]
```

## 채점 — 넷 전부 자동이다

| # | 판정 | 근거 |
|---|---|---|
| 1 | `plugin lint` 오류 0 | 설계-06 §7. **경고는 불합격이 아니다** — 서명 단계에서 사람이 확인하는 자리이고(§8), 여기서 막으면 작성자가 경고를 끄는 법부터 배운다 |
| 2 | 청정 코퍼스 16개에서 파괴 Action 0건 | G1. 정상 Windows·Linux 환경이다 (개수는 `corpus/clean/` 이 정한다) |
| 3 | 감염 스냅샷에서 판정이 선다 | **이것이 없으면 아무것도 탐지하지 않는 룰이 만점을 받는다** |
| 4 | 계획에 `expected-ops.txt` 의 Op 이 전부 있다 | 3 번은 **무엇을 지우는지는 안 본다.** r0 이 세 판정을 통과하고도 Run 값과 Defender 제외를 남겼다 |

3번이 없을 때 무슨 일이 생기는지는 실측했다 — 매치될 수 없는 문자열 하나만 든
매니페스트가 1·2 를 만점으로 통과한다.

```
  1. 린트          오류 0 · 경고 0
  2. 청정 코퍼스   7개 중 파괴 0개
  3. 감염 탐지     1개 중 판정 0개
  4. 계획 완결성   기대 6건 중 빠짐 6건
실패: 불합격 — 감염 스냅샷 1건에서 판정이 서지 않는다 · 계획에 빠진 Op 6건
```

**"안전한 쪽으로 틀리기" 는 여기서 합격이 아니다.** 아무것도 지우지 않는
전용백신은 안전하지만 쓸모가 없다.

### 4 번은 Op 을 본다 — 규칙 id 가 아니라

`id` 는 회차마다 다르지만 **Op 은 subject 가 정한다.** 같은 대상을 지우면 같은
Op 이 나오므로 자동으로 잴 수 있다.

기대 목록은 위협마다 `threats/<id>/expected-ops.txt` 에 있고 **고정되는 것 중
하나**다. **빠진 것만 불합격이다** — 초과는 표시만 한다(청정 코퍼스가 오탐을
재고, 감염 스냅샷에서 더 지우는 것은 더 철저한 것일 수 있다).

**첫 플러그인이 이 기준을 넘는지는 테스트가 강제한다**
(`crates/remedy-core/tests/infected.rs`). 정답이 자기 채점 기준을 못 넘기면
기준 쪽이 틀린 것이고, 그것을 아무도 안 재면 도달할 수 없는 목록이 조용히
자리 잡는다 — 1 회차가 그렇게 무너졌다.

### 채점이 재지 않는 것

- **지우는 대상이 맞는가** — 4 번은 Op 종류만 본다. 그 Op 이 **옳은 경로**를
  겨누는지는 사람이 읽고 기록에 적는다.
- **`scan_roots` 가 옳은가** — 대부분 재지 못한다. 평가기는 파일 시스템을 열 수
  없어 토큰을 확장하지 못하고, 스냅샷에 이미 기록된 수집 범위를 쓴다. 그래서
  **존재하지 않는 경로를 선언해도 네 판정을 전부 통과한다**(r1 실측). 실기기
  `scan` 에서만 드러난다.

  **한 부류만 예외다(2026-09-02~).** 선언한 subject 가 그 종류의 루트를 하나도
  갖지 못하면 린트가 오류를 낸다 — `registry_value` 를 적고 레지스트리 루트가
  없으면 실기기에서 언제나 0건이기 때문이다. 채점 1번에 걸리므로 불합격이다.
  그 전까지는 **우리 예제 `ex02` 와 정답 플러그인 하나가 그 상태로 초록이었다.**
- **룰의 품질** — 오탐률은 코퍼스가 재는 만큼만 잰다. **어떤 subject 는 재지 못한다** — 코퍼스에 그 레코드가 0건이면 그 subject 를 겨눈 룰은 오탐 게이트를 한 번도 지나지 않는다.

## 회차가 무엇을 재는지 **채점 전에** 적는다

**합격은 그 자체로 아무것도 말해 주지 않는다.** 두 번 값을 치르고 배웠다.

- `ldso-r2` — 합격했는데 갈리지 않았다. r1 도 빈칸이 있는 채로 합격이었으므로,
  통과가 "메운 문서 덕분" 인지 "원래 되는 것" 인지 숫자가 말해 주지 않았다.
  결국 **답안의 서술**을 읽고 판단했다.
- `appinit-r2` — 채점 전에 기준을 적어 두었다. *"합격이어도 `direction` 을 쓰지
  않았으면 아무것도 못 잰다"*. 답안은 그것을 썼고 근거까지 인용했다. **적어 두지
  않았으면 합격을 그냥 성공으로 읽었을 것이다.**

그래서 회차를 넘기기 전에 이 셋을 적는다.

1. **무엇이 달라졌는가** — 지난 회차 이후 주입 파일 중 바뀐 것 전부.
   `git diff --stat <그때> HEAD -- docs/plugin-guide/` 로 센다.
2. **무엇을 보면 통했다고 할 것인가** — 답안이 실제로 그 자리를 지나야 한다.
   지나지 않고 합격한 것은 **신호가 아니다.**
3. **그래도 못 재는 것** — 모델이 같으면 "다른 모델도 그러한가" 는 모른다.
   표본은 언제나 하나다.

**적는 자리는 회차를 넘기는 보고이고, 채점할 때 그것을 `NOTES.md` 로 그대로
옮긴다.** 파일을 따로 두지 않는다 — `runs/` 아래 디렉터리는 전부
`EXPECTED_RUNS` 에 있어야 해서(`the_table_covers_every_run_on_disk`) 답이
오기 전에는 그 자리를 만들 수 없고, 다른 자리에 두면 채점할 때 아무도 찾지
않는다. **옮겨 적는 것이 절차의 일부다.**

## 기록

`runs/<날짜>-<모델>-r<회차>/NOTES.md` 에 적는다. 최소 항목:

- 모델 이름과 버전, 돌린 날짜
- 채점 출력 그대로
- **AI 가 틀린 것 하나하나** — 이것이 산출물이다
- 틀린 것이 가이드의 어느 빈칸을 가리키는가

기록 속 커밋 해시(`사전 기준` 칸 등)는 **공개 이전 역사의 것이다** — 이 저장소에서는
찾을 수 없고, 그 역사는 내부 보관본에 있다.

## 모델이 거부하면 그 회차는 없다

**교차 모델 측정은 우리가 고를 수 있는 변수가 아니다.** 2026-09-02 에
`search-hijack` 을 `fable-5` 로 돌리려다 **그 모델의 안전 필터가 거부해**
진행하지 못했다. 위협 설명이 악성코드 동작을 구체적으로 적는 문서라 그렇게
읽힌 것으로 보인다 — 방어용 전용백신의 룰을 쓰는 일인데도 그렇다.

그래서 회차를 설계할 때 이것을 조건으로 놓는다.

- *"다른 모델도 그러한가"* 는 **물을 수 있을 때만** 물을 수 있다. 못 물은
  회차는 기록에 그렇게 적는다(`hijack-r2`).
- 모델을 못 바꾸면 그 회차는 교차 모델이 아니라 **재현**이 된다. 그것도 값이
  있다 — 같은 조건이 같은 답을 내는지는 이 시험이 열여덟 회차 동안 한 번도
  재지 않았다.

## 오염 — 이 시험의 정직성 한계

**2 단계 "저장소를 읽지 않는다" 는 강제되지 않는다.** 명예 규칙이다. 웹
채팅에서 사람이 파일을 붙여 넣는 방식이라 도구가 막을 자리가 없다.

강제하려면 시험 자체가 CI 에서 돌아야 하고, 그러려면 모델 API 키가 빌드에
들어가야 한다 — 설계-01 D9(치료 경로 네트워크 금지)와는 다른 자리지만, 빌드가
외부 서비스에 의존하게 되는 것은 그 자체로 결정할 일이다. **지금은 하지
않는다.** 대신 오염 가능성을 기록에 적는다.

첫 회차가 이미 그 경우다 — [`runs/`](runs/) 의 1회차 기록을 볼 것.
