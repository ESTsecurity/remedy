가능성을 이 회차가 지우지 못한다(사전 기준 ③).

## r1 사전 기준의 물음 넷 — 전부 맞다

- **두 성질을 함께, 같은 레코드에.** 까닭도 적었다 — *"시각만 보면 갱신된 core.dll 이,
  크기만 보면 설치 때부터 있던 ui.dll 이 걸린다."*
- **기준을 기계에서.** capture 로 읽는다 — *"절대 시각·바이트 수를 리터럴로 적지 않는다."*
- **자를 치우지 않는다.** *"이 규칙은 remove 에 넣지 않는다(자를 치우면 제품이 실행되지
  않는다)."* 채점 5 의 남아야 하는 자리 3/3 이 그것을 쟀다.
- **시각을 `gt` 로 견준다** — 그리고 `gt` 가 초과라 같은 시각의 정상 모듈은 빠진다고 적었다.

## 새 절을 읽었는가 — 사전 신호는 있고, 사후 관찰은 **예시를 가까이 따랐다**고 말한다

| 사전에 정한 것 | 코드 | 설명 | 출처 |
|---|---|---|---|
| 기준 파일과 견준다 | 0 | 0 | 새 절 제목 |
| 레코드끼리 견줄 수 있다 | 0 | 0 | 새 절 |
| RFC3339 UTC | 0 | 0 | 새 절 |
| 자 — remove 에 넣지 않는다 (예시 주석) | 0 | 0 | 새 절 예시 |
| r1 의 지문 셋 | 0 | 0 | `20-detect` |
| **구조 신호 — capture 에 필드를 함수 없이** | **있다** | — | 새 절 예시 한 줄에만 있는 모양 |

사전에 정한 엄격한 기준(예시 주석의 문구 그대로)으로는 **"옮긴 쪽" 이 발동하지 않는다.**
그러나 사후 관찰 셋이 모두 **새 절에만 있고 위협 설명에는 없는** 것이다(꾸러미 · 위협 ·
답안 횟수):

- **capture 이름 `when` · `bulk`** — 꾸러미에서 새 절 예시 한 줄(`capture: { when:
  "mtime", bulk: "size" }`)에만 있는 이름이다. r2 는 `ref_mtime` · `ref_size`, r1 은 다른
  capture 를 썼다. **이름까지 같다.**
- **"remove 에 넣지 않는다"** — 꾸러미 1(그 예시 주석) · 위협 0 · 코드 1. 사전 지문의 앞
  토막 *"자 — "* 만 빠졌다.
- **"자로 삼"** — 꾸러미 1(새 절 본문 *"정상 파일을 자로 삼는 식이다"*) · 위협 0 · 설명 1.

그래서 **예시를 가까이 따라 쓴 쪽으로 적는다(사후 근거).** 사전 기준 ③이 걱정한 *"합격해도
판단이 아니라 옮김일 수 있다"* 가 이 회차에서는 그쪽에 가깝다. 다만 판 통제의 물음에는 이것이
오히려 답이 된다 — **4.8 이 쓴 것은 새 절 그 자체**다. *"자를 치우면"* 은 위협 설명에서 왔다
(꾸러미 1 = 위협 1).

## r2 와 무엇이 같고 다른가

짜임은 r2 와 거의 같다 — 자에서 시각 · 크기 · 폴더를 capture 하고, `from: "${…dir}"` 안에서
두 조건을 한 규칙에 걸고, 로그온 항목을 자의 폴더로 묶어 `and` 한다. 재부팅 재검사도 둘 다
선언했다. 다른 것은 **capture 이름**(위)이다 — r2 는 제 이름을 붙였고 r3 는 예시의 이름을
그대로 썼다.
