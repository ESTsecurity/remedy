# r2 — 불합격. 그런데 **우리 첫 플러그인의 결함 둘을 드러냈다**

| | |
|---|---|
| 날짜 | 2026-08-26 |
| 모델 | **Fable 5** (claude.ai 웹) — r1 과 같은 모델 |
| 오염 | **없음** |
| 입력 | 온전한 꾸러미 (문서 21개 · 122 KB) |
| 결과 | **불합격** — 계획에 빠진 Op 1건 |

```
  1. 린트          오류 0 · 경고 0
  2. 청정 코퍼스   7개 중 파괴 0개
  3. 감염 탐지     1개 중 판정 1개
    빠짐 file.quarantine_only
  4. 계획 완결성   기대 6건 중 빠짐 1건
```

**r1 과 같은 모델·같은 위협이다.** 그래서 모델 변수가 고정되고 **문서 다섯 개가
늘어난 효과만 분리된다** — 다른 벤더로 돌리는 것보다 나은 통제였다.

---

## 1. 새 문서를 읽었다

`10-manifest.md` 를 **직접 인용**했다.

> `%LOCALAPPDATA%` 는 현재 사용자 하나뿐이라, 다중 사용자 기계에서 다른 프로필의
> 감염은 from 이 상한 밖이 되어 그룹째 제외된다. 그래서 `%ALLUSERPROFILES%` 를
> 쓴다 (**10-manifest §지정 확장 토큰**).

r1 도 `%ALLUSERPROFILES%` 를 썼지만 이유가 *"verify 가 다른 계정으로 돌 수
있으므로"* 였다. r2 는 **`from` 이 상한 밖이면 그룹째 제외된다**는 정확한 기전을
댄다 — `20-detect-recipes.md` 의 내용이다.

그리고 `persistence` 에 `path` 가 없어 상한 검사를 거치지 않는다는 것도 안다.

---

## 2. 불합격 사유 — `file.quarantine_only`

`remediate.remove` 에 `{ ref: payload }` 가 없다. 재귀 삭제로 폴더를 통째
지우므로 개별 파일 제거가 불필요하다고 본 것이다.

**논리는 서지만 안전망이 사라진다.**

- 재귀 삭제는 **조건 3**(하위에 신뢰 서명 파일이 있으면 거부)에 걸릴 수 있다.
  걸리면 `deferred` 가 되고 **페이로드가 그대로 남는다**
- `file.quarantine_only` 는 risk `low` 이고 되돌릴 수 있다. `dir.delete_recursive`
  는 risk `high` 다 — **덜 위험한 경로를 빼고 더 위험한 것만 남겼다**

`22-remediate-recipes.md` 는 *"3번이 걸리면 재귀 삭제를 빼고 파일 하나하나를
`ref` 로 지운다"* 고 적었다. **"재귀 삭제를 쓰더라도 파일 `ref` 를 함께 둔다"
는 안 적혀 있다.** 그것이 빈칸이다.

---

## 3. **우리 첫 플러그인의 결함 둘을 드러냈다**

r2 가 스스로 넣은 방어 둘이 있다. 문서가 시키지 않은 것이고, **둘 다 실재하는
결함을 막는다.**

### 3-1. `capture` 가 한 단계 얕게 풀리는 것

```yaml
- { field: args, op: matches,
    value: '(?i)\\AppData\\Local\\Programs\\[^"]+\\[^\\"]+\.js("|\s|$)' }
```

> Programs 와 .js 사이에 폴더가 최소 하나 있어야 한다. 그래야 `${task.dir}` 가
> Programs 자체가 될 수 없고, 아래 재귀 삭제가 사용자 프로그램 폴더 전체를
> 겨눌 수 없다.

**첫 플러그인에는 그 제약이 없었다.** 실험했다 — 감염 스냅샷의 `args` 를
`…\Programs\loader.js` 로 바꿨더니:

```
5 dir.delete_recursive  C:\Users\test\AppData\Local\Programs
```

**`%LOCALAPPDATA%\Programs` 전체가 재귀 삭제 대상이 됐다.** 사용자가 설치한
정상 프로그램이 전부 있는 자리다.

**가드가 막지 못했다.** 설계-03 §4 조건 2(그 안에 악성 판정이 있어야 한다)는
`loader.js` 가 거기 있으므로 **통과한다.** 설계가 *"capture 해석이 어긋나 엉뚱한
상위 경로로 잡혀도 그 안에 악성 판정 파일이 없으면 막힌다"* 고 적은 방어가 이
경우엔 안 든다.

같은 스냅샷에서 **r2 는 증거 0 · 판정 0** 이다.

### 3-2. YARA 가 본문 없는 레코드를 훑는 것

```yaml
- id: payload
  where:
    - { field: path, op: ends_with, value: ".js" }   # ← 첫 플러그인에 없었다
    - { yara: "rules/evilai.yar:evilai_locust_js" }
```

> 본문은 .js 에만 담기므로 YARA 도 .js 에만 건다 — 본문 없는 레코드가 미평가로
> 남지 않게.

`collect_extra` 가 담는 것은 `payload-file`(`.js`)뿐이다. `payload` 규칙이 그
폴더의 **모든 파일**에 걸리면 나머지는 본문이 없어 **미평가**가 된다.

같은 실험에서 실제로 났다.

```
주의 'rules/evilai.yar:evilai_locust_js' 를 평가하지 못했다 — 이 관찰에 'content_ref' 가 없다
```

미평가는 미매치가 아니라 **관측 불완전**이다(종료 코드 6). 감염 폴더에 부속
파일이 함께 있는 실기기에서 나온다.

---

## 4. 이 회차가 만든 것

| 관측 | 무엇을 했나 |
|---|---|
| 재귀 삭제가 `scan_roots` 상한 자체를 겨눌 수 있다 | **계획 가드 조건 5 신설** (`guard.rs::check_recursive`) + 테스트 2건 |
| 첫 플러그인의 `args` 에 깊이 제약이 없다 | **첫 플러그인 수정** |
| 첫 플러그인의 `payload` 가 본문 범위를 넘는다 | 〃 |
| 그 둘이 가이드에 없다 | `22-remediate-recipes.md` §조건 5 · `20-detect-recipes.md` §YARA 는 본문이 담기는 것과 같은 범위여야 한다 |
| 설계-03 §4 조건 2 가 못 막는 경우 | 설계-03 §4 표에 조건 5 + 근거 |

**응시자가 우리보다 나은 판단을 했다.** 이 시험이 낼 수 있는 결과 중 가장
값진 형태다 — 가이드의 빈칸이 아니라 **제품의 빈칸**을 가리켰다.

---

## 5. 남는 것

**`file.quarantine_only` 를 빼도 되는가**는 아직 정하지 않았다. r2 의 논리에
일리가 있고, 채점은 *"기대 Op 이 전부 있는가"* 만 본다.

지금은 **빼지 않는 쪽**을 기대값으로 둔다 — 재귀 삭제가 조건 3 에 걸릴 때
페이로드가 남기 때문이다. 그 근거를 `22-remediate-recipes.md` 에 적을지는
다음 회차가 같은 선택을 하는지 보고 정한다.
