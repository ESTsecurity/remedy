## 이 회차가 쟀던 것 — 가이드만 바뀌었지만 **판도 바뀌었다**

| | r1 | r2 |

사전 기준 ②의 셋째 줄(*"r1 + 상대 비교 한 벌 → 합격"*)과 같은 모양으로 넘었다. 그러나
**두 변수(가이드 817 바이트 · 모델)가 함께 바뀌었으므로** 가이드 덕으로만 돌리지
않는다(사전 기준 ③) — `shortcut-r2` 와 같은 사정이다.

## 사전 기준의 물음 셋

**1. 상대 비교를 쓰는가 — 썼다.** 자(`base`)에서 `mtime` · `size` · 폴더를 capture 하고,
`dropped` 가 `from: "${base.dir}"` 안에서 `mtime gt` · `size lt` 를 함께 건다.

**2. 쓴다면 제대로 쓰는가 — r1 사전 기준의 물음 넷이 전부 맞다.**

- **두 성질을 함께 — 그것도 같은 레코드에.** 답안이 까닭까지 적었다: *"두 규칙으로
  나눠 `verdict` 에서 `and` 로 묶으면 … core.dll·ui.dll 이 함께 제거 대상에 든다."*
- **기준을 기계에서** — capture 로 읽는다. 절대값은 없다(*"기계마다 달라 적지 않는다"*).
- **자를 치우지 않는다** — *"치우면 제품이 못 뜨므로 remove 에도 없다"*. 채점 5 의
  남아야 하는 자리 3/3 이 그것을 쟀다.
- **시각을 `gt` 로 견준다.**

**3. 새 절을 읽었는가 — 사전 지문은 0 이다.**

| 지문 | 설명 | 코드 | 출처 |
|---|---|---|---|
| 기준 파일과 견준다 | 0 | 0 | `20-detect` 새 절 (`2d1ba53`) |
| 레코드끼리 견줄 수 있다 | 0 | 0 | 같은 절 |
| RFC3339 UTC | 0 | 0 | 같은 절 |
| 자 — remove 에 넣지 않는다 (**예시 주석**) | 0 | 0 | 같은 절 |
| r1 의 지문 셋 | 0 | 0 | `20-detect` |

- **예시를 옮기지 않았다** — 예시 주석의 지문이 0 이고, 자를 치우지 않는 까닭을 제
  말로 적었다. 짜임도 예시보다 넓다(`from` · 로그온 항목을 자의 폴더로 묶음).
- **사후 관찰 — 필드를 그대로 capture 하는 구조.** `ref_mtime: "mtime"` 처럼 필드를
  함수 없이 담아 `gt` 에 넘기는 모양은 **r1 때의 가이드에 없었고 새 절에만 있다**.
  r1 응시자가 *"숫자 필드를 변수에 담는 예도 … 없다"* 고 짚은 바로 그 자리다.
- **가이드에 없는 추론 둘** — *"`gt`·`lt` 는 엄격 비교라 자 자신은 걸리지 않는다"*
  (평가기가 Greater · Less 로 견주므로 맞다) · *"같은 레코드에 걸어야 한다"*.
