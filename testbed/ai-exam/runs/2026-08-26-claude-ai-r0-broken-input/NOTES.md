# r0 — 첫 오염 없는 회차. 입력이 깨진 채로

| | |
|---|---|
| 날짜 | 2026-08-26 |
| 모델 | claude.ai 웹 (판 미상) |
| **오염** | **없음** — 이 저장소를 읽은 적 없는 새 대화 |
| **조건** | **입력이 깨졌다** — 산문의 한글 절반이 `?` 로 소실 |
| 받았을 때 | 합격 (당시 판정 3개) |
| 지금 | **불합격** — 린트 3건 · 계획에 빠진 Op 2건 |

**이것이 이 시험의 첫 실측이다.** 앞선 r1·r2·r3 은 전부 같은 세션에서 저장소를
보며 쓴 것이었다.

`r0` 인 이유는 입력이 온전하지 않았기 때문이다. 온전한 꾸러미로 받는 회차가
`r1` 이 된다.

---

## 입력이 어떻게 깨졌나 — 응시자가 스스로 진단했다

> 번들이 UTF-8 한국어를 CP949로 잘못 읽은 뒤 UTF-16으로 저장된 상태라 한글
> 음절의 약 절반이 `?`로 소실돼 있었습니다. 다행히 JSON·YAML·정규식·YARA 같은
> ASCII 부분은 온전해서 규격의 정본과 예제는 그대로 읽었고, 산문은 문맥으로
> 복원해 읽었습니다.

절차가 `cargo xtask exam --bundle > exam-bundle.txt` 라고 적고 있었다.
**셸이 그 바이트를 세 번 손댄다** — 콘솔 코드페이지로 디코드 · 리다이렉트 기본
인코딩으로 재인코딩 · 줄 단위 재작성. 실측하니 같은 명령이 Bash 에서 93,884
바이트, PowerShell 에서 96,405 바이트를 냈다.

**고쳤다.** `xtask` 가 파일에 직접 쓴다. 두 셸이 이제 같은 93,884 바이트를 낸다.

### 그래도 이 회차는 유효하다

**설계-06 §4 가 우연히 검증됐다.** *"레퍼런스는 생성물이다"* 가 만든
`machine/*.json` 이 ASCII 라서 인코딩 사고를 견뎠고, **규격 정본은 살아남았다.**
그 결과 이 답에 **필드 수준 오류가 0건**이다. 손으로 적은 표였다면 함께 깨졌을
것이다.

그리고 **아래 두 실패는 인코딩 손상 탓이 아니다.** 산문이 온전했어도 못 찾는다 —
문서에 없었으니까.

---

## 틀린 것 — 이것이 산출물이다

세 판정을 전부 통과했는데 **계획이 2건 부족했다.** 같은 감염 스냅샷에 첫
플러그인과 나란히 걸어 대조했다.

| Action | 첫 플러그인 | r0 |
|---|---|---|
| `task.disable` · `task.delete` | ✓ | ✓ |
| **`autorun.remove`** | ✓ | **없음** |
| `file.quarantine_only` | ✓ | ✓ |
| `dir.delete_recursive` | ✓ | ✓ |
| **`av.restore_exclusions`** | ✓ | **없음** |
| | 6건 | **4건** |

**빠진 둘이 정확히 위협 설명이 경고한 것이다.** *"둘 중 하나만 지우면 나머지가
다시 살린다"* — Run 값이 남으면 재감염된다. Defender 제외도 남아 다음 검체가
같은 폴더를 그대로 쓴다.

**`deferred` 는 0건이었다.** 조용히 빠졌다.

### 원인 1 — `from` 을 `autorun`·`process` 에 걸었다

`from` 은 레코드의 `path` 필드를 읽는다. `path` 가 없는 subject 는 빈 문자열과
비교되어 **모든 레코드가 걸러진다.**

답에서 `from` 두 줄만 지우고 다시 돌려 확인했다.

| | 증거 |
|---|---|
| 원본 | `payload` · `payload-file` · `task` — 3개 |
| **`from` 제거** | 위 + **`run`** — 4개 |

응시자는 이것을 **가정으로 명시했다**: *"`from`이 file 외 subject를 어떤 기준으로
좁히는지는 정의가 없으니 이 부분은 가정입니다."* 그 정직한 보고가 원인을 찾게
해줬다.

### 원인 2 — `restore: av_exclusions` 만 쓰고 탐지 규칙을 두지 않았다

`restore: [av_exclusions]` 는 *"제외 목록을 비워라"* 가 아니라 **`av_exclusion`
증거를 되돌린다.** 그 subject 규칙이 없으면 되돌릴 것이 안 잡히고 Action 이 아예
안 나온다.

응시자: *"(c) `av_exclusion`의 `kind` 값 집합 — 없어서 탐지 규칙 없이
`restore: av_exclusions`만 썼습니다(우리 경로만 빼는 문서화된 레인)."*

**"문서화된 레인" 이라고 읽은 것이 문서 탓이다.** 가이드가 무엇을 되돌리는지
말하지 않았다.

## 잘한 것

- **`collect_extra` 를 `payload-file`(경로 매치)로 정확히 가리켰다** — 순환을
  피했다. 23번 문서가 효과가 있었다
- **`submit_hint.confidentiality_min: 1`** 을 근거와 함께 올렸다 — *"검체 경로에
  사용자 계정명이 들어간다"*
- YARA 룰 머리의 전역 스캔 금지 경고를 `from: "${task.dir}"` 로 지켰다
- 오탐 후보를 **제품 이름으로** 댔다 (VS Code·Cursor·Volta·nvm) — 40-review
  checklist 2번이 요구하는 형태
- **자기 가정 다섯 개를 명시적으로 나열했다**(a~e). 그중 (a)가 이 결함의 원인을
  가리켰고 (e)는 우리 문서의 오류를 잡았다
- 서명 전 확인 절차를 스스로 제안했다 — *"`groups`에서 `run`·`proc`가 task
  그룹의 자식으로만 붙고 깨끗한 쪽은 0건인지 확인하기 전에는 서명하지 않는
  것이 맞습니다"*

### 우리 문서의 오류를 잡았다

> (e) `30-antipatterns.md` §8은 process에 `command`를 쓰지만 정본
> `subjects.json`에는 `image_path`·`cmdline`·`args`뿐이라 정본을 따랐습니다.

**맞다.** 거부 예제도 **"올바른 형태" 예제도** `process` 에 `command` 를 쓰고
있었다. AI 는 예제를 패턴으로 복제하므로(설계-06 §5) 정답 예제가 틀린 것이 더
나쁘다. 고쳤다.

## 이 회차가 만든 것

| 관측 | 무엇을 했나 |
|---|---|
| `from` 이 통하는 subject 가 문서에 없다 | `20-detect-recipes.md` §`from` 은 `path` 가 있는 subject 에만 통한다 |
| `where` 값의 `${}` 보간 예제가 가이드에 **0건**이었다 | 〃 §경로가 아닌 것을 부모에 묶는 법 |
| `restore` 가 무엇을 되돌리는지 없다 | `22-remediate-recipes.md` §되돌릴 **증거**가 있어야 한다 |
| 안티패턴 8의 필드가 틀렸다 | `30-antipatterns.md` §8 수정 |
| 두 결함 다 린트가 못 잡았다 | `check_from_subject` · `check_restore_named` 신설 |
| **채점이 무엇을 지우는지 안 봤다** | **채점 4번 신설** — `expected-ops.txt` |
| 절차가 셸에 따라 다른 입력을 냈다 | `--bundle` 을 파일 직접 쓰기로 |

지금 다시 채점하면 이렇게 나온다.

```
    remediate.restore[0] :: 'av_exclusions' 은 av_exclusion 증거를 되돌리는데
                            그 subject 를 탐지하는 규칙이 없다
    detect[run].from  :: subject 'autorun' 에는 path 필드가 없어 from 이 통하지 않는다
    detect[proc].from :: subject 'process' 에는 path 필드가 없어 from 이 통하지 않는다
  1. 린트          오류 3 · 경고 0
  2. 청정 코퍼스   7개 중 파괴 0개
  3. 감염 탐지     1개 중 판정 1개
    빠짐 autorun.remove
    빠짐 av.restore_exclusions
  4. 계획 완결성   기대 6건 중 빠짐 2건

실패: 불합격 — 린트 오류 3건 · 계획에 빠진 Op 2건
```

**합격 출력은 이 회차를 받았을 때의 것이고, 그대로 뒀다.** 지우면 채점이 무엇을
못 봤는지가 사라진다.
