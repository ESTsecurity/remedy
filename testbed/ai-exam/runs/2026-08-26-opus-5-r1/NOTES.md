| | |
|---|---|
| 날짜 | 2026-08-26 |

| 결과 | **불합격** — 감염 스냅샷에서 판정이 서지 않음 |
| 오염 | **있음.** 아래 *"오염"* 절 |

```
  1. 린트          오류 0 · 경고 0
  2. 청정 코퍼스   7개 중 파괴 0개
  3. 감염 탐지     1개 중 판정 0개

```

## 왜 틀렸나 — 응시자가 아니라 문제가 틀렸다

`verdict.require` 가 `task and payload` 인데 `payload` 가 서지 않았다. 그 규칙은
YARA 에 걸려 있었고, 그 YARA 룰은 위협 설명이 준 특징으로 썼다.

**위협 설명이 실제 검체와 달랐다.** 1 회차의 `THREAT.md` 는 첫 플러그인
매니페스트에서 **역산해** 쓴 것이었다 — 검체도 코퍼스도 보지 않고. 감염
스냅샷을 열어 보니 다섯 항목이 어긋나 있었다.

| `THREAT.md` 가 쓴 것 | 스냅샷 실측 |
|---|---|
| 런타임과 스크립트가 같은 폴더에 있다 | `node.exe` 는 `C:\Program Files\nodejs\` — **시스템 설치본을 빌려 쓴다** |
| 폴더 전체가 검체가 만든 것(런타임 + 부속 파일) | 그 폴더에 `.js` **하나**, 254 바이트 |
| `Buffer.from(...,'base64')` · `child_process` · 원격 주소 | **본문에 0 건.** 평문 IOC 가 아예 없다 |
| 정상 라이브러리를 흉내 낸 주석 | 없다. `'use strict'` 로 시작한다 |
| `node.exe` 프로세스가 떠 있다 | 스냅샷에 프로세스 **0 건** (수집 시점에 트리거 전) |

내 YARA 룰은 `Buffer.from` · `child_process` · `exec(` 를 찾았다. **검체에 그런
문자열이 하나도 없다.**

## 관측 — 이것이 이 회차의 산출물이다

### 1. 시험 문제와 채점 데이터가 어긋나면 시험이 아니다

응시자가 무엇을 하든 통과할 수 없는 문제였다. **위협 설명은 채점에 쓰는 코퍼스
에서 실측해 써야 한다.** `THREAT.md` 에 그 규칙을 못 박았다.

### 2. YARA 상수 도출은 룰 작성자의 일이 아니다

실검체 룰을 열어 보고 알았다 — 이 검체는 **평문 IOC 가 0 건**이고, 룰은 커스텀
알파벳 base64 로 인코딩된 상수 **90 개를 열거하고 임계값 20** 을 쓴다. 그 상수는
검체 16 건을 손에 쥐고 교차 분석해야 나온다.

**위협 설명이 아무리 정확해도 여기서 룰을 재도출할 수는 없다.** 시험 범위가
잘못 잡혀 있었다.

→ 분석가가 도출한 `threat-rules/evilai.yar` 를 **함께 주는** 것으로 바꿨다.
실제 작업 흐름과도 이쪽이 맞다 — 분석가가 검체를 돌려 룰을 뽑고, 룰 작성자가
매니페스트를 쓴다. 그래도 시험은 남는다: 규격 준수 · `from` 으로 범위 좁히기 ·
청정 코퍼스 0 건 · 치료 선언.

### 3. AI 는 틀린 위협 설명을 검증하지 않는다

위협 설명이 준 특징을 그대로 YARA 문자열로 옮겼다. **검체를 볼 수 없으므로
확인할 방법도 없었다.** 위협 설명이 틀리면 룰은 오류 없이 조용히 안 맞는다 —
린트도 청정 코퍼스도 통과한다. 채점 3 번이 없었다면 **합격으로 보였을 것이다.**

### 4. 관측된 것보다 좁게 썼다

위협 설명은 *"문자열 배열 하나를 만들어 놓고 인덱스로 꺼내 쓴다"* 고만 했는데,
나는 그것을 이렇게 옮겼다.

```
$arr = /var _0x[0-9a-f]{4,6}\s*=\s*\[/
```

`_0x` 는 obfuscator.io **기본 설정**의 출력 형태다. 위협 설명에 없는 세부를
"흔한 형태" 라는 이유로 덧붙였다. 실제 검체의 변수명은 `F` 였다.

**설명에 없는 것을 채워 넣으면 룰이 좁아진다.** 좁은 룰은 오탐이 아니라 미탐을
낳고, 미탐은 시험에서 잘 안 보인다.

## 오염

**이 회차는 오염됐다.** 답을 쓴 모델이 같은 세션에서 이 저장소를 작업 중이었고,
`plugins/evilai-locust/plugin.yaml` 을 **출제 직전에 읽었다**(위협 설명을 쓰기
위해). 매니페스트 구조가 기억에 남은 상태로 답을 썼다.

그래서 **1·2 번 판정의 통과를 실력으로 읽으면 안 된다.** 반대로 **3 번의 실패는
오염과 무관하다** — 오염된 지식으로도 통과하지 못했다는 뜻이고, 그것이 문제 쪽
결함을 가리켰다.

읽지 않은 것: `plugins/evilai-locust/rules/evilai.yar` (답을 낸 뒤 진단 단계에서
처음 열었다) · 감염 코퍼스 스냅샷.
