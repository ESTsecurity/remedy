## r1 과 달라진 자리 — 세 곳

### 1. 열쇠 파일을 줄에서 뽑지 않고 리터럴로 적었다 ← 간판

```yaml
  r1   keyfile: "line | first_path"          → AuthorizedKeysFile (경로가 아니다)
  r2   - { field: path, op: starts_with, value: "/etc/ssh/.maint/" }
```

r1 을 넘어뜨린 바로 그 자리다. 새 문장이 *"공백으로 쓰는 설정에서는 둘 다 비므로
그 자리는 리터럴로 적는다"* 고 적고, 답안이 그대로 했다.

### 2. `from` 을 쓰지 않았다 — 그래서 그룹 제외가 일어날 자리가 없다

r1 은 자식 넷에 `from: "${부모.dir}"` 를 달았고, 그중 하나가 빈 경로가 되어 그룹이
제외됐다. r2 는 자식을 **`where` 의 보간**(`path equals "${cron.bin}"`)으로만
묶었다. `from` 이 없으니 파생 경로가 상한을 넘을 일이 없고, 그룹이 제외될 길 자체가
없다.

**답안이 그 이유를 적지는 않았다.** 그룹 문단의 흔적이 없으므로, 이것을 *"그룹
공유를 알고 피했다"* 로 읽지 않는다 — **결과적으로 피했다**로 적는다.

### 3. `first_path` 를 경로에만 썼다

```yaml
  bin:     "command | first_path"    # command 는 경로다
  deffile: "source | first_path"     # source 는 경로다
  cfgfile: "path | first_path"       # path 는 경로다 (항등)
```

39줄이 *"first_path 는 첫 토큰만 취해 args 를 떼어낸다"* 고 적는다. 첫 토큰이
경로인 필드에만 썼다.

## 정답과 다른 것

| | 정답 | 이 답안 |
|---|---|---|
| 페이로드·정기 작업 자리 | 리터럴(`path in [...]`) | **증거에서 파생**(`${cron.bin}` · `${cron.deffile}`) |
| 열쇠 파일 | 리터럴(`path in`) | 리터럴(`starts_with ".maint/"`) |
| 판정식 | `keyfile_line and reinstall` | 두 갈래의 **논리합** |
| 압력 | 91,339 | 48,971 |

**답안은 r1 의 "전부 파생하려는" 방향을 유지하되, 파생할 수 없는 자리 하나만
리터럴로 바꿨다.** 그것이 새 문장이 권한 정확히 그 일이다.

`keyfile` 이 `starts_with ".maint/"` 라 그 폴더의 다른 파일도 걸릴 수 있다 — 이
기계에는 `keys` 하나뿐이라 기대 밖 0 이다. 정답은 `path in` 으로 한 파일을 짚는다.

1. **가이드 수정의 효과를 가장 깨끗하게 쟀다.** 같은 모델 · 같은 채점 자료 · 다른
   것은 877 바이트뿐이고, 불합격이 합격으로 바뀌었다. 답안이 그 문장을 절 이름으로
   인용했다.
2. **사전 기준의 진단 행이 결과를 맞혔다.** *"r1 구조 + sshd 자리만 리터럴 →
   합격"* — 받기 전에 적어 둔 그대로다.
3. **그룹 문단은 이 회차로 판정하지 않는다.** 흔적이 없고, 답안은 `from` 을 안 써
   그 문단이 잡을 자리를 만들지 않았다. 사전 기준 ③이 미리 그렇게 적었다.
4. **한 회차는 한 표본이다.** 같은 판도 같은 답을 두 번 내지 않는다. 이 결과를
   *"문장 하나면 언제나 넘는다"* 로 일반화하지 않는다.
