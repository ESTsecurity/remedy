## 중심 물음에 답했다 — 미끼를 보고 술어 둘을 곱했다

사전 기준 ②가 물은 것은 하나였다. 감염 스냅샷에 정답의 경로 정규식과 같은
모양인 서비스가 **둘**이고, 하나는 정상 벤더의 것이다.

| 서비스 | 시작 유형 | |
|---|---|---|
| `AcmeUpdater` (`Acme Update Service`) | **manual** | 정상 |
| `SvcHostCache` (`Host Cache Service`) | auto | 검체 |

답안 47~58줄.

```yaml
all:
  # 조사된 정상 벤더 서비스(Acme Update Service)는 수동 시작이었다.
  - { field: start_type, op: equals, value: "auto" }
  - { field: image_path, op: matches,
      value: '(?i)\\ProgramData\\[^\\"]+\\[^\\"]+\.exe("|\s|$)' }
```

**미끼를 이름으로 짚고 그것을 `auto` 술어의 이유로 적었다.** 함정이 설계대로
작동했고 응시자가 그것을 보았다.

### 계획을 손으로 읽었다 (③의 약속)

```
service.clear_recovery · stop · disable · delete   HKLM\…\Services\Host Cache Service
file.quarantine_only    …\SvcHostCache-3f8a\svc.exe
file.quarantine_only    …\SvcHostCache-3f8a\cache.db
dir.delete_recursive    C:\ProgramData\SvcHostCache-3f8a

```

**Action 8건 · 겹침 0 · 보류 0 · 미끼 없음.** 사전 기준이 걱정한 자리
(`extra` 가 불합격이 아니라 미끼를 죽여도 합격한다)는 이번에 발동하지 않았다.

## 두 번째 함정도 피했다 — `state`

이 위협의 합성 스냅샷은 한때 서비스 상태를 `running`·`stopped` 로 적었다.
**수집기는 그런 값을 낸 적이 없다** — 실행 여부는 레지스트리에 없어 언제나
`unknown` 이다(2026-09-04 에 픽스처를 실기기로 옮기며 고친 자리).

답안 41~43줄이 그것을 먼저 말한다.

> `state` 를 조건에 넣지 않는다 — 수집기가 살아 있는 서비스 관리자에게 묻지
> 않아 이 필드는 어느 기계에서도 `unknown` 이다. **보고서의 "실행 중" 은
> 데이터에 없다.** `running` 으로 비교하면 술어가 언제나 거짓이 된다.

위협 설명은 그 서비스가 돌고 있다고 적는다. **관측 보고의 문장과 스냅샷의
필드가 다르다는 것을 알아채고 데이터 쪽을 따랐다.**

## 산출물 — **응시자가 자기 검증 절차를 적었고, 그것이 맞았다**

`answer.md` 의 마지막 절.

> **서명 전에 확인할 것.** `scan_roots` 의 `%PROGRAMDATA%` 는 넓다는 경고가
> 날 수 있다 — 페이로드 폴더 이름이 감염마다 바뀌어 부모를 적을 수밖에 없다는
> 것이 그 이유다. **코퍼스는 이것을 재지 못하므로**(스냅샷은 이미 수집된
> 것이다) 실기기 `scan` 을 한 번 돌려 `file` 수집이 상한에 잘리지 않는지,
> `registry_value` 가 0건이 아닌지 확인해 첨부한다.

세 가지를 스스로 했다 — **받을 경고를 예측하고**, **코퍼스가 그것을 못 잰다는
것을 알고**(평가가 스냅샷의 상한을 쓴다), **무엇을 확인해야 하는지 이름으로
적었다.**

그대로 돌렸다. 청정 `Win10x64-Test`:

| | |
|---|---|
| 종료 코드 | **0** |
| `truncated` | **false** |
| `file` | 5,553 (상한 50,000) |
| `registry_value` | **35** (0건이 아니다) |

**두 예측이 다 맞았다.** 이 위협은 `structured_config` 를 쓰지 않아
`appinit-r3` 이 밟은 종료 코드 6 이 없다.

지난 네 회차 동안 그 실기기 확인은 **내가 채점하며 하던 일**이었다. 응시자가
그것을 답안에 적은 것은 처음이다.

## 그 밖에 정답보다 나은 자리

**정규식의 꼬리.** 정답은 `\.exe$` 이고 이 답안은 `\.exe("|\s|$)` 다.
`ImagePath` 가 따옴표로 묶이거나 인자를 달고 오는 경우까지 잡는다.

**재귀 삭제의 조건 5 를 설계로 만족시킨다.** 경로 정규식이 ProgramData 아래
폴더 **한 겹**을 요구하므로 `dirname` 이 상한 자체(`%PROGRAMDATA%`)로 풀리지
않는다. 그 이유를 주석에 적었다.

**개별 파일 `ref` 를 함께 둔 이유.** 바이너리가 이미 지워진 기계에서는 재귀
삭제만 미뤄지고 나머지 치료는 그대로 수행된다 — `guard` 의 거동을 알고 썼다.

## 못 재는 것

- **`payload-process` 는 이 스냅샷에서 한 번도 서지 않는다.** 감염 스냅샷에
  `process` 레코드가 없다. 규칙 하나가 시험되지 않은 채 통과했고, 그것은
  답안의 잘못이 아니라 재료의 성질이다.
- **`extra` 는 여전히 불합격 사유가 아니다.** 이번에는 발동하지 않았지만
  미끼를 죽이는 답안이 합격하는 구조는 그대로다.
- **실기기 `apply` 는 돌리지 않았다.** `scan` 까지다.
- 표본이 하나다. 이 위협의 네 회차는 재료가 달라 나란히 놓을 수 없다.
