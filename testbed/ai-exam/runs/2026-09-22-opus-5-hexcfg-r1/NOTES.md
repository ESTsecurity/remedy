**치료 후 기계 상태가 정답의 것과 sha256 까지 같다** (`03bcc2e7af47…`). 청정·

압력 265건은 정답과 같은 수다 — 뿌리 규칙이 설정 항목 하나이고 나머지 둘이
부모에 묶여 있기 때문이다. 사전 기준이 신호로 적어 둔 그대로다.

### ③의 가장 큰 구멍을 피했다 — 기계로 확인했다

사전 기준 ③이 *"위협 설명이 풀어 낸 결과를 평문으로 보여 주므로, 그것을 그대로
박은 답안이 자동 다섯을 전부 통과한다"* 고 적었다(변형 실측). 그래서 **사람이
매니페스트를 읽어야** 갈린다. 주석을 뺀 본문에서:

```
  libnetcache                     0회
  libNetCache                     0회
  /usr/lib/nodewatch/plugins      0회
```

`where` 의 `value` 는 일곱 개뿐이고 전부 **벤더 설정 파일 이름 · 키 이름 ·
16진 정규식 · `${relay.name}` 보간**이다. 검체의 폴더도 파일 이름도 없다.

## 정답에 없는 것 넷

| | 정답 | 이 답안 |
|---|---|---|
| 설정 파일 지목 | 없다 (`scan_roots` 에 맡긴다) | **`path ends_with "/nodewatch/agent.json"`** · 목록도 같다 |
| 판정식 | `cfg and payload` | `relay and (entry **or** payload)` |
| 재검사 | 없다 | `verify.after_reboot: true` |
| 권한 상한 | `/usr/lib/nodewatch/plugins` | `/usr/lib/nodewatch` — **한 단계 넓다** |

**첫째는 답안이 더 좁다.** 상한 안에 설정 파일이 둘뿐이라 결과는 같지만, 조건이
스스로 자리를 못박아 상한이 넓어져도 안 흔들린다.

**둘째는 트레이드오프이고 답안이 근거를 적었다** — *"다른 백신이 `.so` 만
잡아간 기계에서 설정 둘이 남아 에이전트가 매 기동마다 없는 것을 부른다"*.
근거 둘의 논리곱은 유지된다(`relay` 는 언제나 필요하다). 감염 스냅샷에서는
셋이 다 서므로 점수 차이가 없다.

**셋째에서 실측이 하나 나왔다 — 아래.**

**넷째는 답안이 더 넓고, 그 한계를 스스로 적었다** — *"검체가 설치 트리 밖에
떨어뜨린 변종은 파생 경로가 상한을 벗어나 제외된다. `/usr/lib` 로 넓히면 읽기와
삭제 권한이 함께 커지므로 그 관측이 나오기 전에는 넓히지 않는다."*

## 이 회차가 드러낸 것 둘 (제품·채점기 쪽, 답안의 흠이 아니다)

### 1. `after_reboot` 이 리눅스에서 예약되지 않는다

답안이 `verify.after_reboot: true` 를 걸었다. **위협 픽스처 스무 개 중 어느
것도 리눅스에서 이 자리를 밟은 적이 없다** — 이 답안이 처음 밟았다. 실기기
로그(`results/exam-apply-hexcfg-r1-answer/run.log`):

```
  계획 화면   * 치료를 마친 뒤 이 PC 를 재시작하면 자동으로 한 번 더 검사합니다.
  실행 뒤     주의: 재평가를 예약하지 못했다 (이 플랫폼에서는 지원되지 않는다:
              이 백엔드는 재부팅 후 검증을 예약하지 않는다). 재부팅 뒤
              `remedy verify --run … --plugin …` 를 직접 부를 것
```

**계획 화면이 약속하고 실행이 못 한다.** 주의를 내므로 조용히 지나가지는
않고, 채점 5도 이것 때문에 떨어지지 않았다(종료 1 · 합격). 범위 밖이라
고치지 않고 적어만 둔다.

### 2. 청정 코퍼스에 `nodewatch` 기계가 없다 — 답안이 먼저 지적했다

답안 설명문: *"`scan_roots` 가 이 제품의 두 디렉터리뿐이라 nodewatch 가 없는
기계에서는 뿌리 규칙이 마주하는 레코드가 0건이다. 그래서 청정 코퍼스의 '파괴
0건' 은 이 룰을 시험한 적이 없다는 뜻이기도 하다."*

**확인했다.** 청정 스냅샷 28장을 풀어 훑어 `nodewatch` 가 든 것은 **0장**이다.

채점기가 찍는 265건은 `scan_roots` 를 적용하지 않은 수다 — 정답과 답안 모두
nodewatch 전용 상한인데 둘 다 265건이 나오기 때문이다(실측 둘). 즉 뿌리 규칙이
설정 레코드 265건을 마주해 전부 떨어뜨린 것은 맞지만, **그중 nodewatch 의 정상
설치는 한 건도 없다.** 이 위협의 오탐 안전은 아직 재어지지 않았다.

답안이 걸릴 수 있는 정상 구성까지 하나 댔다 — *"관리자가 `relay.module` 에
16진으로 경로를 손수 적어 둔 nodewatch 기계"*.

## 이 회차가 남긴 것

1. **감춘 값을 푸는 위협이 실제로 그렇게 풀렸다.** 모델이 레퍼런스의 함수
   목록에서 셋을 골라 순서까지 맞혀 이었다 — 가이드에 조립 예제가 없는데도.
2. **사전 기준이 미리 못박은 "자동으로 안 갈리는 자리" 가 실제로 쓸모 있었다.**
   변형 실측이 없었다면 "합격" 만 보고 받아쓰기와 구별하지 못했을 것이다.
3. **채점 5 를 응시자 답안으로 리눅스에서 처음 돌렸다.** `--plugin <답안>` ·
   `--record` 없이. 하네스가 `--record` 와 `--plugin` 을 함께 주면 거부한다.
4. **코퍼스에 구멍이 하나 있다** — 위협이 가리키는 제품의 **정상 설치** 스냅샷.
   답안이 그것을 먼저 말했다.
