## 채점 — **합격**

```
  1. 린트          오류 0 · 경고 0
  2. 청정 코퍼스   16개 중 파괴 0개
  3. 감염 탐지     1개 중 판정 1개
  4. 계획 완결성   기대 7건 중 빠짐 0건
```

**응시자 답안으로 두 번째 무경고 합격**이다(첫 번째는 `tls-r1`). 폭 경고를
피한 이유는 상한을 `%PROGRAMDATA%` 가 아니라 `%PROGRAMDATA%\WebBoost` 로
잡았기 때문이다 — 앞선 세 회차가 전부 맞던 자리다.

> 채점 숫자는 **위협을 고친 뒤**의 것이다. 받을 때는 기대 5건이었고, 이
> 답안이 우리 위협의 결함을 드러내 6건 → 7건이 됐다. 아래 참조.

## 채점 전에 적어 둔 기준 — 그대로 옮긴다

**① 무엇이 달라졌는가** — 새 위협이라 비교 대상이 없다. 대신 이 위협이 처음
요구하는 것은 **`edit` 절**이다. `22-remediate-recipes.md` §edit 는 2026-09-01
에 넣었고, `appinit-implant` 는 일부러 그것이 필요 없게 지었다(값 전체가 검체
것이라 `remove` 가 정답). 두 위협이 같은 질문의 양쪽을 묻는다.

**② 무엇을 보면 통했다고 할 것인가** — 답안이 경로 목록과 부팅 목록을
`remove` 가 아니라 **`edit`** 에 넣는가. `remove` 에 넣으면 린트·코퍼스·판정을
전부 통과하고 **채점 4번에서만** 갈린다(`tls-intercept` 와 같은 모양).
그리고 정상 확장 넷과 `bootalyac.exe` 가 남아야 한다.

**③ 못 재는 것** — `browser_extension` 압력이 4건(스냅샷 1개), `proxy_config`
는 1건이다. 정상 확장을 함께 지우는 답안은 잡히지만 더 미묘한 오탐은 못
잡는다. 표본 하나다.

## ②가 충족됐다 — 그리고 값을 증거에서 파생시켰다

```yaml
edit:
  - { ref: pathvar,  op: strip, value: "${svc.dir}" }
  - { ref: bootexec, op: strip, value: "${wbb.entry}" }
```

> 통째로 지우면 기계를 못 쓰게 되는 값들이다. 값을 남기고 덧붙은 부분만 뺀다.
> **두 value 모두 증거에서 파생됐다** — 리터럴 문자열로 임의 편집을 지시하지
> 않는다.

**우리 정답은 리터럴을 썼다**(`"C:\ProgramData\WebBoost;"` · `"wbboot.exe"`).
답안이 낫다. `${wbb.entry}` 는 `path | basename` 으로 뽑은 것이라 파일 이름이
바뀌는 변종에서도 맞는다.

정상 항목도 전부 지켰다 — 확장은 `ext_id` 하나로만 갈랐고(*"브라우저·프로필
이름으로 고르면 같은 자리에 사는 정상 확장이 함께 없어진다"*), 부팅 목록은
`wbboot.exe` 를 담은 값만 짚었다.

## 이 회차의 산출물 — **답안이 우리 위협의 결함을 찾았다**

답안이 프로세스 규칙을 세우고 `process.kill` 을 걸었다.

```yaml
- id: proc
  subject: process
  where:
    - { field: image_path, op: starts_with, value: "${svc.dir}" }
```

그런데 우리 `expected-ops.txt` 는 그것을 **빼면서 이렇게 적고 있었다.**

> `process.kill` : 보고가 실행 중인 프로세스를 관측하지 않았다. 되돌릴 수
> 없는 Op 을 관측 없이 열지 않는다.

**THREAT.md 34행은 정반대를 적는다.**

```
wbsvc.exe     1,245,184 바이트    상주하며 광고를 받아 온다
```

**문제와 채점 데이터가 갈라져 있었다** — 출제자 주의 2번을 출제자가 어겼다.
1 회차를 무너뜨린 그 규칙이다. 이번엔 감염 스냅샷에 `process` 레코드가 없어
그 규칙이 0건을 맞혔고, 그래서 채점이 **어느 쪽으로도 말하지 않았다.**
답안은 벌을 받지 않았지만 우리 자료는 어긋난 채였다.

### 어느 쪽으로 고쳤나

보고가 상주를 말하므로 **위협 쪽을 맞췄다.** 되돌릴 수 없는 Op 은 근거가
있어야 연다는 원칙은 그대로고, 달라진 것은 **근거가 보고에 실제로 있다**는
사실이다.

- 감염 스냅샷에 `process` 2건을 넣었다(검체 하나 · `explorer.exe` 하나).

> **2026-09-02 정정.** 처음에는 `cmdline` 을 비워 두고 *"실기기 수집기가 WMI 로
> 명령줄을 받아 오지 못한다"* 고 적었다. **틀렸다.** `record.rs` 의 실측이
> 적은 것은 *"145개 중 **19개**가 비었다"* 이고, WMI 이야기는 그 19개에
> 대해서만 0개였다는 뜻이다 — OS 가 **보호 프로세스**의 명령줄을 아무에게도
> 주지 않는다는 말이지 전부 빈다는 말이 아니다.
>
> 청정 코퍼스 실측: Windows 307개 중 **269개**에 `cmdline` 이 있고, 빈 38개는
> 전부 Defender·ALYac·nProtect·`SecurityHealthService` 같은 보호 프로세스다.
> 광고 임플란트는 그 부류가 아니므로 명령줄이 읽힌다. 픽스처를 실기기 모양
> (`cmdline`·`cmdline_decoded`·`args`·`user` SID)으로 고쳤다.
- `expected-ops.txt` 에 `process.kill` 을 넣고 경위를 적었다.
- 정답 플러그인에 프로세스 규칙을 더했다.

### 그 뒤를 `file.delete_on_reboot` 이 따라왔다

프로세스 레코드가 생기자 계획기가 파일을 다르게 다뤘다.

```
기대 밖 file.delete_on_reboot
```

`removal_ops_for` 가 `locked_by_a_process` 로 *"이 파일을 물고 있는 프로세스
**증거**가 있는가"* 를 보고, 있으면 격리 대신 재부팅 삭제로 간다.

**공짜가 아니다** — 그 증거는 플러그인이 잡은 것이라, **프로세스를 탐지한
플러그인만** 이 Op 을 받는다. 그래서 기대 목록에 넣었다. 이 검체의 두 파일이
그렇게 갈린다.

| 파일 | 도는가 | Op |
|---|---|---|
| `wbsvc.exe` | 그렇다 | `file.delete_on_reboot` |
| `wbboot.exe` | 아니다 | `file.quarantine_only` |

**Op 진도 22 → 24/29.** 한 회차가 둘을 밟았고, 둘 다 우리가 "일곱 번째 위협
재료" 로 미뤄 뒀던 것이다.

## 답안이 우리보다 나은 자리 둘

- **확장 상한을 `%ALLUSERPROFILES%` 로 폈다.** 우리 정답은 `%LOCALAPPDATA%`
  였다 — *"확장은 사용자마다 설치되므로 보통 환경변수를 쓰면 현재 로그온
  사용자만 치료되고 나머지 사용자는 감염된 채 남는다."* 맞다. 정답을 고쳤다.
- **`edit` 의 `value` 를 증거에서 파생시켰다**(위 참조).

`User Data` 가 아니라 `Extensions` 까지 내려 잡은 이유도 적었다 — *"쿠키·기록·
로그인 정보까지 읽을 수 있게 되고, 그것은 이 룰이 필요로 하는 범위가 아니다."*
우리가 코퍼스 상한을 고를 때 든 이유(json 폭발)와 다른 각도인데 결론이 같다.

## 그밖에 밟은 것

- **`proxy_config.scope: "user"`** — **이 회차를 넘기기 직전에 닫은 값 전수**다.
  HKLM 쪽을 `machine` 이라 적기 쉬운 자리인데 맞췄다.
- **괄호 판정식** — `"(svc or ext) and (pathvar or bootexec or proxy)"`.
  2026-09-02 에 `31-nonexistent.md` 에 문법 전수를 적기 전까지 예가 0건이던
  형태다. 이유도 적었다 — *"확장 하나만으로는 서지 않는다. 스토어에서 받은
  확장을 지우는 룰이 되면 안 된다."*
- **파일 크기·확장 판을 조건에 넣지 않았다** — *"재빌드 한 번에 바뀌므로.
  좁은 룰은 오탐이 아니라 미탐을 낳고, 미탐은 아무도 잡아 주지 않는다."*
- `confidentiality_min` 을 올린 이유가 구체적이다 — *"계획·보고에 브라우저
  프로필 경로가 실리고 거기에 사용자 계정명이 들어간다."*

## 못 재는 것

- ③에 적은 그대로다. `browser_extension` 4건 · `proxy_config` 1건은 얇다.
- **이 회차의 채점 숫자는 위협을 고치기 전후가 다르다.** 받을 때 기대 5건,
  지금 7건이다. 답안은 그대로이고 **우리 기대가 자란 것**이므로 이 회차를
  "7건을 맞혔다" 로 읽으면 안 된다 — 정확히는 *"답안이 이미 갖고 있던 것이
  기대에 들어왔다"* 다.
- 표본 하나다.
