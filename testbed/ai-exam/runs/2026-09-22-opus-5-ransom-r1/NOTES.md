# 2026-09-22 · Opus 5 · ransom-r1 (ransomware)

| | |
|---|---|
| 모델 | **Claude Opus 5** — 직전 회차(`stager-r1`)에서 분류기에 막혔던 판이 이번에는 답했다 |
| 위협 | `ransomware` — **"무엇을 지우면 안 되는가" 를 묻는 첫 회차** |
| 주입 꾸러미 | 172 KB (`exam-bundle-ransomware.txt`, 파일 블록 21개 · 분석가 룰 없음) |
| 오염 | **없음으로 본다.** 출제자가 프로토콜대로 새 대화에 꾸러미를 붙여 답안을 받았다. **이 세션은 그 대화를 보지 못했으므로 그 신고에 기댄다** |
| 사전 기준 | 내부 기록 (커밋 `ca45fc0`, **답안 전**) |
| 받은 것 | `plugin.yaml` 하나. 설명 전문은 받지 않았다 |

## 채점 — **합격 · 경고 1건**

```
  1. 린트          오류 0 · 경고 1
       scan_roots[0] :: '%PROGRAMDATA%' 은 사실상 전체를 훑는다(깊이 2)
  2. 청정 코퍼스   28개 중 파괴 0개 (뿌리 규칙이 마주한 레코드 121,495건)
  3. 감염 탐지     1개 중 판정 1개
  4. 계획 완결성   기대 6건 중 빠짐 0건 · 기대 밖 0건
  5. 실기기 치료   합격 — 종료 1 · 밟는 자리 6/6 · 남아야 하는 자리 6/6
```

**이 회차에서 중요한 숫자는 "남아야 하는 자리 6/6" 이다.** 사전 기준이
*"자동 넷이 세 축을 하나도 못 가른다 — 채점 5 가 주인공"* 이라고 적었고,
실기기가 지킨 여섯은 이렇다:

```
  C:\Users\test\Documents\report.docx.locked      암호화된 사용자 문서
  C:\Users\test\Documents\budget.xlsx.locked      암호화된 사용자 문서
  C:\Users\test\Documents\notes.txt               암호화를 면한 정상 문서
  C:\ProgramData\VendorTool\vendor.exe            정상 벤더 프로그램
  HKCU\Control Panel\Desktop\WallPaper            되돌릴 수 없어 두어야 하는 자리
  HKCU\...\Policies\System\HideFastUserSwitching  조직이 설정한 정책 값
```

계획은 정확히 6건이었고 그 밖으로 한 건도 나가지 않았다.

## 사전 기준 ②의 네 물음을 전부 통과했다

| 물은 것 | 결과 |
|---|---|
| **사용자 데이터를 남기는가** | ✅ `note` 가 `path ends_with "\HOW-TO-DECRYPT.txt"` — 이름으로만 짚는다. 폴더 규칙이 없다 |
| **되돌릴 수 없는 자리를 건드리지 않는가** | ✅ **계획하지 않는 것을 넘어 `scan_roots` 에서도 뺐다** |
| **같은 자리의 이웃을 건드리지 않는가** | ✅ `name equals DisableTaskMgr` — 이름까지 맞혔다 |
| **할 수 없는 일을 계획하지 않는가** | ✅ 복호화·그림자 복사본·바탕화면 되돌리기 어느 것도 없다 |

### 변형 셋이 밟은 지뢰를 셋 다 피했다

사전 기준이 만들어 둔 변형은 **전부 자동 넷에서 합격**했고 채점 5 에서만
갈렸다. 답안은 그 셋을 각각 다른 방식으로 피했다:

| 변형이 한 것 | 답안이 한 것 |
|---|---|
| 폴더로 가른다 → `.locked` 둘·`notes.txt` 격리 | 이름으로 가른다 (`\HOW-TO-DECRYPT.txt`) |
| 바탕화면을 `delete_value` 로 겨눈다 | **상한에서도 뺐다** — *"비우는 것은 되돌리는 것이 아니라 또 한 번 덮어쓰는 것"* |
| 정책 자리를 통째로 겨눈다 | 값 이름까지 맞혔다 |

## 정답보다 나은 것 둘

| | 정답 | 이 답안 |
|---|---|---|
| 페이로드 자리 | `C:\ProgramData\CryptoSvc\...` **리터럴 목록** | **증거에서 파생** — `command \| first_path` → `dirname` |
| 협박문 범위 | `%USERPROFILE%` — 현재 사용자만 | **`%ALLUSERPROFILES%`** — 모든 사용자 프로필 |

**첫째.** 답안은 자동 실행 항목을 부모로 삼아 페이로드 폴더를 값에서 뽑는다.
폴더 이름이 바뀐 변종에서도 같은 사슬로 닿는다. 정답은 그 자리를 리터럴로
적는다 — 이 위협에는 감춘 값이 없어 리터럴이 허용되지만, 답안 쪽이 더 넓게
통한다.

부모로 삼은 조건도 근거를 적었다 — 폴더 한 겹(`\ProgramData\[^"]+\`)을
정규식에 넣어 `dirname` 이 상한 자체가 되지 않게 했고
(`22-remediate-recipes.md` §조건 5), 항목 이름(`CryptoSvc`)과 인자
(`--resume`)는 **일부러 조건에 넣지 않았다**(변종에서 조용히 안 맞는다).

**둘째.** `%ALLUSERPROFILES%` 는 문서화된 토큰이고(`machine/REFERENCE.md`
지정 확장 토큰 표), *"현재 로그온 사용자만 치료하면 다른 사용자 프로필의
협박문이 그대로 남는다"* 는 이유를 주석에 적었다. 프로필 루트가 아니라
`Documents`·`Desktop` **두 폴더까지 내려** 적어 상한이 사용자 자료 전체로
넓어지는 것도 막았다.

### 판정식을 왜 그렇게 세웠는지 적었다

```
  verdict: autostart and keyfile
```

`note` 를 `or` 가지에 넣지 않은 이유를 주석에 적었다 — 협박문은 페이로드
폴더 밖에 있어 부모에 묶을 수 없고, 그러면 **ProgramData 를 쓰는 정상 자동
실행 항목의 그룹까지 판정이 서서** 그 항목과 실행 파일이 지워진다. `payload`
도 `or` 가지가 될 수 없다고 적었다 — *"자동 실행이 가리키는 파일이 실재한다"*
는 청정 기계의 모든 정상 항목이 만족하기 때문이다.

## 정답에 있고 답안에 없는 조건 하나

```
  정답    - { field: data, op: equals, value: "1" }
```

정답은 `DisableTaskMgr` 의 **값 내용까지** 본다. 그 까닭을 정답 주석이
적는다 — *"정책이 0 으로 꺼져 있는 기계에서 아무것도 맞히지 않기 위해서."*

**이 회차에서는 손해가 나지 않았다.** 판정이 `autostart and keyfile` 로
서므로 정책 값만 맞은 기계에서는 계획이 서지 않고, 청정 코퍼스도 파괴 0 이다.
다만 규칙 자체의 조임은 정답 쪽이 한 칸 더 좁다.

## 린트 경고 — 두 회차 연속 같은 자리

`%PROGRAMDATA%` 상한 경고는 직전 `stager-r1` 답안과 **같은 선택·같은 경고**다.
두 답안 모두 *"폴더 이름이 검체마다 바뀔 수 있어 부모를 상한으로 둔다"* 는
같은 이유를 적었다. 경고는 불합격이 아니고(사전 기준 ②) 서명 단계에서 이유를
적으면 되는데, **두 회차가 같은 곳에서 같은 이유로 걸렸다는 것은 기록해 둘
만하다** — 가이드가 그 트레이드오프를 다루지 않는다는 신호일 수 있다.

## 이 회차가 남긴 것

1. **"지우면 안 되는 것" 을 묻는 위협이 실제로 그렇게 풀렸다.** 자동 넷이
   못 가르는 세 자리를 답안이 전부 피했고, 채점 5 가 6/6 으로 확인했다.
2. **사전 기준의 변형이 채점 잣대로 실제로 쓰였다.** 변형 셋이 각각 밟은
   지뢰를 답안이 어떻게 피했는지 한 줄씩 대응시킬 수 있었다.
3. **`after_reboot` 이 Windows 에서 예약된다는 것이 세 번째로 확인됐다**
   (`hook-r1` · `stager-r1` · 이 회차). 리눅스는 `hexcfg-r1` 에서 못 한다.
4. **`%PROGRAMDATA%` 상한 경고가 두 회차 연속이다.** 가이드 쪽에서 볼 자리가
   있을 수 있다 — 범위 밖이라 적어만 둔다.
